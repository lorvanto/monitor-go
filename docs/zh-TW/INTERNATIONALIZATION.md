# 國際化與文檔維護

[English](../en-US/INTERNATIONALIZATION.md) · [简体中文](../zh-CN/INTERNATIONALIZATION.md) · [日本語](../ja-JP/INTERNATIONALIZATION.md) · [한국어](../ko-KR/INTERNATIONALIZATION.md) · **繁體中文** · [Documentation](../README.md)

本次整理支援 `zh-CN`（簡體中文）、`en-US`（英文）、`ja-JP`（日文）、`ko-KR`（韓文）、`zh-TW`（繁體中文）。這是現有 v0.4 上的界面、介面提示和文檔整理，不代表新增公開發佈版本。

## 語言與內容邊界

瀏覽器首次存取預設英文，不自動按瀏覽器語言選擇界面；以後還原本地儲存 `monitor.locale` 中的有效選擇，未儲存、無效或儲存不可用時均使用英文。語言包按需載入，載入失敗時保留當前語言並顯示錯誤。`zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO` 歸為繁體中文；其他中文區域回退簡體。日期、時間、數字通過 `Intl` 格式化，時區使用瀏覽器本地時區。語言偏好不寫入實例共享設定。

`api()` 與兩種檔案上傳入口都會攜帶 `Accept-Language`。API 按權重選擇語言，錯誤正文採用對應翻譯，回應帶 `Content-Language` 與 `Vary: Accept-Language`。無此請求頭時保留原介面的簡體中文行為；有請求頭但沒有受支援語言時使用英文。HTTP 狀態碼、JSON 字段名、權限鍵、頁面鍵、機器 API 路徑保持穩定。介面訊息是給人閱讀的內容，調用方應依據狀態碼及業務回應判斷結果，不應解析翻譯後的字串。

本次覆蓋頁面固定文案、表單、按鈕、狀態、空狀態、對話框、無障礙標籤、匯出表頭、權限／金鑰範圍元資料和 API 校驗提示。記錄中的自定義名稱、主機備注、檔案名、檔案內容、歷史告警與審計、探測診斷、SMTP/Webhook 本文、日誌和 CLI 幫助保留原文；這部分不等於已完成全鏈路翻譯。

內建菜單僅在未改名時返回可翻譯的 `nameKey`，界面在顯示處翻譯。自定義菜單和改名後的菜單不參與匹配。編輯表單始終保留原資料，不能對整個 API 回應或 DOM 文本進行替換。根目錄等系統名稱如未覆蓋也按原始記錄顯示，不能拿普通檔案名去匹配文案目錄。

## 文案約定

- 使用源文案作為 gettext 風格訊息鍵。鍵位於類型受約束的目錄中；修改源文案時同時修改調用與五語目錄。
- React 可見文案調用 `t()`；靜態標籤表用 `localizedLabels()` 惰性求值，避免語言切換後保留舊標籤。後端固定權限／範圍元資料只在指定展示位置調用 `metadataLabel()`。
- 帶變量的整句使用 `{p0}`、`{p1}` 等佔位符，允許翻譯調整順序。不要拼接“數量＋單位＋後半句”。原始參數通過 React 文本插值顯示，不使用 `dangerouslySetInnerHTML`。
- 伺服器端帶數字的校驗使用 `badf()` 保留格式模板和參數，選定語言後再格式化。目錄中的 `%d` 數量必須一致。
- 時間範圍採用 `1h`、`24h`、`7d` 穩定值，不能用翻譯後的“24 小時”作查詢條件。永久刪除界面按所選語言確認，向後端發送固定 `DELETE`，後端兼容舊中文確認值。
- 使用者填寫的文本不是語言資源。切換語言不可重建表單、清空輸入或重新提交任何業務操作。
- 繁體中文使用獨立目錄。首次整理使用系統文字轉換輔助，並調整伺服器、資料、檔案、設定等術語；後續按獨立譯文維護。英文、日文、韓文均有完整訊息鍵集合，但仍歡迎母語使用者校訂表達。

## 文檔佈局

根 `README.md` 是英文項目入口。五語文檔統一按 `docs/<locale>/` 組織，目錄和檔案名稱使用英文，正文保留對應語言。[完整簡體中文指南](../zh-CN/README.md)保存目前部署細節，歷史驗證集中在 [歷史驗證記錄](../zh-CN/VALIDATION_HISTORY.md)，繁體指南位於 `docs/zh-TW/README.md`。總入口是 [docs/README.md](../README.md)。國際化維護規範也提供英日韓繁體入口。

現有簡體中文設計文檔集中在 `docs/zh-CN/`，保留原有實施邊界，不把歷史建議重新包裝為已實現功能。當前沒有宣稱把全部歷史設計文檔逐篇翻譯。修改部署命令、支援版本、安全邊界或操作規則時，應同步五語當前指南；修改中文資料時更新 [文檔索引](../zh-CN/INDEX.md)。

## 新增語言

1. 複製現有 `locales/en-US.json`，將值完整翻譯，保留所有訊息鍵和佔位符。
2. 在 Go 的 `Supported`／`Match` 和前端 `locales`／`matchLocale`／動態載入表中登記 BCP 47 語言代碼。新增佈局方向時同時處理 `dir` 和 CSS 邏輯屬性；當前五語都是從左到右。
3. 更新目錄檢查腳本的語言集合、測試用例、語言原文名稱和文檔導航。為新語言建立當前使用指南，不僅新增空鏈接。
4. 在隔離 SQLite 實例驗證登入前切換、重新整理保留、表單保留、介面錯誤、上傳提示、導航、時間範圍和窄屏顯示。

## 表單與錯誤提示的語言

安裝、登入、彈窗、瀏覽器欄位驗證及暫時提示均跟隨所選介面語言；切換語言後，無需重新提交即可更新既有錯誤。編輯彈窗中未修改的預設名稱也隨語言切換，已輸入的名稱和其他未儲存內容保持不變。新增檢測的空分組顯示本地化預設名稱；既有分組名稱及歷史記錄保留原文。

原生表單驗證統一使用 `Form`，需保留的暫時提示使用 `notice()` / `errorMessage()`。API 錯誤保留 `message` 並附帶明確的 `key` / `args`，供介面回應語言切換；不得從使用者文字猜測翻譯鍵。下載與圖片連結用 `apiLink()` 攜帶 `lang`，有效的 GET/HEAD 語言參數優先於瀏覽器標頭。總覽和可用率介面用 `ungrouped=1` 篩選空預設分組；省略或傳入空 `group` 仍表示全部分組。檢查器拒絕英文翻譯值中的中文及共用元件以外的原生 form，Go 測試檢查 API 錯誤翻譯涵蓋範圍。

## 在對話框中切換語言

所有共用對話框都提供語言選擇器，無須關閉編輯器即可切換。已填寫的名稱、備註、密碼、核取方塊與下拉選項保持不變；刪除確認依輸入時的語言辨識，伺服器仍接收固定的 `DELETE` 標記。API／上傳回傳格式異常時顯示本地化錯誤，不存在的介面也提供可隨語言切換的錯誤鍵。

文案檢查新增其他語言字形混用及整條英文複製檢查，對共用產品與協定名稱保留明確例外；繁體中文統一使用登入、金鑰、封存、連接埠等術語。日文正常漢字及語言選項的自稱不算混用。檢查只處理系統文案，不處理使用者資料或已儲存診斷。互動測試使用對話框內的語言選擇器，驗證草稿保留且不新增請求。
