# 自願使用情況回報

[English](../en-US/USAGE_REPORTING.md) · [简体中文](../zh-CN/USAGE_REPORTING.md) · [日本語](../ja-JP/USAGE_REPORTING.md) · [한국어](../ko-KR/USAGE_REPORTING.md) · [繁體中文](../zh-TW/USAGE_REPORTING.md)

Monitor Go 與 Monitor Console 是獨立儲存庫和服務，放在同層目錄，各自使用資料目錄。Monitor Go 無需統計後台也能正常執行。

同時維護兩個專案時，將原始碼目錄並列放置，資料目錄各自獨立。一般 Monitor Go 安裝只需要此公開倉庫；選擇性回報只需要可存取的統計服務，不需要取得私有後台原始碼。

新安裝以及從不含此功能的版本升級時，回報預設關閉。後續重新啟動或升級會保留管理員對同一接收方儲存的選擇。先在伺服器設定統計後台網址，再由具有 system:settings 權限的管理員，在系統設定中查看欄位並明確開啟。僅設定網址不會開啟回報；更換接收方網址需要重新同意。

回報僅包含隨機執行個體編號、版本、系統類型、處理器架構、部署方式，以及已登入使用者實際操作介面的 UTC 日期。不包含本機帳號清單、監控目標、主機名稱/IP、檔案、告警內文、密碼、監控金鑰或應用程式金鑰。執行個體憑據僅用於登記及請求驗證，不顯示於介面。後台登入另外儲存自願關聯的 GitHub 編號、使用者名稱及顯示名稱。

先用 GitHub 登入 Monitor Console，產生 10 分鐘有效的一次性綁定碼，再貼到 Monitor Go 的回報設定卡片。需先開啟回報。解除綁定僅移除帳號關聯，不會關閉回報；也可在後台解除自己名下執行個體的關聯。

「上次同步的 GitHub 帳號」是本機儲存的快照。在 Monitor Console 端解除綁定後，Monitor Go 要等到下一次成功回報才會更新此顯示。關閉回報期間不會聯絡後台，因此可能繼續顯示舊帳號。「重新整理回報狀態」只重新讀取本機設定，不會請求後台或啟動遠端同步。

開啟後獨立工作先回報一次，其後約每 6 小時回報並加入隨機間隔。單次請求 5 秒逾時，不跟隨重新導向，失敗採有限退避重試；最多保留 7 個 UTC 日期的待傳送活躍標記。自動更新和單純載入頁面不計入人工活躍。每日按執行個體去重，不代表獨立使用者人數；這些是自行回報的使用情況估算，無法證明身分或完整安裝量。

可隨時關閉：取消進行中的請求、清空待傳送活躍記錄，監控、告警和登入保持獨立。關閉不刪除後台已收到的歷史記錄。後台每日記錄保留 90 天，365 天未回報的執行個體會被清理；之後重新回報可再次登記，但需要重新綁定帳號。

僅支援 HTTPS；數字迴環位址的 HTTP 僅供本機整合測試。預設不內建官方後台網域。容器中的迴環位址指向容器本身，分開部署的容器應連線真實 HTTPS 網址。不要將憑據、資料目錄或備份提交 Git；反向代理記錄應避免儲存 OAuth 查詢參數、完整來源 IP 及憑據。

結構版本 9 新增回報設定及粗粒度活躍日期。升級前完整備份資料目錄，還原需使用原備份。隨機執行個體身分隨資料目錄持久保存，複製目錄可能合併統計；關閉回報、離線或修改原始碼的安裝無法完整統計。

```sh
MONITOR_CONSOLE_URL=https://console.example.com ./bin/monitor -data data -listen 127.0.0.1:5080
```

`MONITOR_CONSOLE_URL` / `-console-url`; `MONITOR_DEPLOYMENT=native|docker` / `-deployment`.

原生程式預設使用 `native`；Docker 映像和 Compose 自動設定為 `docker`。
