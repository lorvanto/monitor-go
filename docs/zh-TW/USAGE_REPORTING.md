# 首次啟用與使用情況回報

[English](../en-US/USAGE_REPORTING.md) · [简体中文](../zh-CN/USAGE_REPORTING.md) · [日本語](../ja-JP/USAGE_REPORTING.md) · [한국어](../ko-KR/USAGE_REPORTING.md) · [繁體中文](../zh-TW/USAGE_REPORTING.md)

Monitor Go 與 Monitor Console 是獨立儲存庫、服務及資料庫，原始碼與資料目錄分別放在同層目錄。安裝 Monitor Go 只需此公開儲存庫，不需要私有後台原始碼。標準首次安裝會連線至設定的 Console 完成啟用；後續登入、監控和告警獨立執行。

標準新安裝須先線上啟用，再建立首位本機管理員。安裝頁明確顯示目的地（預設使用預先指定的 Console 來源，實際位址以安裝或確認頁面顯示為準）、統計用途、具體欄位，以及回報持續啟用且沒有關閉開關的規則，要求手動確認告知版本 `2`。登記成功後建立本機管理員並啟用持續背景回報；不會向 Console 傳送本機使用者名稱、顯示名稱或密碼。登記失敗不建立管理員，恢復網路後以同一執行個體身分重試。啟用不需 Console 帳號或 GitHub 登入，也不會自動綁定開發者帳號。

既有已啟用回報的執行個體升級時保留身分、憑據、帳號綁定及歷史同意記錄，不補造新的確認。舊版關閉回報的執行個體不會被默默啟用；具有 `system:settings` 權限的管理員須查看目前目的地、欄位及不可關閉規則，進行一次確認，登記成功後才啟用回報。登記或本機交易失敗仍維持關閉。等待確認期間，本機登入、監控及告警繼續執行。更換接收方會清除原本機回報身分，並要求確認新目的地後才向其傳送。

回報僅包含隨機執行個體編號、版本、系統類型、處理器架構、部署方式，以及已登入使用者實際操作介面的 UTC 日期。不包含本機帳號清單、監控目標、主機名稱/IP、檔案、告警內文、密碼、監控金鑰或應用程式金鑰。執行個體憑據僅用於登記及請求驗證，不顯示於介面。後台帳號獨立於 Monitor Go：本機 Console 帳號儲存使用者名稱及顯示名稱；選擇 GitHub 登入時另外儲存經驗證的 GitHub 編號、使用者名稱及顯示名稱。

執行個體登記及活躍統計不需綁定帳號。Console 支援本機管理員使用者名稱與密碼登入，GitHub 登入為選用功能；安裝 Monitor Go 不需設定 OAuth。

如需關聯帳號，先使用本機 Console 帳號或已啟用的 GitHub 登入 Monitor Console，產生 10 分鐘有效的一次性綁定碼，再貼到 Monitor Go 的回報設定卡片。需先開啟回報。解除綁定僅移除帳號關聯，不會關閉回報；也可在後台解除自己名下執行個體的關聯。

「上次同步的 Console 帳號」是本機快照。在 Monitor Console 端解除綁定後，Monitor Go 要等到下次成功回報才更新顯示。網路故障或舊執行個體等待確認期間可能保留舊帳號。「重新整理回報狀態」僅重新讀取本機設定，不啟動遠端同步。

開啟後獨立工作先回報一次，其後約每 6 小時回報並加入隨機間隔。單次請求 5 秒逾時，不跟隨重新導向，失敗採有限退避重試；最多保留 7 個 UTC 日期的待傳送活躍標記。自動更新和單純載入頁面不計入人工活躍。每日按執行個體去重，不代表獨立使用者人數；這些是自行回報的使用情況估算，無法證明身分或完整安裝量。

若遠端登記成功，但本機建立管理員的交易失敗或安裝遭取消，後台可能保留未綁定的隨機執行個體記錄；重試沿用同一身分。因此登記數不等於已完成安裝數或實際使用者人數。

啟用或確認後，回報持續開啟，介面、API 及部署參數均不提供關閉方式；請求關閉會回傳 HTTP 403。Console 故障只觸發獨立背景退避重試，不會阻斷登入、監控或告警。後台每日記錄保留 90 天，365 天未回報的執行個體會清理；後續回報可再次登記，但須重新綁定帳號。解除綁定不會停止回報，也不刪除已接收的歷史記錄。

僅支援 HTTPS；數字迴環位址的 HTTP 僅供本機整合測試。容器中的迴環位址指向容器本身，分開部署的容器應連線真實 HTTPS 網址。不要將憑據、資料目錄或備份提交 Git；反向代理記錄應避免儲存 OAuth 查詢參數、完整來源 IP 及憑據。

資料庫繼續使用結構版本 10；告知版本 `2` 利用既有告知版本、同意時間及啟用時間欄位記錄持續回報規則的確認，不改寫既有歷史同意。升級前完整備份資料目錄，還原須使用原備份。隨機身分隨資料目錄保存，複製目錄可能合併統計；未確認的舊執行個體及網路不可達的用戶端不會構成完整安裝量統計。

`MONITOR_CONSOLE_URL` 未設定時，原生程式及 Compose 使用預先指定的 Console 來源，實際位址以安裝或確認頁面顯示為準；可設為其他 HTTPS 來源以更換目的地，原生 `-console-url` 參數優先。空值或只有空白的目的地（包括環境變數提供的值）屬於無效設定，標準 CLI 會拒絕啟動，不能用於關閉回報或略過啟用。版本查詢與備份命令不依賴啟用設定。

標準 CLI 與 Compose 必須啟用並回報。舊的 `-require-activation=false` 及 `MONITOR_REQUIRE_ACTIVATION=false` 設定會明確報錯，不再支援；`true` 保留相容。沒有受支援的離線安裝或關閉回報參數。應設定可達的 HTTPS Console 網址，空值或只有空白的目的地屬於無效啟動設定，不能用於關閉回報或略過啟用要求。Console URL 參數優先於對應環境變數；既有 activation=false 設定不能透過另加 true 參數變為有效。

```sh
./bin/monitor -data data -listen 127.0.0.1:5080
```

`MONITOR_CONSOLE_URL` / `-console-url`; `MONITOR_REQUIRE_ACTIVATION` / `-require-activation`; `MONITOR_DEPLOYMENT=native|docker` / `-deployment`.

原生程式預設使用 `native`；Docker 映像和 Compose 自動設定為 `docker`。
