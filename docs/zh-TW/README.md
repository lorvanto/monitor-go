# Monitor Go

面向個人和團隊自行部署的監控運維平台。Go 服務、React 19 界面、內建 SQLite 檔案資料庫；一套安裝內多人協作，不做多租戶。當前開發基線 0.4.0 已完成五類核心頁面、遠端 Agent、郵件 / Webhook 通知，以及菜單、檔案、圖片樣式、操作審計、基礎設定、應用金鑰、安裝包、QR 碼和條碼。其餘模塊按 [項目文檔](../zh-CN/INDEX.md) 分階段實施。

## 國際化

界面支援簡體中文、英文、日文、韓文、繁體中文。登入頁和登入後側欄均可切換；首次存取預設英文，不自動跟隨瀏覽器語言；此後還原本瀏覽器已儲存的有效選擇，未儲存、無效或儲存不可用時均使用英文。語言僅影響當前瀏覽器顯示，日期、數字和圖表時間跟隨語言，時區仍採用瀏覽器本地時區。正在編輯的表單不會因語言切換而重建。

頁面固定文案、未改名的內建導航、權限與介面範圍說明、API 校驗錯誤已接入語言目錄。使用者填寫的名稱、備注、目錄、歷史告警、探測診斷、審計記錄、SMTP/Webhook 內容及伺服器端日誌保留原文。歷史設計資料目前以簡體中文為準，其他語言使用指南列明當前能力與限制。擴展規範見 [國際化與文檔維護](INTERNATIONALIZATION.md)。

## React 前端結構

目前使用 React / React DOM 19.3.0、TypeScript 5.9.3、Vite 8.3.4 和 Zustand 5.0.15。`web/src/views/` 依業務頁面組織，透過 `React.lazy` 按需載入；`components/` 為共用 TSX 元件，`stores/app.ts` 管理工作階段、權限、導覽與更新，`lib/` 保存 API 型別、圖表及格式化工具，`i18n/` 訂閱五語狀態。建置產物由 Go 內嵌提供，正式環境不需要 Node.js 服務。

`npm --prefix web test` 執行語言測試與 Vitest / React Testing Library 互動測試；`npm --prefix web run typecheck` 同時檢查應用與測試程式。此次遷移保留原有 API、CSRF、上傳和 SQLite 契約，沒有新增資料庫遷移。部署時重新增置 Go 執行檔並重新啟動服務。

前端會忽略舊登入工作階段及舊頁面選取的延遲回應；主機備註與告警靜默綁定開啟視窗時的物件和版本。檔案末頁清空後自動調整頁碼，稽核查詢載入中仍可清除條件。瀏覽器無法儲存偏好時仍可切換主題；頁面載入失敗會提供重新整理入口，並提醒未儲存的變更將遺失。

## Docker 部署

宿主機安裝 Docker 與 Compose 後，可直接從原始碼建置，無須宿主機 Go 或 Node.js：

```sh
docker compose up -d --build
docker compose exec monitor cat /data/setup-token
```

開啟 5080 連接埠，使用初始化碼建立管理員。具名磁碟區持久保存完整資料目錄；容器預設關閉本機指標採集，真實主機使用原生 Agent。連接埠衝突、HTTPS、備份還原與升級詳見 [Docker 部署指南](DOCKER.md)。

## 啟動

示例命令使用 POSIX shell；Windows 開發者可使用 WSL。開發構建需要 Go 1.26.9 或更新的兼容版本，以及 Node.js 22.12+ / 24.x。依賴鎖定在 `go.mod`、`go.sum` 和 `web/package-lock.json`。前端運行依賴為 React / React DOM 19.3.0、Zustand 5.0.15、`lucide-react` 1.57.0 圖標，以及 `@fontsource-variable/ibm-plex-sans` 5.3.0 與 `@fontsource/ibm-plex-mono` 5.3.0 字體（OFL-1.1 許可，用於數字、英文和機器標識）；字體檔案隨前端資源嵌入二進制，瀏覽器按字符範圍按需載入（中文界面通常只載入拉丁子集），中文使用系統字體。

```sh
make build
./bin/monitor -data data -listen 127.0.0.1:5080
```

打開 [本地服務](http://127.0.0.1:5080/)。成品二進制已嵌入前端資源，運行時無需 Node.js、Java 或外部資料庫。

首次啟動後，從同一資料目錄讀取初始化碼：

```sh
cat data/setup-token
```

在頁面輸入初始化碼、使用者名稱、姓名和密碼。初始化完成後自動刪除初始化碼檔案，進入監控中心。此時本機指標會自動採集，檢測列表為空，按需要新增真實目標。不會自動建立公網檢測、演示帳號或虛構業務資料。

用於多人存取時可修改監聽地址，並在可信 HTTPS 反向代理後運行：

```sh
./bin/monitor -data data -listen 127.0.0.1:5080 \
  -public-url https://monitor.example.com -secure-cookie
```

`-public-url` 填瀏覽器實際存取的來源，不帶末尾斜槓。代理須正確轉發請求。`-collect-host=false` 可關閉本機採樣。當前支援一個活動服務進程，不允許多個實例共享一個資料目錄。

## 接入遠端主機

在「主機詳情」點擊「接入遠端主機」，填寫名稱後生成有效期 15 分鐘的接入碼。每次接入綁定一台預登記主機，不能用同一接入碼註冊其他機器。主機頁支援切換、重新接入與撤銷；操作需要新增的 `host:agents` 權限，預設僅超級管理員擁有。

`make build` 同時生成伺服器端 `bin/monitor` 與採集端 `bin/agent`。將匹配遠端系統 / 架構的採集程序複製到遠端主機，例如構建 Linux 版本：

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o bin/agent-linux-amd64 ./cmd/agent
# ARM64 主機將 GOARCH 改為 arm64
```

在遠端主機保存頁面下載的 `enrollment-token`，然後運行：

```sh
chmod 600 enrollment-token
./agent -server https://monitor.example.com -enrollment-file enrollment-token -config agent-data/config.json
```

Agent 必須能存取伺服器端，HTTPS 證書要有效且受系統信任。私有 CA 可在首次運行加 `-ca-file /path/to/ca.pem`。僅數字回環地址允許 HTTP 本機聯調。伺服器端通過反向代理公開時，應轉發 `/api/v1/agent/`，無需開放 Agent 入站連接埠。

成功註冊後，持久憑據保存到 `agent-data/config.json`（0600 權限），接入碼從配置中移除，原 `enrollment-token` 檔案可由部署者刪除。以後啟動只需要：

```sh
./agent -config agent-data/config.json
```

不要把同一配置檔案複製給其他主機。重新接入會立即吊銷舊憑據，需要停止舊進程並使用新的配置路徑註冊。憑據只可上報自身指標，不具有後台登入或修改權限。當前最多登記 1000 台遠端主機，此數值只是配置限制，尚未完成容量壓測。

Agent 註冊後立即採樣，隨後約每 15 秒上報 CPU、記憶體、磁碟、網路和系統資訊。伺服器端以接收時間記歷史；同一報告重復發送不會重復入庫或延長在線時間。採樣時間需在伺服器端 ±5 分鐘內，亂序資料拒絕寫入。網路錯誤退避重試，最長 60 秒；當前不保存斷網期間的歷史，曲線如實留空。超過 90 秒未收到資料產生離線告警，最多再等待 10 秒巡檢；新上報自動恢復。待接入主機不觸發離線告警，已註冊但一直未上報的主機會觸發。

Linux 常駐運行可使用 [systemd 單元](../../deploy/monitor-go-agent.service)。先由部署者建立 `monitor-go-agent` 系統使用者與 `/var/lib/monitor-go-agent`（該使用者所有、0700），將程序放到 `/usr/local/bin/monitor-go-agent`；以該使用者完成首次註冊，配置路徑為 `/var/lib/monitor-go-agent/config.json`。隨後安裝單元到 `/etc/systemd/system/`，執行 `systemctl daemon-reload` 和 `systemctl enable --now monitor-go-agent`。該單元無需 root 運行，配置與採樣權限不足時應檢查日誌。此檔案是部署模板，當前機器沒有自動安裝系統服務。

## 外部告警通知

在「告警中心 → 通知渠道」新增 SMTP 郵件、通用 Webhook 或群組機器人 Webhook；配置需要 `notification:manage`，預設僅超級管理員擁有。支援編輯、啟停、軟封存及真實測試投遞，渠道最多 20 個。SMTP 密碼 / 授權碼和 Webhook 簽名金鑰不通過讀取介面回顯，整個渠道配置在 SQLite 中使用 AES-GCM 加密。編輯時金鑰留空保持不變。

- SMTP 僅支援校驗證書的 TLS（通常 465）或 STARTTLS（通常 587），拒絕降級明文。可配置 1–20 個收件郵箱，SMTP 服務接受不保證郵件最終進入收件箱。
- Webhook 必須為 HTTPS（數字回環地址可 HTTP 聯調），POST JSON，通用格式以 HTTP 2xx 視為成功；不跟隨重定向，不發送瀏覽器 Cookie。與檢測撥號共用地址校驗，拒絕鏈路本地 / 雲元資料地址。
- 新故障與恢復各生成一次持久投遞任務，同一事件與渠道有唯一約束。新渠道不追溯歷史事件。兩名後台執行器併發發送，網路調用不佔用資料庫事務。
- 最多嘗試 4 次，失敗後依次等待 15 秒、60 秒、5 分鐘；重啟繼續未完成任務。最終失敗後可在「投遞記錄」手動重試，保留相同投遞 ID。
- 發出前再次檢查事件靜默和渠道狀態；靜默期跳過故障及恢復通知，不在到期後補發；已恢復故障的過時首報也會跳過。修改或停用渠道取消舊的待投遞任務。已開始發送的訊息不能保證撤回。
- 傳輸採用至少一次語義：發送成功但確認入庫前崩潰可能重復。Webhook 接收端以 `X-MonitorGo-Delivery-ID` 去重；SMTP 使用穩定 Message-ID，但不承諾收件端去重。
- 投遞記錄保留 30 天，頁面返回最近 200 條；靜默跳過、失敗原因、嘗試次數和下次執行時間均可查看。測試通知每渠道每分鐘最多 3 次，不受某一事件靜默影響。

通用 Webhook 請求體示例（字段值僅為示意）：

```json
{"deliveryId":"101","event":"opened","at":1791936000000,"alertId":"22","resource":"api.example.com","severity":"critical","title":"服务异常","description":"HTTP 503"}
```

`event` 為 `opened`、`resolved` 或 `test`。配置簽名金鑰後，`X-MonitorGo-Signature` 為 `sha256=` 加 HMAC-SHA256 十六進制值；待簽位元組為 `X-MonitorGo-Timestamp` 的秒級時間文本、一個英文句點、未經重新編碼的請求體。接收端應驗證簽名與時間窗口，並以穩定投遞編號做冪等處理。

## 菜單、檔案和基礎管理

側欄新增「檔案與資源」和「系統管理」分組。導航由 `GET /api/v1/me/navigation` 按角色權限返回；每 10 秒重新整理，保存菜單後立即重新整理。最多 200 個菜單、3 層結構，支援分組、已註冊頁面和不含登入憑據的 HTTP(S) 外鏈。排序值越小越靠前，父子關係不能成環。內建菜單可編輯或隱藏，類型和綁定頁面固定；自定義菜單可軟刪除，刪除分組前需先處理子菜單。恢復內建導航會保留自定義項。隱藏只改變展示，不撤銷直接存取頁面或 API 的權限；個人菜單始終為有權使用者提供「管理導航」和「系統設定」入口。

檔案在本實例內由團隊共享，建立人僅用於審計。原檔案寫入 `data/uploads/objects/`，磁碟名稱為伺服器生成的隨機對象鍵；SQLite 保存目錄、名稱、MIME、大小、SHA-256 與版本。重命名和移動不複製原檔案，存儲使用 `os.Root` 限制路徑和越界符號鏈接。目錄內名稱採用 SQLite NOCASE 唯一約束（ASCII 大小寫不區分），最多 1000 個未永久刪除的目錄，目錄層級受限。

- 界面支援一次選擇最多 50 個檔案，逐個上傳並顯示進度，失敗逐項提示。伺服器端同時接收最多 2 個上傳，每個請求包含一個 multipart `file`。預設單檔案 32 MB，可配置 1–1024 MB；預設原檔案總配額 1024 MB，可配置 10–1048576 MB。最終入庫再次檢查配額，資源回收筒佔用也計入。
- 上傳先寫臨時檔案，計算 SHA-256 並同步磁碟，再以短事務和原子重命名完成存儲。失敗清理本次臨時對象；啟動和每小時巡檢會在受限時間內清理超過 24 小時的未引用上傳殘留，保留近期傳輸和已引用原檔案。
- 檔案列表每頁 50 項，名稱搜尋限定當前目錄；資源回收筒只顯示每次刪除的根條目。普通刪除將整個有效子樹一同移入資源回收筒。根目錄與包含預設上傳目錄的子樹不可刪除，需先更換預設目錄。
- 恢復時可選擇新目錄或名稱，重名、層級和成環檢查在事務中執行。永久刪除必須輸入界面當前語言顯示的確認短語，先記錄不可恢復的刪除狀態，再回收原檔案與其快取；中斷會在啟動和每小時巡檢繼續回收，保留元資料墓碑。此前單獨刪除的子項仍獨立保留在資源回收筒。
- 原檔案只通過鑒權介面下載，使用附件回應和 `nosniff`，不作為公開靜態資源。圖片預覽支援 PNG、JPEG、GIF 首幀、WebP，最多 2400 萬像素、單邊 16384 像素。伺服器端重新編碼為 PNG，樣式寬高 16–2048，最多 30 個；等比適配不放大，裁切填滿指定尺寸。
- UTF-8 文本按轉義文本預覽，最多 256 KB；HTML/SVG 不直接執行，其他檔案提供下載。快取根據原檔案對象鍵和樣式版本生成，讀取仍鑒權，不保留瀏覽器快取；磁碟樣式快取上限 128 MB，可在系統設定中清理。預覽授權本身允許讀取預覽內容，下載權限控制原檔案和樣式下載入口。

新增權限為 `menu:manage`、`file:read`、`file:upload`、`file:download`、`file:manage`、`file:styles`、`audit:read`、`system:read`、`system:settings`，預設只授予超級管理員。普通角色需要明確勾選。檔案查看、上傳、下載、管理分別校驗，檔案頁面可對僅上傳成員開放元資料列表，但不給予預覽和下載能力。總覽中的審計摘要也必須具有 `audit:read`。

審計記錄成功的管理變更，保存操作人、動作、資源摘要、伺服器端請求編號、方法和路徑，不記錄密碼、渠道金鑰或上傳正文。列表每次最多 50 條，使用編號游標載入更多；預設保留 90 天，可配置 7–365 天，每小時分批清理。歷史記錄沒有請求編號時如實顯示為空。運行資訊展示 Go/應用版本、SQLite 版本號、資料庫及原檔案佔用和待回收數量，不回顯主機絕對資料路徑。

## 應用金鑰、安裝包與編碼工具

在「應用與金鑰」建立應用，填寫不可變的 3–48 位小寫標識。每個應用最多 10 個未撤銷且未過期的金鑰，實例最多 200 個有效應用。金鑰使用 256 位隨機值，明文僅建立/輪換時返回一次，資料庫僅保存 SHA-256 摘要與短前綴；有效期 1–365 天。輪換在同一事務中撤銷舊金鑰並簽發新金鑰，撤銷、到期或停用應用後拒絕後續請求。封存應用前必須先封存它的安裝包，封存會撤銷全部金鑰。

瀏覽器繼續使用 Cookie + CSRF；程序接入單獨使用 `Authorization: Bearer $MONITOR_GO_API_KEY`，不接受查詢參數傳金鑰、不允許金鑰登入管理介面。提供主機讀取、檢測狀態、告警讀取、安裝包列表與下載五個範圍，按需勾選。前三項是本實例共享資料，安裝包只限金鑰所屬應用。每個金鑰與來源 IP 每 5 分鐘最多 300 次請求，過限返回 429。完整協議及示例見 [應用分發與編碼工具](../zh-CN/APPLICATION_DISTRIBUTION.md)。

安裝包關聯已有檔案或直接上傳，也可使用不含使用者名稱/密碼的 HTTPS 外鏈。本地檔案關聯需要 `file:download`，直接上傳還需 `file:upload`。首次發佈後鎖定所屬應用、版本號、平台、架構與檔案來源；更新檔案應建立新版本。應用、版本號、平台與架構的組合在封存後仍不能重復使用。所有未封存安裝包（含草稿與下架）都阻止關聯檔案或父目錄移入資源回收筒，封存不刪除檔案。

只有已啟用應用下的已發佈版本可下載。本地下載支援 Range/HEAD 並返回 `X-Checksum-SHA256`；下載次數統計成功的 GET 請求（含分段），不代表安裝量。瀏覽器外鏈下載返回 302，統計跳轉次數；機器 API 返回外部 URL 的 JSON，調用方須另起不含應用金鑰的下載請求，該地址查詢不計下載次數。外部內容不由伺服器抓取、不提供外部檔案校驗值。私有部署首次不包含示例應用、金鑰或安裝包。

編碼工具在本實例生成，不保存輸入正文，不調用外部圖像服務。QR 碼支援 UTF-8、L/M/Q/H，內容最多 1200 位元組；Code 128 支援可打印 ASCII、Code 39 支援大寫字母與指定符號；EAN-13/8 自動補齊或檢查校驗位。匯出 PNG 與安全的純幾何 SVG，自動保留靜區與整數模塊尺寸。寬度 128–2048 像素，條碼高度 80–512；尺寸不足返回所需寬度。改變內容後需重新生成才能匯出。每人/來源 IP 每 5 分鐘最多生成 120 次，全局最多 2 個並行生成任務。正式印刷請實際試掃，生成 EAN 不等於取得商品編號。

新增 `application:read`、`application:manage`、`application:keys`、`release:read`、`release:manage`、`release:download`、`tool:generate` 七項權限，預設只給超級管理員。`application:keys` 是敏感權限，持有者可為應用簽發五種介面範圍；應用管理與金鑰管理可分別授權。只擁有安裝包權限的成員可讀應用目錄以選擇歸屬，但不能管理應用或讀取金鑰。

## 從早期版本升級

先正常停止舊服務並完整備份資料目錄（包括 `master.key` 和已有 `uploads/`），再用新二進制啟動同一目錄。已實現 v1 → v2 → v3 → v4 → v5 → v6 → v7 → v8 順序事務遷移：v2 新增 Agent 與通知，v3 新增菜單、檔案、圖片樣式、基礎設定和審計請求資訊。原有主機、使用者、檢測和告警保留。新增權限只授予內建超級管理員並撤銷其舊會話，其他角色需明確授權。v4 新增應用、金鑰和安裝包，以及按固定內建鍵分配的新導航，避免與已有自定義菜單編號衝突。舊版本二進制不能直接讀取 v8，回退需恢復整套升級前備份。

## 資料、調度與備份

- `data/monitor.db`：使用者、角色、會話、主機資料、採樣、檢測、執行任務、告警和審計。
- `data/master.key`：檢測存取憑據的 AES-GCM 主金鑰，與資料庫分開保存。憑據介面不返回明文。
- `data/uploads/`：原檔案、上傳臨時對象和可重建的圖片快取，備份必須包含原檔案。
- `data/instance.lock`：實例鎖；運行資料、金鑰、構建產物均被 Git 忽略。
- 後台最多同時執行 4 項檢測，活動任務佇列最多 256 項，同目標活動任務合併；重啟後恢復未完成任務。
- 當前最多配置 500 個有效檢測目標，這是輸入上限，不代表已完成該規模壓力測試。單目標週期 15–86400 秒，超時 1–30 秒且短於週期。
- 主機與檢測原始指標預設保留 7 天（可設定 1–30 天），檢測小時彙總預設保留 90 天（可設定 90–730 天），每小時先彙總再分批清理；告警持續保留，審計按系統設定保留 7–365 天。曲線按時間桶聚合，缺失區間不補零，可用率為成功次數 / 總檢測次數。
- 告警確認、靜默或暫停檢測都不會偽造恢復。檢測連續異常達到目標閾值後建立事件，一次正常結果恢復；主機 CPU、記憶體和磁碟閾值可在系統設定中配置，詳見下方說明。
- 探測允許私網和回環，適合內部服務監測；拒絕鏈路本地、常見雲元資料、組播和未指定地址，HTTP 重定向也經過同一撥號檢查。HTTP/SSL 和啟用 TLS 的資料庫連接均校驗證書。

備份時先正常停止服務，再完整複製資料目錄，包括 SQLite 可能存在的伴隨檔案、`master.key` 與 `uploads/` 原檔案。恢復時整體放回並使用同版本啟動。當前沒有在線備份界面；運行中不要只複製 `monitor.db` 當作完整備份。

## 可信代理與登入限流

`-trusted-proxy` 接受逗號分隔的代理 CIDR，預設留空（不信任代理），無效值會阻止啟動。只填寫本程序實際看到的代理位址；代理必須覆寫或安全追加 `X-Forwarded-For`。伺服器從右向左尋找首個不可信位址，忽略其他來源的轉送標頭。登入只統計失敗：每個用戶端 IP 每 5 分鐘 30 次、每個正規化使用者名稱每 5 分鐘 10 次；成功登入不消耗也不重設計數。初始化對所有嘗試計數（每個 IP 每 5 分鐘 10 次）。

## 檢測編輯與封存

檢測清單支援完整編輯名稱、類型、位址、週期、逾時、閾值及憑證。密碼留空保留舊值，輸入新密碼則取代，勾選「清除已儲存的憑證」則清空；改為 HTTP/TCP/SSL 會清除資料庫憑證。儲存採版本校驗，重設目前狀態和排程並取消排隊工作，保留歷史與未恢復的告警。封存需要確認並停止後續檢測。唯讀成員沒有編輯或封存入口。409 衝突會重新載入伺服器資料並保留表單；再次儲存前請重新開啟編輯器核對最新設定。

預設實例名稱會隨介面語言切換，英文顯示 “My monitoring center”。在系統設定勾選「使用預設實例名稱」可恢復此行為；自訂名稱在所有語言下都保持原文。舊安裝未曾修改的預設名稱會自動識別，已儲存的名稱保留原文，須主動選擇預設名稱。

## 群組機器人 Webhook

Webhook 格式支援通用、釘釘、飛書和企業微信，舊渠道預設沿用通用格式。在編輯器選擇格式：釘釘使用 Markdown，在 URL 中附加毫秒時間戳和簽名；飛書使用文字，在本文中附加秒級時間戳和簽名；企業微信使用 Markdown，金鑰位於 URL 的 `key` 參數，無須額外簽名金鑰。切換格式會清除之前的簽名金鑰。

通用格式保留原有 JSON 和簽名標頭。群組機器人格式須同時滿足 HTTP 成功和平台錯誤碼為 0（釘釘/企業微信為 `errcode`，飛書為 `code`）；缺失或格式錯誤視為失敗，依序在 15 秒、1 分鐘、5 分鐘後重試。訊息包含事件、原文標題/資源/描述、級別、UTC 時間及投遞編號，固定標籤使用英文。長欄位僅在通知本文截短，以符合企業微信 Markdown 的 4096 位元組限制，資料庫告警保持不變。本次未做真實平台驗證，僅用本機 HTTP 模擬測試格式、簽名、錯誤碼及重試；部署時請測試自己的機器人金鑰及平台策略。

## 主機告警閾值

系統設定可配置執行個體層級的 CPU、記憶體、磁碟閾值（預設 90%、90%、85%），以及 1–60 分鐘的持續時長（預設 5 分鐘）。單項閾值為 0 時關閉該指標告警。結構版本 6 新增這些有約束的設定；升級前停止服務並完整備份資料目錄，舊程式不能讀取結構版本 8。

本機與遠端主機共用判定規則。CPU/記憶體必須在整段時間內達到或超過閾值：採樣需涵蓋整個時間窗，包含起點或之前的有效樣本，不能缺值或出現超過 45 秒的間隔。資料不足不會新增告警，也不會讓既有告警恢復；最新有效值低於閾值時立即恢復。磁碟按最新可用採樣立即判斷。關閉閾值會在下次回報時恢復該指標告警；設定變更也從下次回報生效。遠端主機 90 秒離線規則不變。尚未實作各主機獨立閾值。

## 按頁重新整理與清單查詢

頁面可見時每 10 秒只重新整理目前頁面所需的主機、檢測和告警資料，同時更新工作階段與導覽。其他頁面使用輕量告警計數介面更新行動版徽章，範圍與告警清單的最近 200 筆事件一致。角色、成員和權限僅在進入對應頁面或變更後讀取，不參與定時輪詢。切頁與寫入後會重新讀取，舊頁面和舊工作階段回應會被捨棄。檢測清單使用 3 次 SQL 查詢，告警清單使用 2 次；回應結構、24 小時可用率、最近 32 次檢測和每個事件最近 100 筆活動保持一致。

## 靜態資源快取

伺服器啟動時使用 Go 標準函式庫預先產生強 ETag 和 gzip 內容。`/assets/` 下帶雜湊的檔案使用 `public, max-age=31536000, immutable`，HTML 和其他無雜湊檔案使用 `no-cache` 並協商驗證。gzip 協商遵守停用和權重偏好，回應帶 `Vary: Accept-Encoding`，壓縮與原始內容使用不同 ETag。條件 GET/HEAD 在符合時回傳 304，保留位元組範圍與原有安全回應標頭，不需外部壓縮服務。

## 建置版本與 CI

伺服器、Agent 回報及外送請求 User-Agent 統一使用 `internal/buildinfo.Version`。直接 `go build` 預設為 `0.4.0-dev`；`make build` 注入 `git describe --tags --always --dirty`，沒有 Git 資訊時回退至預設值。可用 `make build VERSION=0.4.0-dev` 明確指定。兩個執行檔皆支援 `-version`。前端套件使用開發基線，系統設定顯示實際伺服器建置版本。GitHub CI 設定為 push 和 pull request 觸發，使用 go.mod 中的 Go、Node 22、固定提交的 Action，執行 race 測試、型別檢查、建置和格式檢查。工作流程檔案不代表遠端已執行成功或已發布版本。

`make docker-build` 會注入 Git 衍生版本。直接使用 Compose 時可傳入 `MONITOR_VERSION`，未指定則顯示 `0.4.0-dev`。直接建置可用 `docker build --build-arg VERSION="$(git describe --tags --always --dirty 2>/dev/null || printf 0.4.0-dev)" -t monitor-go:local .`。Git 歷史不進入 Docker 建置內容。

## 線上備份與還原

執行命令時服務可繼續運行。輸出目錄必須不存在，父目錄必須已存在。命令唯讀開啟來源資料庫，不取得執行個體鎖、不執行移轉（支援結構版本 3 至目前版本），產生一致的 SQLite 快照並複製主金鑰與快照引用的全部物件，包括回收桶檔案。快照之後的新上傳不納入備份。遺失物件會重試；仍遺失、損壞或變更時以非零狀態結束並保留 BACKUP_INCOMPLETE，不能還原該目錄。完成清單記錄 UTC 時間、建置/結構版本、物件數量及 SHA-256。初始化碼、鎖、暫存檔與圖片快取不複製。

```sh
mkdir -p backups
./bin/monitor backup -data data -out backups/snapshot-001
```

還原前先停服，以完整備份取代整個資料目錄，再使用支援該結構版本或更高版本的程式啟動。驗證成功前保留舊目錄。僅支援離線還原，不要將檔案合併至運行中的執行個體。備份包含憑據，應私密保存並複製到獨立儲存；原有冷備份仍可使用。

## 預設資源名稱

未修改的預設目錄（含設定及安裝包選擇器中的路徑）、角色名稱與說明、圖片樣式及本機別名會隨介面語言切換。重新命名後保留原文；由伺服器明確提供名稱鍵，不會僅因自訂名稱與預設名稱相同就自動翻譯。既有歷史記錄保持原樣。

稽核的固定操作標籤在顯示時翻譯；操作者、資源文字及資料庫中的原始稽核記錄保持原樣。

選單管理的內建名稱、目標頁面、上級群組和權限選項也依介面語言顯示。只修改顯示狀態或排序而未編輯名稱時，保留內建名稱的預設翻譯行為；明確編輯的名稱作為使用者文字儲存，切換語言不會覆蓋草稿。

## HTTP 回應規則

建立與編輯 HTTP 檢測均支援可選 UTF-8 關鍵字（最多 1024 位元組）、反向比對及耗時警告閾值（0–30000 毫秒，0 關閉）。比對區分大小寫，僅檢查解碼後回應本文前 1 MiB，截斷會在詳情中註明。關鍵字為空時保留僅判斷狀態碼的行為。耗時包含讀取受檢查本文的時間。連線或狀態碼失敗優先，其次是關鍵字失敗，再判定耗時警告；詳情不回顯回應內容。非 HTTP 檢測會清除這些規則。自訂請求標頭、GET/HEAD 選擇仍為可選後續功能。結構版本 7 新增欄位，升級前停服並完整備份，舊程式不能讀取新結構。

HTTP 耗時告警使用回應耗時標題；SSL 憑證警告保留憑證專用標題。

## Agent 重試與採集驗證

網路或伺服器故障按連續失敗次數 × 5 秒退避，最長 60 秒；成功上報後恢復正常 15 秒間隔。HTTP 401/403，以及註冊階段的 409，會因憑據失效或註冊衝突而停止 Agent，應使用新設定重新接入，不會持續重試已撤銷憑據。自動測試使用本機 HTTP/TLS 服務與可注入採集器/時鐘，涵蓋憑據持久化、上報、退避上限與重置、禁止重新導向、私有 CA、分割區過濾（最多 16 個可用且不重複的掛載點）、部分指標錯誤與網路計數器/時間重置。

## 長期可用率與保留策略

結構版本 8 新增檢測小時彙總（總數、成功數、平均/最大耗時）、交易內已彙總標記及待彙總部分索引。啟動及每小時維護時先累加已結束小時，再清理原始記錄。重複執行與遲到結果不會重複計數，彙總失敗時保留原始記錄。原始主機/檢測指標預設 7 天（可設定 1–30 天），檢測彙總預設 90 天（可設定 90–730 天）。清理按 UTC 整點對齊並分批執行，實際保留期可能多出一小時及維護積壓時間。未新增主機彙總表。升級前停服並完整備份，舊程式不能讀取結構版本 8。

總覽與服務檢測可選 30/90 天可用率。GET /api/v1/monitors/availability?hours=720 或 2160 需要 monitor:read 權限，總覽支援相同範圍。單次 SQLite 快照合併小時彙總與尚未彙總的原始記錄，按實際檢測次數加權；healthy 與 warning 均計為可用，與原 24 小時定義一致。起點按 UTC 整點對齊並包含目前未結束小時。缺失採樣不假設為成功，無歷史返回 null/「—」；升級前已刪除的歷史無法補回。

容量估算：原始檢測行數 ≈ 目標數 × (86400 / 檢測間隔秒數) × 原始保留天數；彙總行數 ≤ 目標數 × 24 × 彙總保留天數；主機原始行數 ≈ 主機數 × 5760 × 原始保留天數。使用具代表性內容的一次性資料庫測量每行及索引開銷，以 (page_count − freelist_count) × page_size 比較已用頁增長，另預留 WAL、上傳檔案與備份空間。刪除只使頁可重用，不保證檔案立即縮小；公式是估算而非容量承諾。

## SQLite 並行讀取

檢測列表、長期可用率、總覽、告警和主機指標查詢使用最多 2 個唯讀連接（`mode=ro`、`query_only=1`），配合原有單寫連接。鑑權、排程、修改、遷移與 seed 保留寫連接路徑；線上備份仍使用獨立快照連接。交易回呼必須透過自身交易讀取。保留 WAL、FULL 同步和單執行個體鎖，無新增遷移或相依套件。

Apple M1 / Go 1.26.9 / 真實 WAL 檔案下，以 500 個目標 × 1440 條結果、4 路輪詢各讀 5 次及 80 次間隔寫入進行 3 輪合成壓測：單連接寫入 P95 中位數 866.6 ms，2 個唯讀連接為 0.478 ms；總耗時中位數從 10.45 s 降至 5.713 s。此本機測量不構成正式環境容量承諾。重現命令：`go test ./internal/app -run '^$' -bench BenchmarkConcurrentPollingWrites -benchtime=1x -count=3`；比較共用連接、2 個和 4 個唯讀連接，資料建立不計入耗時。

## 表單與錯誤提示的語言

安裝、登入、彈窗、瀏覽器欄位驗證及暫時提示均跟隨所選介面語言；切換語言後，無需重新提交即可更新既有錯誤。編輯彈窗中未修改的預設名稱也隨語言切換，已輸入的名稱和其他未儲存內容保持不變。新增檢測的空分組顯示本地化預設名稱；既有分組名稱及歷史記錄保留原文。

## 在對話框中切換語言

所有共用對話框都提供語言選擇器，無須關閉編輯器即可切換。已填寫的名稱、備註、密碼、核取方塊與下拉選項保持不變；刪除確認依輸入時的語言辨識，伺服器仍接收固定的 `DELETE` 標記。API／上傳回傳格式異常時顯示本地化錯誤，不存在的介面也提供可隨語言切換的錯誤鍵。
