# Monitor Go

面向個人和團隊自行部署的監控運維平台。Go 服務、React 19 界面、內置 SQLite 檔案資料庫；一套安裝內多人協作，不做多租戶。當前開發基線 0.4.0 已完成五類核心頁面、遠程 Agent、郵件 / Webhook 通知，以及菜單、檔案、圖片樣式、操作審計、基礎設定、應用密鑰、安裝包、QR 碼和條碼。其餘模塊按 [項目文檔](../zh-CN/INDEX.md) 分階段實施。

## 國際化

界面支持簡體中文、英文、日文、韓文、繁體中文。登錄頁和登錄後側欄均可切換；首次訪問預設英文，不自動跟隨瀏覽器語言；此後還原本瀏覽器已儲存的有效選擇，未儲存、無效或儲存不可用時均使用英文。語言僅影響當前瀏覽器顯示，日期、數字和圖表時間跟隨語言，時區仍採用瀏覽器本地時區。正在編輯的表單不會因語言切換而重建。

頁面固定文案、未改名的內置導航、權限與介面範圍說明、API 校驗錯誤已接入語言目錄。使用者填寫的名稱、備注、目錄、歷史告警、探測診斷、審計記錄、SMTP/Webhook 內容及伺服器端日誌保留原文。歷史設計資料目前以簡體中文為準，其他語言使用指南列明當前能力與限制。擴展規範見 [國際化與文檔維護](INTERNATIONALIZATION.md)。

## React 前端結構

目前使用 React / React DOM 19.3.0、TypeScript 5.9.3、Vite 8.3.4 和 Zustand 5.0.15。`web/src/views/` 依業務頁面組織，透過 `React.lazy` 按需載入；`components/` 為共用 TSX 元件，`stores/app.ts` 管理工作階段、權限、導覽與更新，`lib/` 保存 API 型別、圖表及格式化工具，`i18n/` 訂閱五語狀態。建置產物由 Go 內嵌提供，正式環境不需要 Node.js 服務。

`npm --prefix web test` 執行語言測試與 Vitest / React Testing Library 互動測試；`npm --prefix web run typecheck` 同時檢查應用與測試程式。此次遷移保留原有 API、CSRF、上傳和 SQLite 契約，沒有新增資料庫遷移。部署時重新建置 Go 執行檔並重新啟動服務。

前端會忽略舊登入工作階段及舊頁面選取的延遲回應；主機備註與告警靜默綁定開啟視窗時的物件和版本。檔案末頁清空後自動調整頁碼，稽核查詢載入中仍可清除條件。瀏覽器無法儲存偏好時仍可切換主題；頁面載入失敗會提供重新整理入口，並提醒未儲存的變更將遺失。

## Docker 部署

宿主機安裝 Docker 與 Compose 後，可直接從原始碼建置，無須宿主機 Go 或 Node.js：

```sh
docker compose up -d --build
docker compose exec monitor cat /data/setup-token
```

開啟 5080 連接埠，使用初始化碼建立管理員。具名磁碟區持久保存完整資料目錄；容器預設關閉本機指標採集，真實主機使用原生 Agent。連接埠衝突、HTTPS、備份還原與升級詳見 [Docker 部署指南](DOCKER.md)。

## 啓動

示例命令使用 POSIX shell；Windows 開發者可使用 WSL。開發構建需要 Go 1.26.9 或更新的兼容版本，以及 Node.js 22.12+ / 24.x。依賴鎖定在 `go.mod`、`go.sum` 和 `web/package-lock.json`。前端運行依賴為 React / React DOM 19.3.0、Zustand 5.0.15、`lucide-react` 1.57.0 圖標，以及 `@fontsource-variable/ibm-plex-sans` 5.3.0 與 `@fontsource/ibm-plex-mono` 5.3.0 字體（OFL-1.1 許可，用於數字、英文和機器標識）；字體檔案隨前端資源嵌入二進制，瀏覽器按字符範圍按需載入（中文界面通常只載入拉丁子集），中文使用系統字體。

```sh
make build
./bin/monitor -data data -listen 127.0.0.1:5080
```

打開 [本地服務](http://127.0.0.1:5080/)。成品二進制已嵌入前端資源，運行時無需 Node.js、Java 或外部資料庫。

首次啓動後，從同一資料目錄讀取初始化碼：

```sh
cat data/setup-token
```

在頁面輸入初始化碼、使用者名、姓名和密碼。初始化完成後自動刪除初始化碼檔案，進入監控中心。此時本機指標會自動採集，檢測列表為空，按需要添加真實目標。不會自動創建公網檢測、演示帳號或虛構業務資料。

用於多人訪問時可修改監聽地址，並在可信 HTTPS 反向代理後運行：

```sh
./bin/monitor -data data -listen 127.0.0.1:5080 \
  -public-url https://monitor.example.com -secure-cookie
```

`-public-url` 填瀏覽器實際訪問的來源，不帶末尾斜槓。代理須正確轉發請求。`-collect-host=false` 可關閉本機採樣。當前支持一個活動服務進程，不允許多個實例共享一個資料目錄。

## 接入遠程主機

在「主機詳情」點擊「接入遠程主機」，填寫名稱後生成有效期 15 分鐘的接入碼。每次接入綁定一台預登記主機，不能用同一接入碼註冊其他機器。主機頁支持切換、重新接入與撤銷；操作需要新增的 `host:agents` 權限，預設僅超級管理員擁有。

`make build` 同時生成伺服器端 `bin/monitor` 與採集端 `bin/agent`。將匹配遠程系統 / 架構的採集程序複製到遠程主機，例如構建 Linux 版本：

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o bin/agent-linux-amd64 ./cmd/agent
# ARM64 主機將 GOARCH 改為 arm64
```

在遠程主機保存頁面下載的 `enrollment-token`，然後運行：

```sh
chmod 600 enrollment-token
./agent -server https://monitor.example.com -enrollment-file enrollment-token -config agent-data/config.json
```

Agent 必須能訪問伺服器端，HTTPS 證書要有效且受系統信任。私有 CA 可在首次運行加 `-ca-file /path/to/ca.pem`。僅數字回環地址允許 HTTP 本機聯調。伺服器端通過反向代理公開時，應轉發 `/api/v1/agent/`，無需開放 Agent 入站端口。

成功註冊後，持久憑據保存到 `agent-data/config.json`（0600 權限），接入碼從配置中移除，原 `enrollment-token` 檔案可由部署者刪除。以後啓動只需要：

```sh
./agent -config agent-data/config.json
```

不要把同一配置檔案複製給其他主機。重新接入會立即吊銷舊憑據，需要停止舊進程並使用新的配置路徑註冊。憑據只可上報自身指標，不具有後台登錄或修改權限。當前最多登記 1000 台遠程主機，此數值只是配置限制，尚未完成容量壓測。

Agent 註冊後立即採樣，隨後約每 15 秒上報 CPU、記憶體、磁碟、網路和系統資訊。伺服器端以接收時間記歷史；同一報告重復發送不會重復入庫或延長在線時間。採樣時間需在伺服器端 ±5 分鐘內，亂序資料拒絕寫入。網路錯誤退避重試，最長 60 秒；當前不保存斷網期間的歷史，曲線如實留空。超過 90 秒未收到資料產生離線告警，最多再等待 10 秒巡檢；新上報自動恢復。待接入主機不觸發離線告警，已註冊但一直未上報的主機會觸發。

Linux 常駐運行可使用 [systemd 單元](../../deploy/monitor-go-agent.service)。先由部署者創建 `monitor-go-agent` 系統使用者與 `/var/lib/monitor-go-agent`（該使用者所有、0700），將程序放到 `/usr/local/bin/monitor-go-agent`；以該使用者完成首次註冊，配置路徑為 `/var/lib/monitor-go-agent/config.json`。隨後安裝單元到 `/etc/systemd/system/`，執行 `systemctl daemon-reload` 和 `systemctl enable --now monitor-go-agent`。該單元無需 root 運行，配置與採樣權限不足時應檢查日誌。此檔案是部署模板，當前機器沒有自動安裝系統服務。

## 外部告警通知

在「告警中心 → 通知渠道」新增 SMTP 郵件或通用 Webhook；配置需要 `notification:manage`，預設僅超級管理員擁有。支持編輯、啓停、軟歸檔及真實測試投遞，渠道最多 20 個。SMTP 密碼 / 授權碼和 Webhook 簽名密鑰不通過讀取介面回顯，整個渠道配置在 SQLite 中使用 AES-GCM 加密。編輯時密鑰留空保持不變。

- SMTP 僅支持校驗證書的 TLS（通常 465）或 STARTTLS（通常 587），拒絕降級明文。可配置 1–20 個收件郵箱，SMTP 服務接受不保證郵件最終進入收件箱。
- Webhook 必須為 HTTPS（數字回環地址可 HTTP 聯調），POST JSON，HTTP 2xx 視為成功；不跟隨重定向，不發送瀏覽器 Cookie。與檢測撥號共用地址校驗，拒絕鏈路本地 / 雲元資料地址。
- 新故障與恢復各生成一次持久投遞任務，同一事件與渠道有唯一約束。新渠道不追溯歷史事件。兩名後台執行器併發發送，網路調用不佔用資料庫事務。
- 最多嘗試 4 次，失敗後依次等待 15 秒、60 秒、5 分鐘；重啓繼續未完成任務。最終失敗後可在「投遞記錄」手動重試，保留相同投遞 ID。
- 發出前再次檢查事件靜默和渠道狀態；靜默期跳過故障及恢復通知，不在到期後補發；已恢復故障的過時首報也會跳過。修改或停用渠道取消舊的待投遞任務。已開始發送的消息不能保證撤回。
- 傳輸採用至少一次語義：發送成功但確認入庫前崩潰可能重復。Webhook 接收端以 `X-MonitorGo-Delivery-ID` 去重；SMTP 使用穩定 Message-ID，但不承諾收件端去重。
- 投遞記錄保留 30 天，頁面返回最近 200 條；靜默跳過、失敗原因、嘗試次數和下次執行時間均可查看。測試通知每渠道每分鐘最多 3 次，不受某一事件靜默影響。

Webhook 請求體示例（字段值僅為示意）：

```json
{"deliveryId":"101","event":"opened","at":1791936000000,"alertId":"22","resource":"api.example.com","severity":"critical","title":"服务异常","description":"HTTP 503"}
```

`event` 為 `opened`、`resolved` 或 `test`。配置簽名密鑰後，`X-MonitorGo-Signature` 為 `sha256=` 加 HMAC-SHA256 十六進制值；待簽位元組為 `X-MonitorGo-Timestamp` 的秒級時間文本、一個英文句點、未經重新編碼的請求體。接收端應驗證簽名與時間窗口，並以穩定投遞編號做冪等處理。

## 菜單、檔案和基礎管理

側欄新增「檔案與資源」和「系統管理」分組。導航由 `GET /api/v1/me/navigation` 按角色權限返回；每 10 秒刷新，保存菜單後立即刷新。最多 200 個菜單、3 層結構，支持分組、已註冊頁面和不含登錄憑據的 HTTP(S) 外鏈。排序值越小越靠前，父子關係不能成環。內置菜單可編輯或隱藏，類型和綁定頁面固定；自定義菜單可軟刪除，刪除分組前需先處理子菜單。恢復內置導航會保留自定義項。隱藏只改變展示，不撤銷直接訪問頁面或 API 的權限；個人菜單始終為有權使用者提供「管理導航」和「系統設定」入口。

檔案在本實例內由團隊共享，創建人僅用於審計。原檔案寫入 `data/uploads/objects/`，磁碟名稱為伺服器生成的隨機對象鍵；SQLite 保存目錄、名稱、MIME、大小、SHA-256 與版本。重命名和移動不複製原檔案，存儲使用 `os.Root` 限制路徑和越界符號鏈接。目錄內名稱採用 SQLite NOCASE 唯一約束（ASCII 大小寫不區分），最多 1000 個未永久刪除的目錄，目錄層級受限。

- 界面支持一次選擇最多 50 個檔案，逐個上傳並顯示進度，失敗逐項提示。伺服器端同時接收最多 2 個上傳，每個請求包含一個 multipart `file`。預設單檔案 32 MB，可配置 1–1024 MB；預設原檔案總配額 1024 MB，可配置 10–1048576 MB。最終入庫再次檢查配額，資源回收筒佔用也計入。
- 上傳先寫臨時檔案，計算 SHA-256 並同步磁碟，再以短事務和原子重命名完成存儲。失敗清理本次臨時對象；啓動和每小時巡檢會在受限時間內清理超過 24 小時的未引用上傳殘留，保留近期傳輸和已引用原檔案。
- 檔案列表每頁 50 項，名稱搜索限定當前目錄；資源回收筒只顯示每次刪除的根條目。普通刪除將整個有效子樹一同移入資源回收筒。根目錄與包含預設上傳目錄的子樹不可刪除，需先更換預設目錄。
- 恢復時可選擇新目錄或名稱，重名、層級和成環檢查在事務中執行。永久刪除必須輸入界面當前語言顯示的確認短語，先記錄不可恢復的刪除狀態，再回收原檔案與其快取；中斷會在啓動和每小時巡檢繼續回收，保留元資料墓碑。此前單獨刪除的子項仍獨立保留在資源回收筒。
- 原檔案只通過鑒權介面下載，使用附件響應和 `nosniff`，不作為公開靜態資源。圖片預覽支持 PNG、JPEG、GIF 首幀、WebP，最多 2400 萬像素、單邊 16384 像素。伺服器端重新編碼為 PNG，樣式寬高 16–2048，最多 30 個；等比適配不放大，裁切填滿指定尺寸。
- UTF-8 文本按轉義文本預覽，最多 256 KB；HTML/SVG 不直接執行，其他檔案提供下載。快取根據原檔案對象鍵和樣式版本生成，讀取仍鑒權，不保留瀏覽器快取；磁碟樣式快取上限 128 MB，可在系統設定中清理。預覽授權本身允許讀取預覽內容，下載權限控制原檔案和樣式下載入口。

新增權限為 `menu:manage`、`file:read`、`file:upload`、`file:download`、`file:manage`、`file:styles`、`audit:read`、`system:read`、`system:settings`，預設只授予超級管理員。普通角色需要明確勾選。檔案查看、上傳、下載、管理分別校驗，檔案頁面可對僅上傳成員開放元資料列表，但不給予預覽和下載能力。總覽中的審計摘要也必須具有 `audit:read`。

審計記錄成功的管理變更，保存操作人、動作、資源摘要、伺服器端請求編號、方法和路徑，不記錄密碼、渠道密鑰或上傳正文。列表每次最多 50 條，使用編號游標載入更多；預設保留 90 天，可配置 7–365 天，每小時分批清理。歷史記錄沒有請求編號時如實顯示為空。運行資訊展示 Go/應用版本、SQLite 版本號、資料庫及原檔案佔用和待回收數量，不回顯主機絕對資料路徑。

## 應用密鑰、安裝包與編碼工具

在「應用與密鑰」創建應用，填寫不可變的 3–48 位小寫標識。每個應用最多 10 個未撤銷且未過期的密鑰，實例最多 200 個有效應用。密鑰使用 256 位隨機值，明文僅創建/輪換時返回一次，資料庫僅保存 SHA-256 摘要與短前綴；有效期 1–365 天。輪換在同一事務中撤銷舊密鑰並簽發新密鑰，撤銷、到期或停用應用後拒絕後續請求。歸檔應用前必須先歸檔它的安裝包，歸檔會撤銷全部密鑰。

瀏覽器繼續使用 Cookie + CSRF；程序接入單獨使用 `Authorization: Bearer $MONITOR_GO_API_KEY`，不接受查詢參數傳密鑰、不允許密鑰登錄管理介面。提供主機讀取、檢測狀態、告警讀取、安裝包列表與下載五個範圍，按需勾選。前三項是本實例共享資料，安裝包只限密鑰所屬應用。每個密鑰與來源 IP 每 5 分鐘最多 300 次請求，過限返回 429。完整協議及示例見 [應用分發與編碼工具](../zh-CN/APPLICATION_DISTRIBUTION.md)。

安裝包關聯已有檔案或直接上傳，也可使用不含使用者名/密碼的 HTTPS 外鏈。本地檔案關聯需要 `file:download`，直接上傳還需 `file:upload`。首次發佈後鎖定所屬應用、版本號、平台、架構與檔案來源；更新檔案應創建新版本。應用、版本號、平台與架構的組合在歸檔後仍不能重復使用。所有未歸檔安裝包（含草稿與下架）都阻止關聯檔案或父目錄移入資源回收筒，歸檔不刪除檔案。

只有已啓用應用下的已發佈版本可下載。本地下載支持 Range/HEAD 並返回 `X-Checksum-SHA256`；下載次數統計成功的 GET 請求（含分段），不代表安裝量。瀏覽器外鏈下載返回 302，統計跳轉次數；機器 API 返回外部 URL 的 JSON，調用方須另起不含應用密鑰的下載請求，該地址查詢不計下載次數。外部內容不由伺服器抓取、不提供外部檔案校驗值。私有部署首次不包含示例應用、密鑰或安裝包。

編碼工具在本實例生成，不保存輸入正文，不調用外部圖像服務。QR 碼支持 UTF-8、L/M/Q/H，內容最多 1200 位元組；Code 128 支持可打印 ASCII、Code 39 支持大寫字母與指定符號；EAN-13/8 自動補齊或檢查校驗位。導出 PNG 與安全的純幾何 SVG，自動保留靜區與整數模塊尺寸。寬度 128–2048 像素，條碼高度 80–512；尺寸不足返回所需寬度。改變內容後需重新生成才能導出。每人/來源 IP 每 5 分鐘最多生成 120 次，全局最多 2 個並行生成任務。正式印刷請實際試掃，生成 EAN 不等於取得商品編號。

新增 `application:read`、`application:manage`、`application:keys`、`release:read`、`release:manage`、`release:download`、`tool:generate` 七項權限，預設只給超級管理員。`application:keys` 是敏感權限，持有者可為應用簽發五種介面範圍；應用管理與密鑰管理可分別授權。只擁有安裝包權限的成員可讀應用目錄以選擇歸屬，但不能管理應用或讀取密鑰。

## 從早期版本升級

先正常停止舊服務並完整備份資料目錄（包括 `master.key` 和已有 `uploads/`），再用新二進制啓動同一目錄。已實現 v1 → v2 → v3 → v4 → v5 順序事務遷移：v2 添加 Agent 與通知，v3 添加菜單、檔案、圖片樣式、基礎設定和審計請求資訊。原有主機、使用者、檢測和告警保留。新增權限只授予內置超級管理員並撤銷其舊會話，其他角色需明確授權。v4 新增應用、密鑰和安裝包，以及按固定內置鍵分配的新導航，避免與已有自定義菜單編號衝突。舊版本二進制不能直接讀取 v5，回退需恢復整套升級前備份。

## 開發聯調

以下命令均在倉庫根目錄執行，使用隔離的開發資料目錄：

```sh
# 第一個終端：先建置 web/dist，供 Go 嵌入
make build
./bin/monitor -data tmp/development -listen 127.0.0.1:5093

# 第二個終端
MONITOR_GO_API_TARGET=http://127.0.0.1:5093 npm --prefix web run dev
```

打開 [前端開發預覽](http://127.0.0.1:5188/)。本例透過環境變數將 `/api` 代理到 5093；省略 `MONITOR_GO_API_TARGET` 時預設連線至 5080。首次使用 `tmp/development/setup-token` 初始化隔離實例，不能使用其他實例的帳號或初始化碼。5188 連接埠被佔用時會報錯，不會自動切換。Go 原始碼修改後需要重新建置並重新啟動服務；開發模式前端支援熱更新。

## 資料、調度與備份

- `data/monitor.db`：使用者、角色、會話、主機資料、採樣、檢測、執行任務、告警和審計。
- `data/master.key`：檢測訪問憑據的 AES-GCM 主密鑰，與資料庫分開保存。憑據介面不返回明文。
- `data/uploads/`：原檔案、上傳臨時對象和可重建的圖片快取，備份必須包含原檔案。
- `data/instance.lock`：實例鎖；運行資料、密鑰、構建產物均被 Git 忽略。
- 後台最多同時執行 4 項檢測，活動任務隊列最多 256 項，同目標活動任務合併；重啓後恢復未完成任務。
- 當前最多配置 500 個有效檢測目標，這是輸入上限，不代表已完成該規模壓力測試。單目標週期 15–86400 秒，超時 1–30 秒且短於週期。
- 主機指標與檢測歷史當前保留約 7 天，每小時分批清理；告警持續保留，審計按系統設定保留 7–365 天。曲線按時間桶聚合，缺失區間不補零，可用率為成功次數 / 總檢測次數。
- 告警確認、靜默或暫停檢測都不會偽造恢復。檢測連續異常達到目標閾值後創建事件，一次正常結果恢復；本機磁碟使用率閾值當前固定為 85%。
- 探測允許私網和回環，適合內部服務監測；拒絕鏈路本地、常見雲元資料、組播和未指定地址，HTTP 重定向也經過同一撥號檢查。HTTP/SSL 和啓用 TLS 的資料庫連接均校驗證書。

備份時先正常停止服務，再完整複製資料目錄，包括 SQLite 可能存在的伴隨檔案、`master.key` 與 `uploads/` 原檔案。恢復時整體放回並使用同版本啓動。當前沒有在線備份界面；運行中不要只複製 `monitor.db` 當作完整備份。

## 當前邊界

- Agent 當前採集主機資源，不執行遠程命令、服務探測或自動升級；檢測任務仍在監控伺服器端執行。
- 外部通知支持 SMTP 和通用 JSON Webhook，預設覆蓋全部資源的故障與恢復；尚未提供按資源路由、重復提醒、維護窗口，以及飛書 / 釘釘等專有消息模板。
- 當前權限樹提供 27 項實際權限。證書簽發仍按規劃實施。檔案僅支持本地私有存儲，不提供公開分享、雲存儲或 Office/PDF/視頻在線渲染。
- 已實現 SQLite v1 → v2 → v3 → v4 → v5 自動事務遷移，升級會撤銷超級管理員現有會話以載入新增權限；尚無在線備份界面和容量報告。

## 可信代理與登入限流

`-trusted-proxy` 接受逗號分隔的代理 CIDR，預設留空（不信任代理），無效值會阻止啟動。只填寫本程序實際看到的代理位址；代理必須覆寫或安全追加 `X-Forwarded-For`。伺服器從右向左尋找首個不可信位址，忽略其他來源的轉送標頭。登入只統計失敗：每個用戶端 IP 每 5 分鐘 30 次、每個正規化使用者名稱每 5 分鐘 10 次；成功登入不消耗也不重設計數。初始化對所有嘗試計數（每個 IP 每 5 分鐘 10 次）。

## 檢測編輯與封存

檢測清單支援完整編輯名稱、類型、位址、週期、逾時、閾值及憑證。密碼留空保留舊值，輸入新密碼則取代，勾選「清除已儲存的憑證」則清空；改為 HTTP/TCP/SSL 會清除資料庫憑證。儲存採版本校驗，重設目前狀態和排程並取消排隊工作，保留歷史與未恢復的告警。封存需要確認並停止後續檢測。唯讀成員沒有編輯或封存入口。409 衝突會重新載入伺服器資料並保留表單；再次儲存前請重新開啟編輯器核對最新設定。

預設實例名稱會隨介面語言切換，英文顯示 “My monitoring center”。在系統設定勾選「使用預設實例名稱」可恢復此行為；自訂名稱在所有語言下都保持原文。舊安裝未曾修改的預設名稱會自動識別，已儲存的名稱保留原文，須主動選擇預設名稱。
