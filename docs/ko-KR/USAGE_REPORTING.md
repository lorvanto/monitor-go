# 최초 활성화와 익명 설치 통계

[English](../en-US/USAGE_REPORTING.md) · [简体中文](../zh-CN/USAGE_REPORTING.md) · [日本語](../ja-JP/USAGE_REPORTING.md) · [한국어](../ko-KR/USAGE_REPORTING.md) · [繁體中文](../zh-TW/USAGE_REPORTING.md)

Monitor Go와 Monitor Console은 독립 저장소, 서비스 및 데이터베이스입니다. 소스와 데이터 디렉터리를 분리하세요. Monitor Go 설치에는 비공개 Console 소스가 필요하지 않습니다. 최초 설정에서 구성된 Console에 온라인 등록하며 이후 로컬 로그인, 모니터링 및 알림은 독립적으로 동작합니다.

표준 새 설치는 첫 로컬 관리자를 생성하기 전에 온라인 활성화가 필요합니다. 화면에서 정확한 목적지, 통계 목적, 항목 및 끄기 스위치 없는 지속 보고 규칙을 보여 주고 고지 버전 `2`를 명시적으로 확인합니다. 등록 실패 시 관리자는 생성되지 않으며 같은 임의 ID로 재시도합니다. 제품 사용자는 Console 계정이 필요하지 않습니다.

개별 설치 수, 활성 설치 수 및 제품 버전/운영체제 분포를 집계합니다. v2 등록은 `instanceId`, `credential`, `version`, `os`, 보고는 `instanceId`, `version`, `os`, `activeDays`를 포함합니다. 임의 ID로 중복을 제거하고 별도 자격 증명으로 인증하며 UTC 날짜별 활동을 집계합니다. 버전과 운영체제는 기술 분포이며 제품 사용자 계정과 연결하지 않습니다. 아키텍처, 배포 방식, 구성원 목록, 호스트 이름/IP, 모니터링 내용, 파일, 비밀번호 및 모니터링/애플리케이션 키는 보내지 않습니다. 익명 통계 User-Agent는 빌드 버전 없는 고정값입니다.

제품 사용자 계정 연결, 연결 코드, 사용자 목록 및 내 설치 기능은 폐기했습니다. Console은 통계 서비스를 관리할 관리자 자신의 인증 정보만 보관하며 이 관리자는 제품 사용자 수가 아닙니다. Monitor Go 로컬 관리자, 구성원 및 권한 기능은 독립적으로 유지됩니다.

임의 설치 ID를 중복 없이 집계하며 실제 사람 수를 나타내지 않습니다. 여러 사람이 한 설치를 사용해도 한 건이며 데이터 디렉터리 복제는 통계를 합칠 수 있고 새 빈 디렉터리는 다른 ID를 만들 수 있습니다. 원격 등록 후 로컬 설정 실패나 취소로 기록이 남을 수 있어 등록 수가 완료된 설치 수와도 같지는 않습니다.

활성화 후 독립 작업이 보고하며 이후 약 6시간마다 시간을 분산합니다. 요청은 5초 후 만료되고 리디렉션을 거부하며 제한된 백오프로 재시도합니다. 대기 중 UTC 활동 날짜는 최대 7일이고 자동 새로 고침이나 단순 페이지 로드는 활동이 아닙니다. Console은 일별 기록을 90일 보관하고 365일 동안 보고가 없는 설치를 정리하며 이후 다시 등록할 수 있습니다.

목적지가 같은 업그레이드는 ID, 자격 증명, 활성 상태, 과거 동의 및 활동 날짜를 유지합니다. 항목 축소로 새 동의를 꾸미지 않으며 고지 버전은 `2`입니다. 이전 버전에서 꺼진 설치는 관리자가 현재 목적지와 규칙을 확인하고 등록에 성공해야 켜집니다. 확인 대기나 Console 장애는 로컬 로그인, 모니터링 및 알림을 중단하지 않습니다. 목적지를 바꿀 때는 새 목적지를 확인하기 전 전송하지 않습니다. 지속 보고에는 끄기 스위치가 없으며 끄기 요청은 HTTP 403입니다.

먼저 Monitor Console을 스키마 `3`으로, 다음으로 Monitor Go를 스키마 `11`로 업그레이드하세요. 새 클라이언트는 `/api/v2/instances/register`와 `/api/v2/instances/report`를 사용합니다. Console v1 등록/보고는 이전 클라이언트와 호환되며 버전과 운영체제는 보관하고 아키텍처 및 배포 방식은 저장하거나 반환하지 않고 버립니다. 연결 API는 폐기했습니다. Monitor Go v11은 이전 `usage_settings.account_login` 스냅샷을 물리적으로 삭제하고 Console v3은 아키텍처, 배포 방식, 계정 연결 및 연결 코드를 제거합니다. 버전/운영체제 분포와 익명 집계는 보존합니다.

업그레이드 전에 정상 종료하고 두 서비스의 데이터 디렉터리를 각각 전체 백업하세요. 롤백은 각 이전 이미지/실행 파일과 전체 사전 백업을 복원해야 하며 데이터베이스를 공유하지 마세요. 옛 백업에는 폐기된 정보가 남을 수 있으므로 비공개로 관리하세요. 목적지가 같은 확인된 설치의 데이터를 지워 다시 활성화할 필요는 없습니다.

`MONITOR_CONSOLE_URL`이 없으면 내장 기본 HTTPS 오리진을 사용하며 실제 주소는 설치/확인 화면에 표시됩니다. 명시한 환경 값은 기본값보다, `-console-url`은 환경 변수보다 우선합니다. 이전 백엔드를 계속 쓰려면 업그레이드 전에 해당 HTTPS 오리진을 명시하세요. 빈 값이나 공백뿐인 목적지는 무효입니다. 옛 `-require-activation=false` / `MONITOR_REQUIRE_ACTIVATION=false` 설정은 거부하며 `true`는 호환됩니다. 버전 조회와 백업은 활성화 설정에 의존하지 않습니다.

HTTPS가 필요하며 숫자 루프백 HTTP는 격리 테스트 전용입니다. 자격 증명, 데이터 및 백업을 Git에 저장하지 말고 통계 프록시 로그에 전체 원본 IP나 자격 증명을 남기지 마세요. `MONITOR_DEPLOYMENT` / `-deployment`는 로컬 실행 방식을 표시하는 호환 설정이며 익명 통계 항목으로 보내지 않습니다.

```sh
./bin/monitor -data data -listen 127.0.0.1:5080
```
