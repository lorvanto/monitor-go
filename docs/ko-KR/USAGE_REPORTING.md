# 선택적 사용 현황 보고

[English](../en-US/USAGE_REPORTING.md) · [简体中文](../zh-CN/USAGE_REPORTING.md) · [日本語](../ja-JP/USAGE_REPORTING.md) · [한국어](../ko-KR/USAGE_REPORTING.md) · [繁體中文](../zh-TW/USAGE_REPORTING.md)

Monitor Go와 Monitor Console은 독립적인 저장소와 서비스입니다. 같은 상위 폴더 아래에 별도 디렉터리와 데이터를 사용하세요. 통계 서버 없이도 모니터링은 작동합니다.

두 프로젝트를 함께 유지 관리할 때는 소스 디렉터리를 같은 상위 폴더에 따로 두고 데이터도 분리하세요. 일반 Monitor Go 설치에는 이 공개 저장소만 필요합니다. 선택적 보고에는 접속 가능한 통계 서비스가 필요하지만 비공개 소스에 대한 접근은 필요하지 않습니다.

새 설치와 이 기능이 없는 이전 버전에서의 업그레이드는 기본적으로 보고가 꺼져 있습니다. 이후 재시작이나 업그레이드에서는 동일한 수신 주소에 대해 관리자가 저장한 선택을 유지합니다. 서버에 콘솔 주소를 설정한 후 system:settings 권한의 관리자가 시스템 설정에서 전송 항목을 확인하고 명시적으로 켭니다. 주소만 설정해도 보고가 켜지는 것은 아닙니다. 수신 주소를 변경하면 다시 동의해야 합니다.

전송 항목은 임의 설치 ID, 버전, 운영체제, CPU 아키텍처, 배포 방식, 로그인한 사람이 화면을 조작한 UTC 날짜입니다. 로컬 계정 목록, 모니터링 대상, 호스트 이름/IP, 파일, 알림 본문, 비밀번호, 모니터링 키 또는 애플리케이션 키는 포함하지 않습니다. 설치 자격 증명은 등록과 인증에만 사용하며 화면에 표시하지 않습니다. 콘솔 로그인은 자발적으로 연결한 GitHub ID, 사용자 이름 및 표시 이름을 별도로 보관합니다.

GitHub로 Monitor Console에 로그인하여 10분 동안 유효한 일회용 연결 코드를 생성하고 Monitor Go 보고 설정에 붙여넣습니다. 먼저 보고를 켜야 합니다. 연결 해제는 계정 연결만 제거하며 보고를 중지하지 않습니다. 콘솔에서도 자신의 설치 연결을 해제할 수 있습니다.

“마지막으로 동기화된 GitHub 계정”은 로컬에 저장된 정보입니다. Monitor Console에서 연결을 해제하면 Monitor Go의 표시는 다음 보고가 성공한 뒤에 갱신됩니다. 보고가 꺼져 있는 동안에는 콘솔에 연결하지 않으므로 이전 계정이 계속 표시될 수 있습니다. “전송 상태 새로 고침”은 로컬 설정만 다시 읽으며 콘솔에 요청하거나 원격 동기화를 시작하지 않습니다.

활성화 후 독립 작업이 한 번 전송하고 이후 약 6시간마다 시간을 분산하여 보고합니다. 요청 제한 시간은 5초이며 리디렉션을 허용하지 않고 제한된 백오프로 재시도합니다. 대기 중 활동 날짜는 최대 7일입니다. 자동 새로 고침과 페이지 로드만으로 활동을 집계하지 않습니다. 일별 집계는 설치 단위 중복을 제거하며 사람 수를 나타내지 않습니다. 자체 보고 추정치이므로 신원이나 전체 설치 수의 증명이 아닙니다.

언제든 끌 수 있습니다. 진행 중 요청을 취소하고 대기 중 활동을 지웁니다. 모니터링, 알림 및 로그인은 독립적으로 동작합니다. 이미 수신한 기록은 삭제하지 않습니다. 일별 기록은 90일, 보고가 없는 설치는 365일 후 삭제됩니다. 이후 다시 등록하면 계정을 다시 연결해야 합니다.

HTTPS가 필요하며 숫자 루프백 HTTP는 로컬 통합 테스트에만 허용됩니다. 기본 공식 콘솔 도메인은 없습니다. 컨테이너 루프백은 자신을 가리키므로 별도 컨테이너에는 실제 HTTPS 주소를 사용하세요. 자격 증명, 데이터와 백업을 Git에 저장하지 마세요. 프록시 로그에 OAuth 쿼리, 전체 원본 IP나 자격 증명을 남기지 마세요.

스키마 9는 보고 설정과 활동 날짜를 추가합니다. 업그레이드 전에 전체 데이터 디렉터리를 백업하고 롤백 시 이전 백업을 복원하세요. 설치 ID는 데이터 디렉터리에 유지되며 복제하면 통계가 합쳐질 수 있습니다. 보고를 끄거나 오프라인 또는 수정된 설치를 모두 집계할 수는 없습니다.

```sh
MONITOR_CONSOLE_URL=https://console.example.com ./bin/monitor -data data -listen 127.0.0.1:5080
```

`MONITOR_CONSOLE_URL` / `-console-url`; `MONITOR_DEPLOYMENT=native|docker` / `-deployment`.

네이티브 실행 파일의 기본값은 `native`이며 Docker 이미지와 Compose는 자동으로 `docker`를 설정합니다.
