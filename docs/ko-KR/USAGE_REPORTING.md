# 최초 활성화와 사용 현황 보고

[English](../en-US/USAGE_REPORTING.md) · [简体中文](../zh-CN/USAGE_REPORTING.md) · [日本語](../ja-JP/USAGE_REPORTING.md) · [한국어](../ko-KR/USAGE_REPORTING.md) · [繁體中文](../zh-TW/USAGE_REPORTING.md)

Monitor Go와 Monitor Console은 독립적인 저장소, 서비스 및 데이터베이스입니다. 소스와 데이터 디렉터리를 분리하세요. Monitor Go 설치에는 공개 저장소만 필요하며 비공개 Console 소스는 필요하지 않습니다. 표준 최초 설정에서는 구성된 Console에 연결해 온라인 활성화를 수행합니다. 이후 로그인, 모니터링 및 알림은 독립적으로 동작합니다.

표준 새 설치에서는 첫 로컬 관리자를 만들기 전에 온라인 활성화가 필요합니다. 설정 화면에 목적지(기본값 `https://feiniu.i7f.cn:5090`), 통계 목적 및 전송 항목을 표시하고 확인란을 직접 선택해야 합니다. 설치 등록에 성공한 뒤 관리자를 만들고 보고를 켭니다. 로컬 사용자 이름, 표시 이름 및 비밀번호는 전송하지 않습니다. 등록에 실패하면 관리자는 생성되지 않으며 연결을 복구한 뒤 같은 설치 ID로 다시 시도할 수 있습니다. Console 계정이나 GitHub 로그인은 필요하지 않으며 개발자 계정에 자동으로 연결하지 않습니다.

이미 초기화된 설치를 업그레이드할 때 활성화를 강제하거나 보고를 몰래 켜지 않으며 동일한 목적지의 저장된 선택을 유지합니다. 이 기능이 없던 기존 설치는 계속 꺼진 상태입니다. `system:settings` 권한의 관리자가 나중에 항목을 확인하고 켤 수 있습니다. 목적지를 바꾸면 다시 동의해야 합니다. 활성화 후에도 보고를 끌 수 있으며 Console 장애가 로그인, 모니터링 또는 알림을 차단하지 않습니다.

전송 항목은 임의 설치 ID, 버전, 운영체제, CPU 아키텍처, 배포 방식, 로그인한 사람이 화면을 조작한 UTC 날짜입니다. 로컬 계정 목록, 모니터링 대상, 호스트 이름/IP, 파일, 알림 본문, 비밀번호, 모니터링 키 또는 애플리케이션 키는 포함하지 않습니다. 설치 자격 증명은 등록과 인증에만 사용하며 화면에 표시하지 않습니다. Console 계정은 Monitor Go와 별개입니다. 로컬 계정은 사용자 이름과 표시 이름을 보관하며 선택적 GitHub 로그인에서는 검증된 GitHub ID, 사용자 이름 및 표시 이름을 별도로 보관합니다.

설치 등록과 활동 통계에는 계정 연결이 필요하지 않습니다. Console은 로컬 관리자 사용자 이름과 비밀번호로 로그인할 수 있으며 GitHub 로그인은 선택 사항입니다. Monitor Go 설치에는 OAuth 설정이 필요하지 않습니다.

계정을 선택적으로 연결하려면 로컬 Console 계정 또는 활성화된 GitHub 로그인으로 Monitor Console에 로그인하여 10분 동안 유효한 일회용 연결 코드를 생성하고 Monitor Go 보고 설정에 붙여넣습니다. 먼저 보고를 켜야 합니다. 연결 해제는 계정 연결만 제거하며 보고를 중지하지 않습니다. 콘솔에서도 자신의 설치 연결을 해제할 수 있습니다.

“마지막으로 동기화된 Console 계정”은 로컬에 저장된 정보입니다. Monitor Console에서 연결을 해제하면 Monitor Go의 표시는 다음 보고가 성공한 뒤에 갱신됩니다. 보고가 꺼져 있는 동안에는 콘솔에 연결하지 않으므로 이전 계정이 계속 표시될 수 있습니다. “전송 상태 새로 고침”은 로컬 설정만 다시 읽으며 콘솔에 요청하거나 원격 동기화를 시작하지 않습니다.

활성화 후 독립 작업이 한 번 전송하고 이후 약 6시간마다 시간을 분산하여 보고합니다. 요청 제한 시간은 5초이며 리디렉션을 허용하지 않고 제한된 백오프로 재시도합니다. 대기 중 활동 날짜는 최대 7일입니다. 자동 새로 고침과 페이지 로드만으로 활동을 집계하지 않습니다. 일별 집계는 설치 단위 중복을 제거하며 사람 수를 나타내지 않습니다. 자체 보고 추정치이므로 신원이나 전체 설치 수의 증명이 아닙니다.

원격 등록 성공 후 로컬 설정이 실패하거나 취소되면 연결되지 않은 임의 설치 기록이 Console에 남을 수 있습니다. 재시도 시 같은 ID를 사용합니다. 따라서 등록 수는 완료된 설치 수나 실제 사용자 수와 같지 않습니다.

언제든 끌 수 있습니다. 진행 중 요청을 취소하고 대기 중 활동을 지웁니다. 모니터링, 알림 및 로그인은 독립적으로 동작합니다. 이미 수신한 기록은 삭제하지 않습니다. 일별 기록은 90일, 보고가 없는 설치는 365일 후 삭제됩니다. 이후 다시 등록하면 계정을 다시 연결해야 합니다.

HTTPS가 필요하며 숫자 루프백 HTTP는 로컬 통합 테스트에만 허용됩니다. 컨테이너 루프백은 자신을 가리키므로 별도 컨테이너에는 실제 HTTPS 주소를 사용하세요. 자격 증명, 데이터와 백업을 Git에 저장하지 마세요. 프록시 로그에 OAuth 쿼리, 전체 원본 IP나 자격 증명을 남기지 마세요.

스키마 10은 스키마 9의 보고 설정에 고지 버전, 동의 시각 및 활성화 시각을 추가합니다. 업그레이드 전에 전체 데이터 디렉터리를 백업하고 롤백 시 이전 백업을 복원하세요. 설치 ID는 데이터 디렉터리에 유지되며 복제하면 통계가 합쳐질 수 있습니다. 보고를 끄거나 오프라인 또는 수정된 설치를 모두 집계할 수는 없습니다.

`MONITOR_CONSOLE_URL`을 설정하지 않으면 네이티브 실행 파일과 Compose는 `https://feiniu.i7f.cn:5090`을 사용합니다. 다른 HTTPS 오리진을 지정해 목적지를 바꾸거나, `MONITOR_CONSOLE_URL=`로 명시적으로 비워 목적지 설정을 해제할 수 있습니다. 네이티브 실행 파일의 `-console-url` 인수가 환경 변수보다 우선하며, `-console-url=`도 목적지 설정을 해제합니다.

표준 CLI와 Compose의 `MONITOR_REQUIRE_ACTIVATION` / `-require-activation` 기본값은 `true`입니다. 자체 배포판 또는 오프라인 환경에서는 `MONITOR_REQUIRE_ACTIVATION=false` 또는 `-require-activation=false`를 명시하세요. 그러면 로컬에서 설정을 완료하며 별도로 켜기 전까지 보고는 꺼진 상태입니다. Console URL을 비우는 것만으로 필수 활성화를 건너뛸 수 없습니다. 유효한 목적지를 설정하거나 요구 사항을 명시적으로 꺼야 합니다. 명령줄 인수가 환경 변수보다 우선합니다.

```sh
./bin/monitor -data data -listen 127.0.0.1:5080
```

오프라인 설치를 명시적으로 선택하는 예:

```sh
./bin/monitor -data data -listen 127.0.0.1:5080 -require-activation=false -console-url=
```

`MONITOR_CONSOLE_URL` / `-console-url`; `MONITOR_REQUIRE_ACTIVATION` / `-require-activation`; `MONITOR_DEPLOYMENT=native|docker` / `-deployment`.

네이티브 실행 파일의 기본값은 `native`이며 Docker 이미지와 Compose는 자동으로 `docker`를 설정합니다.
