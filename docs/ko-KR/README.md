# Monitor Go — 사용 안내

[English](../en-US/README.md) · [简体中文](../zh-CN/README.md) · [日本語](../ja-JP/README.md) · **한국어** · [繁體中文](../zh-TW/README.md) · [Documentation](../README.md)

> 상태: 공개 전 개발 기준은 `0.4.0-dev`, SQLite 스키마는 `8`입니다. 이미 배포된 릴리스를 뜻하지 않습니다. 명령 예시는 POSIX 셸용이며 Windows에서는 WSL을 사용할 수 있습니다.

스키마 5는 대기 중인 작업의 부분 인덱스를 추가하여 완료된 작업 이력을 전체 검색하지 않도록 합니다. 작업 보존 기간은 7일로 유지합니다. 업그레이드 전 서비스를 중지하고 전체 데이터 디렉터리를 백업하세요. 이전 실행 파일은 스키마 8을 읽을 수 없으며 롤백에는 전체 백업이 필요합니다.

기능별 화면은 [영어 UI 스크린샷](../../README.md#screenshots)에서 확인할 수 있습니다. 모든 운영 데이터는 데모용 가상 데이터이며, 처음 접속할 때의 기본 언어는 영어입니다.

## 제품 범위와 구현된 기능

Go, React 19, 내장 SQLite를 사용하는 자체 호스팅 모니터링 및 운영 시스템입니다. 팀이 하나의 설치와 리소스를 공유하며 멀티테넌트 구조는 아닙니다. 생성자 정보는 감사 용도입니다. MySQL과 Redis는 점검 대상이며 저장소나 필수 서비스가 아닙니다.

개요, 로컬 및 원격 호스트 지표, HTTP/TCP/SSL/MySQL/Redis 점검, 장애 처리, 역할과 구성원, SMTP/Webhook 알림, 메뉴, 비공개 파일, 이미지 스타일, 감사, 설정, 애플리케이션 키, 패키지 배포, QR 코드와 바코드를 구현했습니다. 밝은/어두운 테마와 키보드 페이지 검색도 제공합니다. 메뉴 표시와 API 권한 검사는 독립적입니다.

## 프런트엔드 구성

React / React DOM 19.3.0, TypeScript 5.9.3, Vite 8.3.4, Zustand 5.0.15를 사용합니다. 정적 파일을 Go 서버에 내장하므로 운영 환경에 Node.js 서버가 필요하지 않습니다. `web/src/views/`의 화면은 `React.lazy`로 불러옵니다. 공통 TSX 컴포넌트는 `components/`, 세션·권한·탐색 상태는 `stores/app.ts`, 타입·차트·표시 형식은 `lib/`에 둡니다. 다섯 언어의 카탈로그는 `locales/`에서 공유합니다.

`npm --prefix web test`는 언어 테스트와 Vitest / React Testing Library 상호작용 테스트를 실행합니다. `npm --prefix web run typecheck`는 앱과 테스트의 타입을 검사합니다. 기존 API, CSRF, 업로드, SQLite 계약을 유지하며 이번 전환에는 DB 변경이 없습니다. 반영하려면 Go 바이너리를 다시 빌드하고 재시작해야 합니다.

이전 로그인 세션이나 선택 항목에 대한 늦은 응답은 무시합니다. 호스트 메모와 알림 일시 중지는 대화상자를 열었을 때의 대상과 버전을 유지합니다. 파일의 마지막 페이지가 비면 페이지 번호를 조정하며, 감사 로그를 불러오는 중에도 검색 조건을 지울 수 있습니다. 브라우저에서 환경 설정을 저장할 수 없어도 테마를 변경할 수 있습니다. 페이지 로딩에 실패하면 새로 고침 버튼을 표시하고 저장하지 않은 변경 사항이 사라진다고 안내합니다.

## Docker 배포

호스트에 Go/Node.js를 설치하지 않고 Docker 및 Compose로 빌드하고 실행할 수 있습니다.

```sh
docker compose up -d --build
docker compose exec monitor cat /data/setup-token
```

5080에서 초기화 코드로 관리자를 만드세요. 이름 있는 볼륨에 전체 데이터를 보존합니다. 컨테이너 호스트 수집은 기본적으로 꺼져 있으므로 실제 호스트에는 네이티브 Agent를 사용하세요. 포트 변경, HTTPS, 백업/복원 및 업데이트는 [Docker 배포 안내](DOCKER.md)를 참고하세요.

## 빌드와 첫 실행

Go 1.26.9 이상의 호환 버전 및 Node.js 22.12+ / 24.x를 사용하세요. 잠금 파일을 유지하고 이 저장소에서 실행합니다.

```sh
make build
./bin/monitor -data data -listen 127.0.0.1:5080
```

[로컬 서비스](http://127.0.0.1:5080/)를 열고 서버의 `data/setup-token`을 읽어 초기화 코드, 사용자 이름, 이름, 비밀번호를 입력하세요. 기본 계정이나 비밀번호는 없습니다. 초기화 완료 후 코드 파일을 삭제합니다. 비밀번호는 12~72바이트입니다. 세션은 HttpOnly 쿠키 및 CSRF 검증을 사용하며 API 요청마다 권한을 확인합니다.

서버 실행 파일에는 화면 리소스가 포함됩니다. 실행 시 Java, Node.js, 외부 데이터베이스가 필요하지 않습니다. 여러 실행 프로세스가 같은 데이터 디렉터리를 공유할 수 없습니다.

팀이 접근하려면 신뢰할 수 있는 HTTPS 역방향 프록시를 사용하세요.

```sh
./bin/monitor -data data -listen 127.0.0.1:5080 \
  -public-url https://monitor.example.com -secure-cookie
```

`-public-url`은 브라우저에서 접근하는 정확한 오리진이며 끝에 슬래시를 붙이지 않습니다. `-collect-host=false`로 로컬 호스트 수집을 끌 수 있습니다.

## 화면 언어

로그인/초기화 화면 또는 로그인 후 사이드바에서 简体中文, English, 日本語, 한국어, 繁體中文을 선택하세요. 처음 방문하면 브라우저 언어와 관계없이 영어로 표시합니다. 이후에는 저장된 유효한 선택을 복원하며, 선택이 없거나 유효하지 않거나 브라우저 저장소를 사용할 수 없으면 영어를 사용합니다. `zh-Hant`, `zh-HK`, `zh-MO`는 번체 중국어에 대응합니다.

고정 문구, 기본 탐색 메뉴, 권한, API 범위, 날짜, 숫자, 차트 표시를 전환합니다. 페이지를 새로 고치지 않으며 편집 중인 폼도 유지합니다. 시간대는 브라우저의 로컬 시간대를 사용합니다. 언어 팩은 필요할 때 불러오며 선택은 브라우저의 `monitor.locale`에 저장됩니다.

이름, 메모, 파일 내용, 저장된 알림/감사 기록, 점검 진단, 알림 본문, 서버/Agent 로그는 원문을 유지합니다. 언어 변경은 업무 데이터를 다시 쓰지 않습니다. 이름을 변경한 메뉴는 입력한 그대로 표시됩니다.

## 모니터링과 원격 호스트

호스트 지표를 약 15초마다 수집합니다. 서비스 점검은 모니터링 서버에서 실행됩니다. 연속 이상이 임계값에 도달하면 알림을 생성하고 다음 정상 결과로 복구합니다. 확인하거나 알림을 중지하는 것만으로 복구 처리하지 않습니다.

호스트 상세에서 15분 동안 유효한 등록 코드를 발급하고 대상 시스템과 아키텍처에 맞는 Agent를 준비하세요.

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o bin/agent-linux-amd64 ./cmd/agent
# ARM64 호스트는 GOARCH=arm64를 사용합니다.
```

원격 호스트에 Agent와 `enrollment-token`을 배치합니다.

```sh
chmod 600 enrollment-token
./agent -server https://monitor.example.com -enrollment-file enrollment-token -config agent-data/config.json
# 이후 실행:
./agent -config agent-data/config.json
```

유효하고 신뢰할 수 있는 HTTPS 인증서가 필요합니다. 사설 CA는 `-ca-file`로 지정할 수 있습니다. 숫자 루프백 주소만 로컬 HTTP 테스트를 허용합니다. Agent는 아웃바운드로 접속하므로 인바운드 포트를 열 필요가 없습니다. 자격 증명을 다른 호스트에 복사하지 마세요. 철회하거나 다시 등록하면 기존 자격 증명이 무효화됩니다. 연결이 끊긴 동안의 지표는 버퍼링하지 않습니다. 90초 이상 보고가 없으면 다음 순회 시점(최대 추가 10초)에 오프라인 장애가 생성됩니다.

[systemd 템플릿](../../deploy/monitor-go-agent.service)을 사용하려면 배포자가 사용자와 데이터 디렉터리를 먼저 만들어야 합니다. 시스템 서비스는 자동 설치되지 않습니다. Agent는 호스트 리소스만 수집하며 원격 명령이나 서비스 점검을 실행하지 않습니다.

## 알림, 파일 및 배포

알림 센터에서 SMTP, 일반 Webhook 또는 아래의 채팅 봇 형식을 설정하세요. SMTP는 TLS/STARTTLS, Webhook은 HTTPS가 필요합니다(숫자 루프백의 HTTP 테스트 제외). 전송 작업은 영구 저장되며 최대 4회 시도합니다. 최소 한 번 전송 방식이므로 Webhook 수신자는 `X-MonitorGo-Delivery-ID`로 중복을 제거해야 합니다. SMTP 수신 성공이 받은편지함 도착을 보장하지는 않습니다. 알림 중지 기간의 미전송 알림은 나중에도 보내지 않습니다.

서명은 `X-MonitorGo-Signature: sha256=<HMAC-SHA256 16진수>`입니다. 시간 헤더, 마침표, 원본 본문 바이트를 연결하여 서명합니다. 수신 측에서 서명과 허용 시간 범위를 검증하세요.

파일은 설치 내부에서 공유하는 비공개 리소스입니다. 업로드, 미리 보기, 다운로드, 관리 권한을 각각 부여합니다. 휴지통도 저장 한도에 포함됩니다. 영구 삭제 시 현재 언어로 표시된 확인 문구를 입력합니다. 원본은 `data/uploads/`에 저장하고 이미지 스타일은 파생 이미지만 생성합니다.

애플리케이션을 만들면 범위가 지정된 키와 패키지를 관리할 수 있습니다. 전체 키는 발급/교체 시 한 번만 표시하며 해시만 저장합니다. 프로그램은 `/api/v1/integrations`에 `Authorization: Bearer ...`로 접근합니다. 관리 화면 로그인에는 사용할 수 없습니다. 호스트/점검/알림 범위는 인스턴스 공유 리소스에 적용되며 패키지는 키의 소속 애플리케이션으로 제한됩니다.

게시 후에는 소속 애플리케이션, 버전, 플랫폼, 아키텍처 및 파일 출처가 잠깁니다. 파일 교체에는 새 버전이 필요합니다. 외부 주소는 HTTPS여야 하며 외부 다운로드에 애플리케이션 키를 전달하지 마세요. QR 코드와 바코드는 로컬에서 생성하며 입력 내용을 저장하지 않고 PNG/SVG로 내보냅니다.

## 개발 및 검증

저장소 루트에서 격리된 개발용 데이터 디렉터리를 사용하세요.

```sh
make build
./bin/monitor -data tmp/development -listen 127.0.0.1:5093
# 다른 터미널:
MONITOR_GO_API_TARGET=http://127.0.0.1:5093 npm --prefix web run dev
```

프런트엔드는 5188에서 실행되며 이 예시에서는 `/api`를 5093으로 전달합니다. `MONITOR_GO_API_TARGET`을 생략하면 기본값은 5080입니다. 처음에는 `tmp/development/setup-token`으로 격리된 인스턴스를 초기화하세요. Go 변경 후에는 다시 빌드하고 재시작하세요.

```sh
make test
npm --prefix web run typecheck
npm --prefix web run check:i18n
npm --prefix web run check:docs
npm --prefix web test
npm --prefix web run format:check
```

`make test`는 화면 빌드, 언어 테스트, Go 경쟁 조건 검사 및 vet를 실행합니다. API 통합 테스트는 실제 임시 SQLite 파일을 사용합니다. [번역 유지 관리](INTERNATIONALIZATION.md)도 참고하세요.

## 백업, 업그레이드 및 제한

서비스를 정상 종료한 후 SQLite와 관련 파일, `master.key`, `uploads/` 원본을 포함한 전체 데이터 디렉터리를 백업하세요. 실행 중인 `monitor.db`만 복사하는 것은 전체 백업이 아닙니다. 호환되는 서버 버전으로 전체 디렉터리를 복원하세요.

스키마 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8를 트랜잭션으로 마이그레이션합니다. 구버전 실행 파일은 스키마 8을 직접 읽을 수 없으며 롤백에는 업그레이드 전 전체 백업이 필요합니다. 사용자 지정 역할에 새 권한을 자동으로 부여하지 않습니다. 이번 국제화에는 새 스키마 마이그레이션이 필요하지 않습니다.

멀티테넌트, 외부 저장소, 원격 명령, Agent 자동 업데이트, 온라인 백업 화면, 공개 파일 공유은 제공하지 않습니다. 인증서 발급은 계획 단계입니다. 점검 500개 및 Agent 1000대는 설정 제한이며 부하 검증된 용량이 아닙니다. 실제 Linux 수집, 실제 메일 사업자 전송, 용량은 배포 환경에서 검증해야 합니다.

[중국어 문서 색인](../zh-CN/INDEX.md)에는 기록과 설계 제안이 포함되어 있으며 모두 구현된 것은 아닙니다. 소스 저장소는 [lorvanto/monitor-go](https://github.com/lorvanto/monitor-go)입니다. 릴리스 태그 및 지원 대상 플랫폼은 추후 확정합니다. 프로젝트 코드와 문서는 [Apache-2.0](../../LICENSE)을 사용하며 의존성은 각각의 라이선스를 유지합니다. [GitHub 공개 및 기여 안내](GITHUB.md)도 참고하세요.

다섯 언어의 현행 안내는 `docs/<locale>/`에 정리하며 디렉터리와 파일 이름은 영어를 사용합니다. [문서 목록](../README.md)에서 확인할 수 있습니다.

## 신뢰할 프록시와 로그인 제한

`-trusted-proxy`는 쉼표로 구분한 프록시 CIDR 목록이며 기본값은 비어 있습니다(신뢰 없음). 잘못된 CIDR은 시작 오류를 발생시킵니다. 이 프로세스에서 보이는 실제 프록시만 지정하고 프록시가 `X-Forwarded-For`를 덮어쓰거나 안전하게 추가하도록 설정하세요. 서버는 오른쪽부터 확인하여 처음 만나는 신뢰 대상 밖의 주소를 사용합니다. 다른 연결의 헤더는 무시합니다. 로그인 실패만 집계하며 5분당 클라이언트 IP별 30회, 정규화된 사용자 이름별 10회입니다. 성공해도 횟수를 사용하거나 초기화하지 않습니다. 초기 설정은 모든 시도를 집계합니다(IP별 5분당 10회).

## 점검 편집 및 보관

점검에서 이름, 유형, 대상, 주기, 제한 시간, 임계값, 인증 정보를 편집할 수 있습니다. 비밀번호를 비우면 기존 값을 유지하고 새 값을 입력하면 교체하며 삭제를 선택하면 인증 정보를 지웁니다. HTTP/TCP/SSL로 변경해도 데이터베이스 인증 정보를 지웁니다. 버전을 확인한 뒤 현재 상태와 일정을 초기화하고 대기 작업을 취소합니다. 기록과 미해결 알림은 유지됩니다. 보관은 확인 후 이후 점검을 중지합니다. 읽기 전용 구성원에게는 편집과 보관이 표시되지 않습니다. 409 충돌 시 입력을 유지하며 서버 데이터를 새로 불러옵니다. 다시 저장하기 전에 편집기를 다시 열어 최신 설정을 확인하세요.

기본 인스턴스 이름은 화면 언어에 맞춰 바뀌며 영어에서는 “My monitoring center”로 표시됩니다. 시스템 설정에서 기본 이름 사용을 선택하면 이 동작을 복원합니다. 사용자 지정 이름은 모든 언어에서 입력한 그대로 유지됩니다. 이전 설치의 미수정 기본 이름은 자동 인식하며, 이미 저장한 이름은 기본 이름을 명시적으로 선택할 때까지 유지합니다.

## 채팅 봇 Webhook

일반, DingTalk, Feishu, WeCom 형식을 선택할 수 있으며 기존 채널은 일반 형식을 유지합니다. DingTalk는 Markdown과 URL의 밀리초 타임스탬프/서명을, Feishu는 텍스트와 본문의 초 단위 타임스탬프/서명을 사용합니다. WeCom은 Markdown을 사용하며 URL의 `key`가 키이므로 별도 서명 키가 필요 없습니다. 편집기에서 형식을 바꾸면 이전 서명 키를 지웁니다.

일반 형식의 JSON과 서명 헤더 계약은 유지됩니다. 봇 형식은 HTTP 성공과 함께 DingTalk/WeCom의 `errcode` 또는 Feishu의 `code`가 0이어야 성공합니다. 코드 누락이나 잘못된 응답은 실패이며 15초, 1분, 5분 뒤 재시도합니다. 이벤트, 원문 제목/리소스/설명, 심각도, UTC 시각, 전송 ID를 포함하며 고정 라벨은 영어입니다. WeCom의 4096바이트 제한을 맞추기 위해 긴 알림 필드만 줄이고 저장된 경보는 변경하지 않습니다. 실제 플랫폼 전송은 검증하지 않았으며 로컬 HTTP 테스트로 형식, 서명, 오류와 재시도를 검증했습니다. 배포 시 본인 봇으로 테스트 전송하세요.

[DingTalk](https://open.dingtalk.com/document/robots/customize-robot-security-settings) · [Feishu](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot) · [WeCom](https://developer.work.weixin.qq.com/document/path/91770)

## 호스트 알림 임계값

시스템 설정에서 전체 호스트의 CPU, 메모리, 디스크 임계값(기본값 90%, 90%, 85%)과 지속 시간 1–60분(기본값 5분)을 설정합니다. 개별 임계값을 0으로 설정하면 해당 지표 알림을 끕니다. 스키마 6에 범위 제한이 있는 설정을 추가했습니다. 업그레이드 전에 서비스를 중지하고 전체 데이터 디렉터리를 백업하세요. 이전 실행 파일은 스키마 8을 읽을 수 없습니다.

로컬과 원격 호스트는 같은 규칙을 사용합니다. CPU와 메모리는 전체 지속 시간 동안 임계값 이상이어야 합니다. 시작 시각 또는 그 이전 샘플을 포함해 전체 구간을 확인하며, 누락된 값이나 45초 초과 간격이 없어야 합니다. 데이터가 부족하면 새 알림을 만들지 않으며 기존 알림도 복구하지 않습니다. 최신 유효 값이 임계값 미만이면 복구합니다. 디스크는 최신 유효 샘플로 즉시 판단합니다. 임계값 변경과 비활성화는 다음 보고부터 적용하며 비활성화된 지표의 알림은 복구됩니다. 원격 호스트의 90초 오프라인 규칙은 동일합니다. 호스트별 재정의는 아직 구현하지 않았습니다.

## 페이지별 새로 고침과 목록 쿼리

보이는 페이지는 10초마다 필요한 호스트, 점검, 알림 데이터와 세션 및 탐색 메뉴만 새로 고칩니다. 다른 페이지는 가벼운 개수 API로 모바일 배지를 갱신하며 대상은 목록과 동일한 최근 200개 이벤트입니다. 역할, 구성원, 권한은 해당 페이지 진입이나 변경 후에만 읽고 주기적으로 요청하지 않습니다. 페이지 전환과 쓰기 후 새로 읽으며 이전 페이지나 세션의 응답은 버립니다. 점검 목록은 SQL 3회, 알림 목록은 2회를 사용하고 응답 형식, 24시간 가용률, 최근 32개 점검 결과 및 이벤트별 최근 100개 활동을 유지합니다.

## 정적 리소스 캐시

서버 시작 시 Go 표준 라이브러리로 강한 ETag와 gzip 표현을 준비합니다. `/assets/`의 해시 포함 파일은 `public, max-age=31536000, immutable`, HTML 등 해시 없는 파일은 `no-cache`와 조건부 검증을 사용합니다. gzip 선택은 제외 및 우선순위를 따르며 `Vary: Accept-Encoding`과 압축 전후 서로 다른 ETag를 반환합니다. 조건부 GET/HEAD가 일치하면 304를 반환하고 바이트 범위 및 기존 보안 헤더를 유지합니다. 외부 압축 서비스는 필요하지 않습니다.

## 빌드 버전과 CI

서버, Agent 보고와 발신 User-Agent는 `internal/buildinfo.Version`을 공유합니다. 직접 `go build`하면 `0.4.0-dev`를 사용하고, `make build`는 `git describe --tags --always --dirty`를 주입하며 Git 정보가 없으면 기본값을 사용합니다. `make build VERSION=0.4.0-dev`로 명시할 수 있으며 두 실행 파일은 `-version`을 지원합니다. 프런트엔드 패키지는 개발 기준 버전을 사용하고 시스템 설정에는 실제 서버 빌드를 표시합니다. GitHub CI는 push와 pull request에서 실행되도록 설정했으며 go.mod의 Go, Node 22, 커밋 고정 Action으로 race 테스트, 타입 검사, 빌드와 포맷 검사를 수행합니다. 설정 파일 자체가 원격 실행 성공이나 릴리스 게시를 의미하지는 않습니다.

`make docker-build`는 Git 기반 버전을 주입합니다. Compose를 직접 쓸 때는 `MONITOR_VERSION`을 지정하며 생략하면 `0.4.0-dev`를 표시합니다. 직접 빌드할 때는 `docker build --build-arg VERSION="$(git describe --tags --always --dirty 2>/dev/null || printf 0.4.0-dev)" -t monitor-go:local .`을 사용할 수 있습니다. Git 이력은 Docker 빌드 컨텍스트에 포함하지 않습니다.

## 온라인 백업 및 복원

명령 실행 중에도 서비스를 계속 사용할 수 있습니다. 출력 디렉터리는 없어야 하며 부모 디렉터리는 미리 만들어야 합니다. 원본을 읽기 전용으로 열며 인스턴스 잠금이나 마이그레이션을 실행하지 않습니다(스키마 3부터 현재 버전까지 지원). 일관된 SQLite 스냅샷, 마스터 키, 스냅샷에서 참조하는 모든 객체(휴지통 포함)를 복사합니다. 스냅샷 이후의 새 업로드는 제외합니다. 누락 객체를 재시도하며 누락·손상·변경이 남으면 0이 아닌 종료 코드와 BACKUP_INCOMPLETE를 남깁니다. 이 디렉터리는 복원하면 안 됩니다. 완료 목록에는 UTC 시각, 빌드/스키마 버전, 객체 수 및 SHA-256을 기록합니다. 초기화 토큰, 잠금, 임시 파일과 이미지 캐시는 제외합니다.

```sh
mkdir -p backups
./bin/monitor backup -data data -out backups/snapshot-001
```

복원 전에 서비스를 중지하고 전체 데이터 디렉터리를 완전한 백업으로 교체한 다음 해당 스키마 이상을 지원하는 바이너리로 시작합니다. 검증이 끝날 때까지 이전 디렉터리를 보관합니다. 오프라인 복원만 지원하며 실행 중인 데이터에 파일을 병합하지 않습니다. 백업에는 자격 증명이 포함되므로 비공개로 보관하고 독립 저장소에 복사합니다. 기존 콜드 백업도 계속 지원합니다.

## 기본 리소스 이름

수정하지 않은 기본 폴더(설정 및 패키지 선택 경로 포함), 역할 이름과 설명, 이미지 스타일 이름, 로컬 호스트 별칭은 인터페이스 언어를 따릅니다. 이름을 변경한 값은 원문을 유지합니다. 서버의 명시적 번역 키를 사용하므로 기본 이름과 같은 사용자 지정 이름도 문자열만으로 번역하지 않습니다. 저장된 기록은 변경하지 않습니다.

감사의 고정 작업 레이블은 표시할 때 번역합니다. 작업자 이름, 리소스 텍스트와 저장된 감사 행은 유지합니다.

메뉴 관리의 기본 이름, 대상 페이지, 상위 그룹 및 권한 선택지도 인터페이스 언어에 맞춰 표시합니다. 이름을 편집하지 않고 표시 여부나 순서만 바꾸면 기본 이름의 번역 동작을 유지합니다. 명시적으로 편집한 이름은 사용자 텍스트로 저장하고 언어를 전환해도 초안을 덮어쓰지 않습니다.

## HTTP 응답 규칙

HTTP 점검 생성 및 편집에서 선택적 UTF-8 키워드(최대 1024바이트), 반대 일치와 응답 시간 경고(0–30000ms, 0은 비활성화)를 설정할 수 있습니다. 대소문자를 구분하고 디코딩된 본문의 처음 1 MiB만 검사하며 잘림 여부를 상세 정보에 표시합니다. 빈 키워드는 기존 상태 코드 검사만 유지합니다. 응답 시간에는 검사한 본문을 읽는 시간이 포함됩니다. 연결·상태 코드 실패, 키워드 실패, 시간 경고 순으로 우선하며 본문을 상세 정보에 노출하지 않습니다. HTTP가 아닌 점검은 규칙을 지웁니다. 사용자 지정 헤더와 GET/HEAD 선택은 선택적 후속 기능입니다. 스키마 7에서 필드를 추가하므로 업그레이드 전 서비스를 중지하고 전체 백업을 만드세요. 이전 바이너리는 새 스키마를 읽을 수 없습니다.

HTTP 응답 시간 경고는 응답 시간 제목을 사용하며 SSL 경고는 인증서 전용 제목을 유지합니다.

## Agent 재시도 및 수집 검증

네트워크 또는 서버 장애는 연속 실패 횟수 × 5초, 최대 60초 지연을 사용하며 성공하면 정상 15초 간격으로 돌아갑니다. HTTP 401/403 및 등록 중 409는 자격 증명 무효 또는 등록 충돌로 Agent를 중지합니다. 폐기된 자격 증명을 반복 재시도하지 않고 새 설정으로 다시 등록하세요. 로컬 HTTP/TLS 서버와 주입 가능한 수집기/시계를 사용해 자격 증명 저장, 보고, 재시도 상한 및 초기화, 리디렉션 거부, 사설 CA, 최대 16개 사용 가능한 고유 마운트 필터링, 일부 지표 오류, 네트워크 카운터 및 시간 초기화를 테스트합니다.

## 장기 가용률 및 보관 정책

스키마 8은 시간별 총/성공 횟수와 평균/최대 응답 시간, 트랜잭션 내 처리 완료 표시 및 미집계 행 부분 인덱스를 추가합니다. 시작 시 및 매시간 종료된 시간대를 집계한 뒤 원본을 삭제합니다. 반복 실행과 늦은 결과를 중복 계산하지 않으며 실패 시 원본을 보존합니다. 호스트/점검 원본 기본 7일(1–30일), 점검 요약 기본 90일(90–730일)입니다. UTC 정시에 맞춘 배치 정리로 실제 보관은 최대 약 한 시간과 대기 시간만큼 늘 수 있습니다. 호스트 요약 테이블은 없습니다. 업그레이드 전 서비스를 중지하고 전체 백업을 만들며 스키마 8을 읽지 못하는 이전 바이너리로 바로 되돌리지 마세요.

개요와 서비스 점검에서 30/90일 가용률을 선택합니다. GET /api/v1/monitors/availability?hours=720 또는 2160은 monitor:read 권한이 필요하며 개요도 같은 범위를 지원합니다. 하나의 SQLite 스냅샷에서 요약과 미집계 원본을 합쳐 실제 점검 수로 가중합니다. healthy와 warning은 기존 24시간 정의처럼 가용으로 계산합니다. 시작 시각을 UTC 정시에 맞추고 현재 진행 중인 시간도 포함합니다. 누락을 성공으로 간주하지 않고 데이터가 없으면 null/“—”를 표시합니다. 이미 삭제된 기록은 복구할 수 없습니다.

용량 추정: 원본 점검 행 ≈ 대상 수 × (86400 / 간격 초) × 원본 보관 일수, 요약 행 ≤ 대상 수 × 24 × 요약 보관 일수, 호스트 행 ≈ 호스트 수 × 5760 × 원본 보관 일수입니다. 대표 데이터를 담은 일회용 DB에서 인덱스를 포함한 행당 비용을 측정하고 (page_count − freelist_count) × page_size로 사용 페이지 증가를 비교하세요. WAL, 업로드 및 백업 공간은 별도로 추가합니다. 삭제는 페이지를 재사용 가능하게 하며 파일 축소를 보장하지 않습니다. 계산은 추정이며 용량 보장이 아닙니다.

## SQLite 동시 읽기

점검 목록, 장기 가용률, 개요, 알림 및 호스트 지표 조회는 기존 단일 쓰기 연결과 최대 2개의 읽기 전용 연결(`mode=ro`, `query_only=1`)을 사용합니다. 권한 확인, 스케줄러, 변경, 마이그레이션 및 seed는 쓰기 경로를 유지하며 온라인 백업은 별도 스냅샷 연결을 사용합니다. 트랜잭션 콜백은 자신의 트랜잭션으로 읽어야 합니다. WAL, FULL 동기화 및 단일 인스턴스 잠금은 유지되며 스키마 변경이나 의존성 추가는 없습니다.

Apple M1 / Go 1.26.9 / 실제 WAL 파일에서 500개 대상 × 1,440개 결과, 동시 폴러 4개(각 5회 읽기)와 간격을 둔 쓰기 80회를 3번 측정했습니다. 쓰기 P95 중앙값은 공유 연결의 866.6 ms에서 읽기 연결 2개의 0.478 ms로, 전체 시간 중앙값은 10.45초에서 5.713초로 줄었습니다. 합성 로컬 측정이며 운영 용량을 보장하지 않습니다. 재현 명령은 `go test ./internal/app -run '^$' -bench BenchmarkConcurrentPollingWrites -benchtime=1x -count=3`입니다. 공유 연결, 읽기 연결 2개와 4개를 비교하고 데이터 생성 시간은 제외합니다.

## 폼과 오류 메시지 언어

설치, 로그인, 대화상자, 브라우저 입력 검증과 알림은 선택한 화면 언어를 따릅니다. 언어를 바꾸면 다시 제출하지 않아도 기존 오류가 갱신됩니다. 편집창에서 수정하지 않은 기본 이름도 바뀌지만 직접 입력한 이름과 저장하지 않은 내용은 유지됩니다. 새 점검의 빈 그룹은 번역된 기본 이름으로 표시하며, 기존 그룹 이름과 기록은 원문을 유지합니다.

## 대화상자 안에서 언어 전환

공통 대화상자에서 언어를 선택할 수 있어 편집창을 닫을 필요가 없습니다. 입력한 이름, 메모, 비밀번호, 체크박스와 드롭다운 선택은 그대로 유지됩니다. 삭제 확인 문구는 입력 당시의 언어로 인식하며 서버에는 고정된 `DELETE` 값을 보냅니다. API나 업로드 응답 형식이 잘못되어도 번역된 오류를 표시하고, 존재하지 않는 API의 오류에도 번역 키를 제공합니다.

## 휴대전화 레이아웃과 대화상자

좁은 화면에서는 기간 버튼이 줄바꿈되며 긴 애플리케이션 이름, 호스트 이름, 알림 리소스 이름은 패널 안에서 줄바꿈됩니다. 대화상자 본문은 별도로 스크롤되고 닫기와 하단 작업 버튼은 계속 사용할 수 있습니다. 긴 설명은 본문에서, 긴 제목은 높이가 제한된 영역에서 스크롤됩니다. 파일·이미지 미리 보기와 패키지 디렉터리 선택도 화면 너비에 맞습니다.

## 호스트 운영체제 이름

로컬 수집기와 업데이트된 Agent는 실제 제품 버전을 사용하여 Apple 컴퓨터를 `macOS <제품 버전>`으로 보고합니다. Darwin 커널 버전은 시스템 정보의 커널 버전 항목에 별도로 유지됩니다. Go 빌드·실행 환경의 `darwin/arm64`는 기술적인 플랫폼 식별자로 유지됩니다. 기존 원격 호스트는 Agent를 업데이트한 뒤 다음 보고에서 이름이 바뀌며 기록은 다시 쓰지 않습니다. Docker는 Linux 컨테이너 환경을 보고합니다.

## macOS APFS 용량과 디스크 알림

APFS 볼륨은 컨테이너의 여유 공간을 공유합니다. 수집기는 시스템 `diskutil`로 마운트된 볼륨의 소속과 용량을 읽고, 확인된 APFS 컨테이너 UUID마다 한 항목을 보고합니다. 대표 경로와 해당 마운트 지점을 유지합니다. 개수는 용량 항목 수이며 물리 디스크 수가 아닙니다. 명시적인 볼륨 할당량은 별도 항목으로 유지합니다. 사용량 수치가 같아도 독립 컨테이너는 합치지 않으며 Linux/Windows와 용량 식별자가 없는 기존 보고도 수치만으로 합치지 않습니다.

디스크 알림은 설정된 공통 임계값을 사용하며 0이면 비활성화됩니다. 호스트 상세와 개요의 안내 및 경고 색상도 실제 값을 따릅니다. 항목을 합쳐도 기존 호스트 디스크 알림 식별자, 담당자와 알림 억제 설정은 유지합니다. 누락되거나 불완전한 수집에서도 확인된 초과는 알릴 수 있지만 복구 근거로 사용하지 않습니다. 완전한 낮은 값의 수집이나 임계값 비활성화 후 복구할 수 있습니다. APFS 소속 조회가 실패하면 기존 마운트 값을 보존하고 불완전으로 표시하며 읽지 못한 항목을 정상으로 판단하지 않습니다.

서버를 먼저 업데이트한 뒤 새 Agent를 배포하세요. 현재 정보는 다음 보고에서 바뀌고 과거 알림과 샘플은 다시 쓰지 않습니다. 데이터베이스 마이그레이션이나 새 의존성은 없습니다. 컨테이너 사용률에는 공유 할당이 포함되므로 개별 볼륨의 `df` 비율과 다를 수 있습니다. [Apple의 APFS 공간 공유 설명](https://support.apple.com/en-au/guide/disk-utility/dskua9e6a110/mac)을 참고하세요.
