# 번역 유지 관리

[English](../en-US/INTERNATIONALIZATION.md) · [简体中文](../zh-CN/INTERNATIONALIZATION.md) · [日本語](../ja-JP/INTERNATIONALIZATION.md) · **한국어** · [繁體中文](../zh-TW/INTERNATIONALIZATION.md) · [Documentation](../README.md)

Go와 React가 `locales/*.json`을 공유합니다. 지원 언어는 `zh-CN`, `en-US`, `ja-JP`, `ko-KR`, `zh-TW`입니다. Go는 파일을 내장하고 React는 영어 이외의 언어를 필요할 때 불러옵니다. 원문을 gettext 방식의 키로 사용하며 프런트엔드에서 키 타입을 검사합니다.

- 고정 문구는 `t()`를 사용하고 변수가 있는 문장은 `{p0}`, `{p1}`로 묶으세요. 번역된 문장 조각을 이어 붙이거나 HTML로 출력하지 않습니다.
- 레이블 표는 `localizedLabels()`를 사용합니다. `metadataLabel()`은 고정 권한 및 범위 정보 전용입니다. 사용자 이름이나 저장된 기록을 일괄 치환하지 마세요.
- `web/src/i18n/`은 언어 선택과 반응성, `lib/types.ts`는 모델 타입, `format.ts`는 날짜와 숫자 형식을 담당합니다. `stores/app.ts`는 업무 상태를 관리합니다.
- 처음에는 브라우저 언어와 관계없이 영어를 사용합니다. 저장된 유효한 선택은 복원하며, 선택이 없거나 유효하지 않거나 저장소를 사용할 수 없으면 영어를 사용합니다. 언어 선택은 브라우저에 저장됩니다. 폼을 다시 만들거나 입력을 초기화하지 않습니다. 시간대는 브라우저 로컬 설정을 사용합니다.
- JSON 및 업로드 요청은 `Accept-Language`를 보냅니다. API는 가중치를 고려하고 `Content-Language`와 `Vary`를 반환합니다. 헤더가 없으면 기존 간체 중국어, 지원하지 않으면 영어입니다. 상태 코드와 JSON 필드 이름은 바뀌지 않습니다.
- 기간은 `1h`/`24h`/`7d`, 영구 삭제는 `DELETE`라는 고정 값을 사용합니다. 화면 번역을 업무 조건으로 사용하지 않습니다. 서버는 기존 중국어 삭제 확인 값도 허용합니다.
- Go의 숫자 포함 오류는 `badf()`로 언어 선택 후 형식화합니다. 모든 언어에서 자리표시자를 일치시키세요.
- 이름을 바꾸지 않은 기본 메뉴만 `nameKey`로 번역합니다. 사용자 지정 이름, 기록, 진단, 알림 본문, 로그, CLI 도움말은 원문을 유지합니다.

새 언어는 전체 JSON 번역을 만들고 Go `Supported`/`Match`, 프런트엔드 언어 정의/매칭/로더, 검사 스크립트, 테스트, 문서 링크를 갱신하세요. 현재 언어는 모두 왼쪽에서 오른쪽 방향입니다. RTL 언어는 방향과 레이아웃 지원도 필요합니다.

```sh
npm --prefix web run check:i18n
npm --prefix web run check:docs
npm --prefix web run test:docs
npm --prefix web test
npm --prefix web run typecheck
npm --prefix web run build
npm --prefix web run format:check
go test -race ./...
go vet ./...
```

`prettier 3.6.2`는 개발용 포맷터입니다. 잠금 파일을 유지하세요. 격리된 실제 SQLite 파일로 로그인 전 전환, 선택 유지, 폼 입력 유지, API 오류, 파일 업로드 및 좁은 화면을 검증하세요.

현재 사용 안내는 다섯 언어로 제공합니다. 기존 중국어 설계 문서 전체가 번역된 것은 아니며 향후 계획도 포함합니다. 실행 명령, 필수 버전, 제품 제한을 바꾸면 모든 현행 언어 안내를 함께 갱신하세요. 전체 키 번역은 준비되어 있으며 원어민의 표현 검토도 도움이 됩니다.

## 2026-10-14 국제화 검증 (GitHub 문서 정비 이전)

언어별 메시지 1152개와 치환 변수, Markdown 파일 22개의 로컬 링크 92개를 검증했습니다. 빌드에는 `check-docs.mjs`도 포함됩니다. 타입 검사, 프로덕션 빌드, 프런트엔드 테스트, Prettier, Go 형식 검사, 일반 테스트, 경쟁 조건 검사, vet, 서버와 Agent 빌드가 모두 통과했습니다.

`127.0.0.1:5093`의 독립된 SQLite 환경에서 인증, 매개변수 검증, 빈 파일 업로드, 존재하지 않는 API를 5개 언어로 총 20회 확인했습니다. 브라우저에서는 12개 페이지 × 5개 언어 × 데스크톱 및 너비 390px로 총 120개 페이지를 확인했으며 페이지 전체의 가로 넘침이 없었습니다. 언어 선택 유지, 저장 전 폼 입력 유지, 일본어 오류, 다국어 QR 생성, 좁은 화면의 파일 대화상자도 확인했습니다. 운영 데이터는 사용하지 않았습니다. 원어민의 표현 교정은 별도로 진행할 수 있습니다.

## 폼과 오류 메시지 언어

설치, 로그인, 대화상자, 브라우저 입력 검증과 알림은 선택한 화면 언어를 따릅니다. 언어를 바꾸면 다시 제출하지 않아도 기존 오류가 갱신됩니다. 편집창에서 수정하지 않은 기본 이름도 바뀌지만 직접 입력한 이름과 저장하지 않은 내용은 유지됩니다. 새 점검의 빈 그룹은 번역된 기본 이름으로 표시하며, 기존 그룹 이름과 기록은 원문을 유지합니다.

기본 폼 검증에는 `Form`, 저장되는 임시 알림에는 `notice()` / `errorMessage()`를 사용합니다. API 오류는 `message`를 유지하고 화면 갱신용 `key` / `args`를 추가합니다. 사용자 텍스트에서 키를 추측하지 마세요. 다운로드와 이미지 URL은 `apiLink()`로 `lang`을 전달하며 유효한 GET/HEAD 언어 매개변수는 브라우저 헤더보다 우선합니다. 개요와 가용성 API의 `ungrouped=1`은 빈 기본 그룹을 선택하고 생략하거나 빈 `group`은 모든 그룹을 선택합니다. 검사기는 영어 번역의 한자와 공통 컴포넌트 외부의 기본 form을 거부하며 Go 테스트는 API 오류 번역을 확인합니다.

## 대화상자 안에서 언어 전환

공통 대화상자에서 언어를 선택할 수 있어 편집창을 닫을 필요가 없습니다. 입력한 이름, 메모, 비밀번호, 체크박스와 드롭다운 선택은 그대로 유지됩니다. 삭제 확인 문구는 입력 당시의 언어로 인식하며 서버에는 고정된 `DELETE` 값을 보냅니다. API나 업로드 응답 형식이 잘못되어도 번역된 오류를 표시하고, 존재하지 않는 API의 오류에도 번역 키를 제공합니다.

카탈로그 검사는 다른 언어 문자의 혼입과 번역하지 않은 영어 복사를 탐지합니다. 공통 제품명과 프로토콜명은 명시적으로 예외 처리하며 번체 중국어 용어도 통일합니다. 일본어 한자와 언어 선택지의 자국어 표기는 정상입니다. 검사는 시스템 문구에만 적용하며 사용자 데이터와 저장된 진단을 변환하지 않습니다. 상호작용 테스트는 대화상자의 언어 선택기를 사용하여 추가 요청 없이 입력이 유지되는지 확인합니다.

## 휴대전화 레이아웃과 대화상자

좁은 화면에서는 기간 버튼이 줄바꿈되며 긴 애플리케이션 이름, 호스트 이름, 알림 리소스 이름은 패널 안에서 줄바꿈됩니다. 대화상자 본문은 별도로 스크롤되고 닫기와 하단 작업 버튼은 계속 사용할 수 있습니다. 긴 설명은 본문에서, 긴 제목은 높이가 제한된 영역에서 스크롤됩니다. 파일·이미지 미리 보기와 패키지 디렉터리 선택도 화면 너비에 맞습니다.

대화상자는 키보드가 열릴 때 브라우저의 보이는 영역 높이와 이동을 따라가며 입력 중인 필드를 보이도록 스크롤합니다. 작성 중인 내용은 유지됩니다. 모바일 입력 글꼴은 읽기 쉽게 표시하고 하단 버튼의 터치 영역을 넓히며 긴 라벨은 줄바꿈합니다. 5개 언어를 너비 320px·390px 세로 화면, 640px 가로 화면과 높이가 줄어든 화면에서 확인하고 내부 가로 너비와 실제 버튼 클릭 영역을 함께 검증하세요.

## 휴대전화 사용 흐름 검증 (2026-10-15)

화면 캡처뿐 아니라 전체 작업을 독립된 임시 설치와 테스트 파일로 확인합니다. 320×568, 390×844 브라우저 뷰포트에서 다섯 언어를 사용합니다.

1. 첫 방문의 영어 기본값, 필수 입력 오류, 언어 전환 시 설치 입력 유지를 확인합니다. 실제 HTTP로 초기화하고 SQLite의 관리자 기록과 `setup-token` 삭제를 확인합니다.
2. 각 언어로 로그인하고 로그아웃합니다. 로그인 페이지를 새로 고쳐 저장된 언어를 확인하고, 이미 표시된 로그인 오류의 언어가 바뀌어도 입력한 인증 정보는 유지되는지 확인합니다.
3. 애플리케이션과 폴더를 만들고 설정, HTTP 점검 생성·편집을 저장합니다. 저장 전에 언어를 바꾸면서 텍스트·숫자·디렉터리 선택을 확인합니다. 다시 열거나 새로 고친 뒤 HTTP와 SQLite로 저장된 값을 대조하고 로컬 테스트 대상을 실제로 점검합니다.
4. 각 언어에서 파일 선택·업로드·미리 보기·다운로드를 진행하고 원본과 SHA-256을 비교합니다. 여러 언어의 파일명과 내용은 유지합니다. 빈 파일과 정상 파일의 일괄 업로드, 중복 이름 오류의 다섯 언어 표시, 파일 수정 후 재시도, 테스트 서비스 중단 후 복구를 확인합니다. 이름 변경·이동 후에도 다운로드 이름과 내용을 다시 확인합니다.

이번 검증은 빌드 `2a5674c`, 독립 포트 `62538`에서 진행했습니다. 애플리케이션 5개, 새 폴더 1개, 설정, 정상 HTTP 점검 1개와 저장 파일 8개를 확인했습니다. 다섯 언어의 다운로드가 원본과 일치했고 SQLite 무결성과 외래 키 검사도 통과했습니다. 새로운 제품 결함은 재현되지 않아 이번 후속 작업은 문서만 갱신합니다.

초기화 제출은 HTTP로, 설치 입력 검증과 언어 전환은 브라우저로 확인했습니다. 데스크톱 브라우저 뷰포트와 파일 선택 흐름 검증이며 실제 휴대전화, 모바일 기본 선택 창이나 기기 키보드 검증을 뜻하지 않습니다. 서비스 중단 테스트에 운영 데이터를 사용하지 마세요.
