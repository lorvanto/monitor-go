# 初回アクティベーションと匿名インストール統計

[English](../en-US/USAGE_REPORTING.md) · [简体中文](../zh-CN/USAGE_REPORTING.md) · [日本語](../ja-JP/USAGE_REPORTING.md) · [한국어](../ko-KR/USAGE_REPORTING.md) · [繁體中文](../zh-TW/USAGE_REPORTING.md)

Monitor Go と Monitor Console は独立したリポジトリ、サービス、データベースです。ソースとデータを分けて保存します。Monitor Go の導入に非公開 Console のソースは不要です。初回設定では構成済み Console へオンライン登録し、その後のローカルログイン、監視、アラートは独立して動作します。

標準の新規インストールでは最初のローカル管理者を作る前にオンラインで有効化します。画面に正確な送信先、目的、項目、継続送信と無効化スイッチがない規則を表示し、説明文バージョン `2` への明示的な確認を求めます。登録失敗時は管理者を作らず、同じランダム ID で再試行します。製品利用者の Console アカウントは不要です。

個別/アクティブなインストール数と製品バージョン/OS の分布を集計します。v2 登録は `instanceId`、`credential`、`version`、`os`、送信は `instanceId`、`version`、`os`、`activeDays` です。ランダム ID で重複を排除し、専用認証情報で認証して UTC 日付別の活動を集計します。バージョンと OS の種類は技術分布で、製品利用者のアカウントとは結び付けません。アーキテクチャ、導入方法、メンバー一覧、ホスト名/IP、監視内容、ファイル、パスワード、監視用/アプリケーションキーは送りません。匿名統計の User-Agent は固定値でビルドバージョンを付けません。

製品利用者のアカウント連携、連携コード、利用者一覧、マイインストール機能は廃止しました。Console が保持するアカウントは統計サービスを管理する管理者自身の認証用だけで、製品の利用人数ではありません。Monitor Go 内の管理者、メンバー、権限機能は独立して維持します。

ランダムなインストール ID を数え、個人の人数は示しません。複数人が同じインストールを使っても 1 件です。データディレクトリの複製で集計が合算され、空ディレクトリの作成で別の ID ができる場合があります。リモート登録後にローカル設定が失敗・中止された登録も残るため、登録数は完了した導入数とも一致しません。

有効化後に独立処理で送信し、以降は約 6 時間ごとに間隔を分散します。5 秒でタイムアウトし、リダイレクトを拒否して上限付きで再試行します。未送信の UTC 活動日は最大 7 日で、自動更新とページ読み込みだけでは活動に数えません。Console は日別記録を 90 日、報告のないインストールを 365 日で削除し、その後は再登録できます。

送信先が同じ更新では ID、認証情報、有効状態、過去の同意、活動日を保持します。項目を減らしても新たな同意を捏造せず、説明文はバージョン `2` のままです。旧版で無効だったものは管理者の確認と登録成功後に有効にします。確認待ちや Console 障害はローカルログイン、監視、アラートを妨げません。送信先を変更する場合は新しい宛先への確認前に送信しません。継続送信に無効化スイッチはなく、停止要求は HTTP 403 です。

Monitor Console をスキーマ `3` に更新してから Monitor Go をスキーマ `12` に更新します。新クライアントは `/api/v2/instances/register` と `/api/v2/instances/report` を使います。Console の v1 登録/送信は旧クライアントと互換性があり、バージョンと OS は保持し、アーキテクチャと導入方式は保存・返却せず破棄します。連携 API は廃止します。Monitor Go v11 は `usage_settings.account_login` の旧スナップショットを物理的に削除し、Console v3 はアーキテクチャ、導入方式、アカウント関連付け、連携コードを削除します。バージョン/OS 分布と匿名集計は保持します。

更新前に正常停止し、両サービスのデータディレクトリを別々に完全バックアップします。戻す場合は各旧イメージ/バイナリと完全バックアップを復元し、データベースを共有しません。旧バックアップには廃止した情報が残る場合があるため非公開で管理します。同じ宛先で確認済みのインストールを、データ消去して再有効化する必要はありません。

`MONITOR_CONSOLE_URL` がなければ内蔵の既定 HTTPS オリジンを使い、実際の送信先を設定・確認画面に表示します。明示した環境変数は既定値より、`-console-url` は環境変数より優先します。元のバックエンドを保持する場合は更新前にその HTTPS オリジンを明示します。空や空白だけの宛先は無効です。旧 `-require-activation=false` / `MONITOR_REQUIRE_ACTIVATION=false` は拒否し、`true` の互換性は保持します。バージョン表示とバックアップは有効化設定に依存しません。

HTTPS が必須で、数値ループバックの HTTP は隔離テスト専用です。認証情報、データ、バックアップを Git へ登録せず、統計のプロキシログにも完全な送信元 IP や認証情報を保存しません。`MONITOR_DEPLOYMENT` / `-deployment` はローカル実行方式を示す互換設定で、匿名項目には送りません。

```sh
./bin/monitor -data data -listen 127.0.0.1:5080
```
