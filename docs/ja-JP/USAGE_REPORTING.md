# 初回アクティベーションと利用状況の送信

[English](../en-US/USAGE_REPORTING.md) · [简体中文](../zh-CN/USAGE_REPORTING.md) · [日本語](../ja-JP/USAGE_REPORTING.md) · [한국어](../ko-KR/USAGE_REPORTING.md) · [繁體中文](../zh-TW/USAGE_REPORTING.md)

Monitor Go と Monitor Console は独立したリポジトリ、サービス、データベースです。ソースとデータは別のディレクトリに置いてください。Monitor Go の導入に必要なのは公開リポジトリのみで、非公開 Console のソースは不要です。標準の初期設定では設定先の Console でアクティベーションを行います。その後のログイン、監視、アラートは独立して動作します。

標準の新規インストールでは、最初のローカル管理者を作成する前にオンラインでアクティベーションを行います。設定画面に送信先（既定値 `https://feiniu.i7f.cn:5090`）、統計の目的、送信項目、送信が継続し無効化スイッチがないことを表示し、説明文バージョン `2` への明示的な確認を求めます。登録成功後に管理者を作成し、継続的なバックグラウンド送信を開始します。ローカルのユーザー名、表示名、パスワードは Console に送りません。登録失敗時は管理者を作成せず、接続回復後に同じインストール ID で再試行します。Console アカウントや GitHub ログインは不要で、開発者アカウントへの自動連携も行いません。

送信が有効な既存インストールは更新時に ID、認証情報、アカウント連携、過去の同意を保持し、新しい確認を捏造しません。旧版で送信を無効にしていたインストールを自動的に有効にはしません。`system:settings` 権限の管理者が現在の送信先、項目、無効化できないルールを一度確認し、登録が成功してから送信を有効にします。登録やローカルトランザクションが失敗すると無効のままです。確認待ちでもローカルのログイン、監視、アラートは動作します。送信先の変更時は以前のローカル送信 ID を消去し、新しい送信先への確認前には送信しません。

送信項目はランダムなインストール ID、バージョン、OS、CPU アーキテクチャ、配備方法、ログインした人が画面を操作した UTC 日付です。ローカルアカウント一覧、監視対象、ホスト名/IP、ファイル、アラート本文、パスワード、監視用キー、アプリケーションキーは含みません。インストール認証情報は登録と認証にのみ使用し、画面には表示しません。Console のアカウントは Monitor Go と独立しています。ローカルアカウントはユーザー名と表示名を保持し、任意の GitHub ログインでは検証済み GitHub ID、ユーザー名、表示名を別途保持します。

インストールの登録と活動統計にアカウント連携は不要です。Console はローカル管理者のユーザー名とパスワードでログインでき、GitHub ログインは任意です。Monitor Go の導入に OAuth 設定は不要です。

任意でアカウントを関連付けるには、ローカル Console アカウントまたは有効な GitHub ログインで Monitor Console にログインし、有効期限 10 分の使い捨て連携コードを生成して Monitor Go の送信設定に貼り付けます。先に送信を有効にしてください。連携解除はアカウントとの関連付けのみを解除し、送信は停止しません。コンソールから自分のインストールの連携も解除できます。

「前回同期した Console アカウント」はローカルに保存された情報です。Console 側の連携解除は次回の送信成功後に表示へ反映されます。接続障害や旧インストールの確認待ちでは以前のアカウントが残る場合があります。「送信状態を更新」はローカル設定を読み直すだけで、リモート同期は行いません。

有効化後に独立した処理が一度送信し、その後は約 6 時間ごとに間隔を分散して送信します。タイムアウトは 5 秒で、リダイレクトを許可せず、制限付きのバックオフで再試行します。未送信の活動日は最大 7 日です。自動更新やページ読み込みだけでは利用とみなしません。日別集計はインストール単位で重複を排除し、人数は示しません。自己申告の推定値であり、身元や全インストール数の証明ではありません。

リモート登録の成功後にローカル初期設定が失敗または中止されると、未連携のランダムな登録が Console に残る場合があります。再試行では同じ ID を使用します。そのため登録数は完了したインストール数や実際の人数とは一致しません。

アクティベーションまたは確認後は送信が継続し、画面、API、配備引数から無効にできません。無効化の要求は HTTP 403 を返します。Console 障害時は独立したバックグラウンド処理で間隔を延ばして再試行し、ログイン、監視、アラートを妨げません。日別記録は 90 日、報告のないインストールは 365 日で削除します。後の送信で再登録できますが、アカウントの再連携が必要です。連携解除は送信を停止せず、受信済み履歴も削除しません。

HTTPS が必要です。数値ループバックの HTTP はローカル統合テスト専用です。コンテナー内のループバックは自身を指すため、別コンテナーには実際の HTTPS URL を使用します。認証情報、データやバックアップを Git に保存しないでください。プロキシログには OAuth のクエリ、完全な送信元 IP や認証情報を残さないでください。

データベースはスキーマ 10 のままです。説明文バージョン `2` は既存の説明文バージョン、同意日時、アクティベーション日時の列を使い、継続送信ルールの確認を記録します。過去の同意は書き換えません。更新前にデータディレクトリ全体をバックアップし、ロールバック時はその完全バックアップを戻してください。ID はデータと共に保持され、複製すると統計が合算される場合があります。未確認の旧インストールや到達不能なクライアントを含む完全な導入数は集計できません。

`MONITOR_CONSOLE_URL` が未設定の場合、ネイティブ版と Compose は `https://feiniu.i7f.cn:5090` を使用します。別の HTTPS オリジンで送信先を変更でき、ネイティブ版の `-console-url` 引数が優先されます。空または空白文字だけの送信先は、環境変数で指定した場合も設定エラーとして標準 CLI が拒否します。送信を無効にしたりアクティベーションを回避したりはできません。バージョン表示とバックアップのコマンドにはアクティベーション設定は不要です。

標準 CLI と Compose はアクティベーションと送信を必須とします。旧設定の `-require-activation=false` と `MONITOR_REQUIRE_ACTIVATION=false` は設定エラーとして拒否し、サポートしません。`true` は互換性のため受け付けます。オフライン導入や送信の無効化を行う引数はありません。到達可能な HTTPS Console URL を設定してください。空または空白文字だけの送信先は起動時の設定エラーとなり、アクティベーションを回避できません。Console URL の引数は対応する環境変数より優先されます。activation=false の設定は true の引数を追加しても有効にはなりません。

```sh
./bin/monitor -data data -listen 127.0.0.1:5080
```

`MONITOR_CONSOLE_URL` / `-console-url`; `MONITOR_REQUIRE_ACTIVATION` / `-require-activation`; `MONITOR_DEPLOYMENT=native|docker` / `-deployment`.

ネイティブ版の既定値は `native` です。Docker イメージと Compose は自動的に `docker` を設定します。
