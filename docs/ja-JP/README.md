# Monitor Go — 利用ガイド

[English](../en-US/README.md) · [简体中文](../zh-CN/README.md) · **日本語** · [한국어](../ko-KR/README.md) · [繁體中文](../zh-TW/README.md) · [Documentation](../README.md)

> 状態：公開前の開発基準は `0.4.0`、SQLiteスキーマは `6` です。公開済みリリースを意味しません。コマンド例はPOSIXシェル用です。WindowsではWSLを利用できます。

スキーマ5では待機中のジョブ用の部分インデックスを追加し、完了済みジョブ履歴の全走査を避けます。ジョブの保存期間は7日のままです。更新前に停止してデータディレクトリ全体をバックアップしてください。旧バイナリはスキーマ6を読めず、ロールバックには完全バックアップが必要です。

機能の画面例は[英語UIのスクリーンショット](../../README.md#screenshots)をご覧ください。データはデモ用の架空データです。初回アクセス時の表示言語は英語です。

## 対象と実装済み機能

Go、React 19、内蔵SQLiteを使うセルフホスト型の監視・運用システムです。1つのインストールをチームで共有します。マルチテナント方式ではなく、作成者は監査情報として扱います。MySQLとRedisは監視対象であり、保存先や必須サービスではありません。

監視概要、ローカル／リモートホスト指標、HTTP・TCP・SSL・MySQL・Redisチェック、アラート対応、ロールとメンバー、SMTP／Webhook通知、メニュー、非公開ファイル、画像スタイル、監査、設定、アプリキー、パッケージ配布、QRコードとバーコードを実装済みです。ライト／ダークテーマとキーボードによるページ検索も利用できます。メニューの表示とAPIの権限検証は独立しています。

## フロントエンド構成

React / React DOM 19.3.0、TypeScript 5.9.3、Vite 8.3.4、Zustand 5.0.15を使用します。静的ファイルをGoサーバーに埋め込むため、本番環境にNode.jsサーバーは不要です。`web/src/views/`の画面は`React.lazy`で読み込み、共通TSXコンポーネントは`components/`、認証・権限・ナビゲーションの状態は`stores/app.ts`、型・グラフ・書式の処理は`lib/`に置きます。5言語のカタログは`locales/`で共有します。

`npm --prefix web test`は言語テストとVitest / React Testing Libraryの操作テストを実行します。`npm --prefix web run typecheck`はアプリとテストの型を検査します。既存のAPI、CSRF、アップロード、SQLiteの仕様を維持し、今回の移行によるDB変更はありません。反映にはGoバイナリの再ビルドと再起動が必要です。

以前のログインセッションや選択に対する遅延レスポンスは無視されます。ホストのメモ編集とアラートの通知抑制は、ダイアログを開いた時点の対象とバージョンを保持します。ファイルの最終ページが空になるとページ番号を調整し、監査ログの読み込み中も検索条件を解除できます。設定の保存ができないブラウザーでもテーマを切り替えられます。ページの読み込みに失敗した場合は再読み込みボタンを表示し、未保存の変更が失われることを案内します。

## Dockerでの導入

ホストにGo／Node.jsを入れず、DockerとComposeからビルドして実行できます。

```sh
docker compose up -d --build
docker compose exec monitor cat /data/setup-token
```

5080を開き、初期化コードで管理者を作成します。名前付きボリュームに全データを保持します。コンテナーのホスト採集は既定で無効なので、実ホストではネイティブAgentを使います。ポート変更、HTTPS、バックアップ、復元、更新は[Docker導入ガイド](DOCKER.md)を参照してください。

## ビルドと初回起動

Go 1.26.9以降の互換バージョンとNode.js 22.12+／24.xを使用します。ロックファイルを保持し、このリポジトリで実行してください。

```sh
make build
./bin/monitor -data data -listen 127.0.0.1:5080
```

[ローカルサービス](http://127.0.0.1:5080/)を開き、サーバー上の`data/setup-token`を読み取って初期化コード、ユーザー名、氏名、パスワードを入力します。既定のアカウントやパスワードはありません。初期化後にコードファイルを自動削除します。パスワードは12〜72バイトです。セッションはHttpOnly CookieとCSRF検証を使用し、各APIで権限を確認します。

生成したサーバーバイナリには画面の資源を含みます。実行時にJava、Node.js、外部DBは不要です。同じデータディレクトリを複数の稼働プロセスで共有できません。

チームで利用する場合は、信頼できるHTTPSリバースプロキシを配置します。

```sh
./bin/monitor -data data -listen 127.0.0.1:5080 \
  -public-url https://monitor.example.com -secure-cookie
```

`-public-url`はブラウザーからアクセスするオリジンで、末尾のスラッシュを付けません。`-collect-host=false`でローカル指標収集を停止できます。

## 表示言語

ログイン／初期化画面、またはログイン後のサイドバーで簡体中文・English・日本語・한국어・繁體中文を選択します。初回はブラウザーの言語に関係なく英語で表示します。以後は保存済みの有効な選択を復元し、未保存・無効・保存機能が利用できない場合は英語を使用します。`zh-Hant`、`zh-HK`、`zh-MO`は繁体字に対応します。

固定文言、標準ナビゲーション、権限、APIスコープ、日付・数値・グラフ表示を切り替えます。ページを再読み込みせず、編集中のフォームも保持します。時刻はブラウザーのローカルタイムゾーンを使用します。言語パックは必要時に読み込み、選択はブラウザー内の`monitor.locale`に保存します。

名前、メモ、ファイル本文、保存済みアラート・監査履歴、探測診断、通知本文、サーバー／Agentログは原文を維持します。言語変更で業務データは書き換えません。名前を変更したメニューは入力どおりに表示します。

## 監視とリモートホスト

ホスト指標を約15秒ごとに収集します。サービスチェックは監視サーバーで実行します。連続異常がしきい値に達するとアラートが発生し、次の正常結果で復旧します。確認や通知停止だけでは復旧扱いになりません。

ホスト詳細から有効期間15分の登録コードを発行し、対象OSとアーキテクチャ向けAgentを用意します。

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o bin/agent-linux-amd64 ./cmd/agent
# ARM64にはGOARCH=arm64を指定します。
```

リモートホストにAgentと`enrollment-token`を配置します。

```sh
chmod 600 enrollment-token
./agent -server https://monitor.example.com -enrollment-file enrollment-token -config agent-data/config.json
# 2回目以降:
./agent -config agent-data/config.json
```

信頼された有効なHTTPS証明書を使用します。私設CAは`-ca-file`で指定できます。数値ループバックアドレスのみHTTPテストを許可します。Agentは発信接続するため、受信ポートの開放は不要です。認証情報を他ホストにコピーしないでください。取り消しや再登録で旧認証情報は失効します。切断中の指標はバッファリングしません。90秒を超えて報告がないと、次の巡回（最大さらに10秒）でオフライン障害を作成します。

[systemdテンプレート](../../deploy/monitor-go-agent.service)を使う場合、管理者がユーザーとデータディレクトリを事前作成します。サービスは自動インストールされません。Agentはホスト資源の収集のみ行い、リモートコマンドやサービスチェックは実行しません。

## 通知・ファイル・配布

アラートセンターでSMTP、汎用Webhook、または下記のチャットボット形式を設定します。SMTPはTLS／STARTTLS、WebhookはHTTPSが必須です（数値ループバックのみHTTPテスト可）。配信ジョブは永続化され、最大4回試行します。少なくとも1回の配信方式なので、Webhook受信側は`X-MonitorGo-Delivery-ID`で重複を排除してください。SMTP受付は受信トレイへの到着を保証しません。通知停止中の未送信通知は後送しません。

署名は`X-MonitorGo-Signature: sha256=<HMAC-SHA256の16進値>`です。時刻ヘッダー、ピリオド、元のリクエスト本文を連結して署名します。受信側で署名と時刻の許容範囲を検証します。

ファイルはインストール内で共有する非公開資源です。アップロード・表示・ダウンロード・管理を個別に認可します。ゴミ箱も容量に含みます。完全削除は選択中の言語で表示された確認文字列を入力します。原本は`data/uploads/`に保存し、画像スタイルは派生画像のみ生成します。

アプリを作成するとスコープ付きキーとパッケージを管理できます。キー全体は発行／更新時に一度だけ表示し、ハッシュのみ保存します。プログラムは`/api/v1/integrations`に`Authorization: Bearer ...`を付けてアクセスします。管理画面へのログインには使えません。ホスト・チェック・アラートのスコープはインスタンス共有資源を対象とし、パッケージはキー所属アプリに限定します。

公開後は所属アプリ、バージョン、OS、アーキテクチャ、ファイルソースを固定します。ファイル更新には新規バージョンが必要です。外部URLはHTTPSに限り、外部ダウンロードへアプリキーを転送しないでください。QR／バーコードはローカル生成し、入力を保存せずPNG／SVGで出力します。

## 開発と検証

リポジトリ直下で、独立した開発用データディレクトリを使います。

```sh
make build
./bin/monitor -data tmp/development -listen 127.0.0.1:5093
# 別のターミナル:
MONITOR_GO_API_TARGET=http://127.0.0.1:5093 npm --prefix web run dev
```

フロントエンドは5188で動作し、この例では`/api`を5093に転送します。`MONITOR_GO_API_TARGET`省略時の既定値は5080です。初回は`tmp/development/setup-token`で開発用インスタンスを初期化します。Goを変更したら再ビルド・再起動してください。

```sh
make test
npm --prefix web run typecheck
npm --prefix web run check:i18n
npm --prefix web run check:docs
npm --prefix web test
npm --prefix web run format:check
```

`make test`は画面ビルド、言語テスト、Go競合検査、vetを実行します。API統合テストには実際の一時SQLiteファイルを使用します。[翻訳の保守](INTERNATIONALIZATION.md)も参照してください。

## バックアップ・更新・制限

サービスを正常停止し、SQLiteと付随ファイル、`master.key`、`uploads/`の原本を含むデータディレクトリ全体をバックアップします。稼働中の`monitor.db`だけのコピーは完全なバックアップではありません。互換バージョンでディレクトリ全体を復元します。

スキーマ1 → 2 → 3 → 4 → 5 → 6をトランザクションで移行します。旧バイナリはスキーマ6を直接読めず、ロールバックは更新前の完全バックアップが必要です。独自ロールへ新権限を自動付与しません。今回の国際化にDB移行は不要です。

マルチテナント、外部ストレージ、リモート実行、Agent自動更新、オンラインバックアップ画面、公開ファイル共有は未対応です。証明書発行は今後の計画です。500チェック／1000 Agentは設定上限で、負荷検証済みの容量ではありません。Linux実機、実メール事業者、容量は導入環境ごとの確認が必要です。

[中国語資料索引](../zh-CN/INDEX.md)には履歴と設計案が含まれ、すべてが実装済みではありません。ソースは[lorvanto/monitor-go](https://github.com/lorvanto/monitor-go)で管理します。リリースタグと対応対象の確約は今後決定します。プロジェクトのコードと文書は[Apache-2.0](../../LICENSE)、依存関係はそれぞれのライセンスに従います。[GitHub公開と貢献](GITHUB.md)も参照してください。

現行の5言語ガイドは`docs/<locale>/`にまとめ、ディレクトリ名とファイル名は英語を使用します。[文書一覧](../README.md)から参照できます。

## 信頼するプロキシとログイン制限

`-trusted-proxy` はカンマ区切りのプロキシ CIDR を受け取り、既定は空（信頼なし）です。不正な CIDR は起動エラーになります。このプロセスから見える実際のプロキシのみを指定し、プロキシで `X-Forwarded-For` を上書きするか安全に追記してください。サーバーは右から左へ解析し、最初の信頼対象外のアドレスを使います。他の接続元のヘッダーは無視します。ログインの失敗だけを集計し、5 分間にクライアント IP ごとに 30 回、正規化したユーザー名ごとに 10 回までです。成功しても回数を消費・リセットしません。初期設定ではすべての試行を集計します（IP ごとに 5 分間で 10 回）。

## 検査の編集とアーカイブ

検査の編集では名前、種類、接続先、間隔、タイムアウト、閾値、認証情報を変更できます。パスワードの空欄は既存値を維持し、新しい値は置換、削除の選択は認証情報を消去します。HTTP/TCP/SSL への変更でもデータベース認証情報を消去します。バージョンを検証して現在の状態とスケジュールをリセットし、待機ジョブをキャンセルします。履歴と未解決アラートは保持します。アーカイブは確認後に以降の検査を停止します。読み取り専用メンバーには操作を表示しません。409 競合時は入力を保持してサーバーデータを更新します。再保存の前に編集画面を開き直し、最新の設定を確認してください。

デフォルトのインスタンス名は表示言語に合わせて切り替わり、英語では “My monitoring center” です。システム設定でデフォルト名を選ぶとこの動作に戻せます。カスタム名は全言語で入力どおりに表示します。旧環境で未変更の初期名は自動認識し、保存済みの名前は明示的にデフォルトへ戻すまで維持します。

## チャットボット Webhook

形式は汎用、DingTalk、Feishu、WeCom から選択します。既存の設定は汎用のままです。DingTalk は Markdown と URL 内のミリ秒時刻・署名、Feishu はテキストと本文内の秒時刻・署名に対応します。WeCom は Markdown を使い、キーは URL の `key` に含めます。別の署名キーは不要です。形式を切り替えると以前の署名キーを消去します。

汎用形式の JSON と署名ヘッダーは変更しません。ボット形式は HTTP 成功に加え、DingTalk/WeCom の `errcode` または Feishu の `code` が 0 の場合のみ成功です。欠落や不正な応答は失敗とし、15 秒、1 分、5 分後に再試行します。イベント、元のタイトル・リソース・説明、重要度、UTC 時刻、配信 ID を含め、固定ラベルは英語です。WeCom の 4096 バイト制限に合わせて通知内の長文を省略しますが、保存済みアラートは変更しません。実サービスでの検証は未実施で、ローカル HTTP テストで形式、署名、エラー、再試行を検証しました。導入時に自分のボットでテスト送信してください。

[DingTalk](https://open.dingtalk.com/document/robots/customize-robot-security-settings) · [Feishu](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot) · [WeCom](https://developer.work.weixin.qq.com/document/path/91770)

## ホストアラートのしきい値

システム設定で全ホスト共通のCPU・メモリ・ディスクしきい値（既定値90%・90%・85%）と継続時間1～60分（既定値5分）を設定できます。各しきい値を0にすると該当指標のアラートを無効にします。スキーマ6はこれらの制約付き設定を追加します。更新前にサービスを停止し、データディレクトリ全体をバックアップしてください。旧バイナリはスキーマ6を読めません。

ローカルとリモートで同じ判定を使います。CPU・メモリは継続時間全体でしきい値以上である必要があります。開始時刻以前のサンプルを含めて時間窓をカバーし、欠測や45秒超の間隔がないことを確認します。データ不足では新規アラートを作成せず、既存アラートも復旧させません。最新の有効値がしきい値未満になると復旧します。ディスクは最新の有効サンプルで即時判定します。しきい値の変更・無効化は次回の報告から反映し、無効化した指標のアラートは復旧します。リモートホストの90秒オフライン判定は変わりません。ホスト別の上書きは未実装です。

## ページ別更新と一覧クエリ

表示中のページは10秒ごとに、必要なホスト・チェック・アラートだけをセッションとナビゲーションとともに更新します。他のページでは軽量な件数APIでモバイルバッジを更新し、対象は一覧と同じ直近200イベントです。ロール・メンバー・権限は対象ページへの移動時や変更後に取得し、定期取得しません。ページ移動や書き込み後は再取得し、古いページやセッションの応答は破棄します。チェック一覧は3回、アラート一覧は2回のSQLで取得し、応答形式、24時間可用率、直近32チェックと各イベントの直近100活動は維持します。
