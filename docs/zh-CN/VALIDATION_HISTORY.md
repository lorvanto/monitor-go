## Docker 部署验证（2026-10-15）

提供三阶段 Dockerfile、Compose、构建上下文白名单与五语部署指南。基础镜像为带 manifest digest 的 Node 24.22.0、Go 1.26.9 和 Alpine 3.24.2。运行用户为 UID/GID 10001；Compose 使用只读根文件系统、独立持久卷、临时目录、就绪探针及正常退出宽限期。默认关闭容器内本机采集，实际主机使用原生 Agent。

本机 Docker Desktop 引擎 29.8.2、Compose 5.5.1；`linux/arm64` 在 Linux VM 内原生运行，`linux/amd64` 在同一引擎中模拟运行。两种镜像均实际启动并完成初始化、SQLite schema 4、Cookie/CSRF 写入、上传字节与 SHA-256、容器重建、会话及密钥文件保留、停机备份和空卷恢复。最终验证端口分别为 `54612`、`54622`，数据完全位于临时 Compose 项目和命名卷；脚本结束后清理测试容器与数据卷。

首轮备份暴露出 root 辅助进程在去除 capabilities 后无法读取 0700 数据目录的问题；已将备份与恢复统一为相同的非 root 运行用户，并同步五语命令，随后两种架构全流程通过。没有放宽服务权限或目录权限。

`docker build --check` 无警告；构建阶段容器实测不含源码树中的 `data/`、`tmp/` 或 `.git/`。Go 测试、文档检查器回归和格式检查通过；镜像构建内执行五语检查、44 份 Markdown / 387 个本地链接检查、TypeScript 类型检查和生产构建。五语 Docker 指南的命令逐段一致。

镜像大小约 30 MB，已提供本地源码构建方式；没有推送镜像仓库、创建 Release 或宣称裸机生产平台与容量验证通过。当前可验证的边界为以上 Docker Desktop 环境，宿主机采集、真实 SMTP 与部署容量仍需按目标环境验证。
