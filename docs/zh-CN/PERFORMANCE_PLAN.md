## 验收基线

建议部署基线：2 核 CPU、1 GiB 内存，20 台主机、100 个服务检测、5 人同时查看。主机采集保持 15 秒，检测默认 60 秒且允许原有自定义周期，页面前台刷新保持 10 秒。原始历史 7 天、服务小时汇总 90 天不变。图片密集使用建议预留 2 GiB。上述容量及常态内存 100–200 MiB、列表 P95 200ms / 图表 500ms 都是待压测目标，不是生产保证。

[复现命令与测量边界](../en-US/PERFORMANCE.md)。使用独立真实 SQLite WAL 文件与随机回环 HTTP 端口；不读写已有安装数据。固定数据：100.8 万条检测结果、80.64 万条主机采样、1 万条告警活动；5 个并发客户端、40 次并发探测/告警入库。突发请求与正常 10 秒轮询的负载不同；同一测试进程包含服务、客户端与 SQLite，不能直接当作独立服务内存。

### P2 查询与接口

- 24 小时统计按完整小时汇总 + 起始小时原始记录 + 未消费记录组合，在同一 SQLite 快照中读取；迟到记录及重复汇总不重复计数。显式使用未汇总记录索引，避免查询计划生成全表临时索引。
- 总览历史图表使用现有索引，32 项 / 2 秒有界缓存合并并发相同查询；当前检测、主机、事件、鉴权与通知不缓存。分组和时间范围独立，取消/错误不污染后续请求。
- 新增按页且按实时权限返回的 `/poll` 和单事件时间线接口；保留旧接口完整结构。前端接入属于 P3。
- 原接口同负载复测（56675，未启用图表缓存）列表 P95 520.174ms、总览 1027.608ms、CPU 10.484s。随后启用缓存复测（57756）CPU 4.935s，但宿主 Chrome / WindowServer 高负载下墙钟 18.683s、告警入库 P95 432.656ms，不能拿此轮墙钟值证明性能提升。最终阶段需重测，不隐藏波动。

### P3 前端刷新

- 每页基础轮询合并为一次鉴权请求；默认总览每轮为 `/poll` + `/overview` 两次，指定分组时增加一次总体统计。角色页仍按需获取团队资料；告警页只加载选中事件的时间线。
- 未变化的 JSON 子树复用引用；应用外壳和表单订阅自身依赖，图表缓存数据变换与路径计算，避免游标操作重复处理全部点。全量缓存不用于授权。
- 主机图表在最新采样、选中主机或时间范围改变时请求；没有新采样时最多每分钟更新时间窗口。前台轮询仍为 10 秒，隐藏时暂停，重新显示立即刷新。表单保存仍强制追加刷新，旧会话/旧页面响应继续丢弃。
- 53080 独立实例实际登录、总览、检测保存、告警详情和认领时间线正常；五语切换及超过一轮刷新后检测名称/目标草稿保留，控制台未见错误。历史事件的原始文字不改写。没有修改用户 5080 实例。

### P4 采集与调度

- OS、主机名、CPU 型号缓存 5 分钟；动态内存、IP、CPU、网络、磁盘容量与 APFS 身份逐次采集，运行时长递增。缓存到期读取失败仍报错，不用旧值伪装成功；无协议或依赖变化。
- SQLite 提交成功后发合并唤醒提示，任务完成立即释放工作槽并唤醒；按下个到期时间设定时器，30 秒兜底。回滚不唤醒，SQLite 仍为持久队列，4 个检测槽、2 个通知槽、通知 5 秒缓冲、失败阈值和退避策略保留。数据库写入失败按 1 秒退避，避免空转。
- 独立 HTTP 61965：12 个检测及告警 22.915ms 完成；61983：告警通知 5.002768s（含原 5 秒缓冲），手动测试通知 1.737ms。这是小型本机延迟测试，不是生产上限；实际通知网络耗时取决于渠道。
- 修正测试请求漏带乐观锁版本的 409 后，全量 Go 测试与专项 race 均通过。五语指南记录 Agent 升级与采集行为。

### P5 峰值与综合对照

- 图片仅在生成/缓存修改和打开缓存文件期间持锁，响应传输前释放；生成仍串行以限制内存。慢客户端阻塞时，另一缓存响应约 0.5ms 完成；缓存清理及重新生成保持内容一致（独立 HTTP 64627）。
- 每次历史汇总最多提交 2,000 行，汇总与标记同事务。故障注入在第 6,001 行中断时，前 6,000 行已完整提交；移除故障后继续，12,345 条记录无重复/遗漏。维护独立于检测调度运行，仍等待安全退出。
