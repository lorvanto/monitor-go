## 已实现范围

登录与初始化、12 个业务页面和共享组件已改为 React TSX。运行技术栈为 React / React DOM 19.3.0、Zustand 5.0.15；构建使用 TypeScript 5.9.3、Vite 8.3.4 和 React 插件。依赖版本与许可见 [第三方声明](../../THIRD_PARTY_NOTICES.md)，锁文件为 `web/package-lock.json`。

保留五语文案、语言偏好、表单未保存内容、浅深色主题、响应式布局、页面搜索、权限判断、上传进度、图表键盘操作和弹窗焦点管理。业务 API、Cookie / CSRF 约定、数据归属与 SQLite 结构保持兼容。此改动没有迁移真实数据库。

## 代码组织

| 路径 | 职责 |
|---|---|
| `web/src/main.tsx`、`App.tsx` | React 入口、应用框架、导航和按需加载页面 |
| `web/src/views/` | 按业务模块划分的页面和表单 |
| `web/src/components/` | 弹窗、图标、语言选择、图表、导航和通知组件 |
| `web/src/stores/app.ts` | 会话、权限、导航、API 与周期刷新 |
| `web/src/lib/` | 明确的业务类型、图表计算、状态与格式化工具 |
| `web/src/i18n/`、`locales/` | Zustand 语言订阅、按需加载及 Go / React 共享文案 |
| `web/tests/` | 语言单元测试、React 渲染与交互测试；数据为隔离实例合成样本 |

共享状态通过 Hook 订阅；事件中使用当前状态处理异步操作，更新嵌套表单时保留其他字段。不得在渲染阶段修改共享状态。页面卸载时清理定时器、监听器和上传任务。图表时间轴在同一数据窗口内保持稳定，业务页面和语言包分别按需加载。

## 迁移后复查（2026-10-15）

复查范围包括登录 / 初始化、12 个业务页面、共享组件、导航、权限判断、轮询、上传下载、表单和五语文案。对照迁移前各页面的入口与操作，未发现整块业务功能遗漏；以下边界问题已修复。

| 场景 | 修复后的行为 |
|---|---|
| 退出或重新登录时旧请求仍在运行 | 会话代次隔离请求；旧数据和旧 401 不再覆盖新登录，退出清空选择、检测中状态和提示 |
| 写入成功与周期刷新重叠 | 等待正在进行的刷新，再读取写入后的数据，不再跳过刷新 |
| 退出时网络断开 | 清理本地会话并显示连接错误，不产生未处理的 Promise 拒绝；服务端会话是否失效仍取决于退出请求是否送达 |
| 主机或时间窗口切换 | 图表数据绑定主机与时间窗口，加载期间不展示其他主机的曲线 |
| 编辑期间后台列表变化 | 主机备注和告警静默使用打开弹窗时的资源 ID 与版本，保留服务端冲突校验 |
| 连续预览文件、应用 A → B → A 切换 | 只接受最新请求；旧预览或旧密钥列表不能覆盖当前选择 |
| 删除末页最后一项 | 文件列表回到有效页码，避免出现“第 2 / 1 页” |
| 审计查询期间清除条件 | 新查询替换旧查询，迟到响应不会恢复已经清空的条件结果；查询失败后不能向旧条件结果追加数据 |
| 关闭安装包编辑窗口 | 忽略旧目录请求及错误，卸载时作废请求并中止上传 |
| 浏览器禁用偏好存储、页面分块加载失败 | 主题在当前会话可用；失败页面显示五语恢复入口，明确提醒刷新会丢失未保存修改 |

回归用例位于 `web/tests/regressions.test.tsx`，使用受控的迟到响应验证竞态。首批 8 个用例先在原实现中复现失败，再验证修复；新增共 16 个用例。全量 105 项 React 测试和 2 项语言基础测试通过，严格类型检查、生产构建、格式检查和五语检查通过。五语各 1155 条消息，新增 3 条页面恢复提示。

独立验证实例使用 `tmp/react-audit/` 的 SQLite，生产 Go 二进制监听 `127.0.0.1:5096`；测试账号、Agent 上报与文件均为合成数据。浏览器实测应用创建、密钥签发 / 撤销、安装文件上传 / 发布及字段锁定、文件夹创建 / 回收 / 恢复、文本预览、主机切换 / 备注保存、关联告警跳转 / 确认 / 静默、审计查询与清除。

另实测五语切换保留设置草稿，以及退出后切换只读账号：导航仅显示 4 项，直接访问设置页显示无权限。390px 窄屏下文件、应用、安装包、审计和设置页面没有页面级横向溢出，验证中未见浏览器控制台错误。

真实 HTTP 校验 32 个内嵌静态资源与生产产物一致，发布包下载内容及 SHA-256 一致，上述业务变更已保存，HTTP 检测正常；只读账号访问应用、文件、设置返回 403。`go test ./...`、`go test -race ./...`、`go vet ./...` 和服务端 / Agent 构建通过。

本次没有更改 Go API 或 SQLite 结构，没有使用正式数据，没有连接真实 SMTP 服务商或远程生产主机。浏览器下载事件监听在当前自动化环境未返回文件路径，因此下载内容以真实 HTTP 结果校验；不将其记为浏览器落盘验证。GitHub 同步不代表发布了标签、Release 或通过了远端 CI。

## 部署与后续开发

运行 `make build` 后，重新启动使用新二进制的 Go 服务。生产运行仍只需要 Go 二进制和数据目录，不需要 Node.js 服务。升级前按 [中文指南](README.md) 备份整套数据目录。浏览器刷新即可获取新的前端入口和带内容哈希的资源。

继续开发时维护现有服务端权限检查和版本冲突处理，不把菜单是否可见当作授权依据。新增交互补充对应测试；修改可见文案同步五语目录。此前阶段的验收记录保留为历史材料，不替代本次或后续版本的验证。
