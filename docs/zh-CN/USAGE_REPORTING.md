# 首次激活与使用情况上报

[English](../en-US/USAGE_REPORTING.md) · [简体中文](../zh-CN/USAGE_REPORTING.md) · [日本語](../ja-JP/USAGE_REPORTING.md) · [한국어](../ko-KR/USAGE_REPORTING.md) · [繁體中文](../zh-TW/USAGE_REPORTING.md)

Monitor Go 与 Monitor Console 是独立仓库、服务和数据库，源码与数据目录分别放在同级目录。安装 Monitor Go 只需本公开仓库，不需要私有后台源码。标准首次安装会连接配置的 Console 完成激活；后续登录、监控和告警独立运行。

标准新安装须先在线激活，再创建首个本地管理员。安装页明确展示目的地（预设为 `https://feiniu.i7f.cn:5090`）、统计用途、具体字段，以及上报持续开启且没有关闭开关的规则，要求手动确认告知版本 `2`。登记成功后创建本地管理员并启用持续后台上报；不会向 Console 发送本地用户名、显示名称或密码。登记失败不创建管理员，恢复网络后以同一实例身份重试。激活不要求 Console 账号或 GitHub 登录，也不会自动绑定开发者账号。

已有开启上报的实例升级时保留身份、凭据、账号绑定和历史同意记录，不补造新的确认。旧版关闭上报的实例不会被静默开启；具有 `system:settings` 权限的管理员需要查看当前目的地、字段和不可关闭规则，进行一次确认，登记成功后才启用上报。登记或本地事务失败仍保持关闭。等待确认期间，本地登录、监控和告警继续运行。更换接收方会清除原本地上报身份，并要求确认新目的地后才向其发送。

上报仅包含随机实例编号、版本、系统类型、处理器架构、部署方式，以及已登录用户实际操作界面的 UTC 日期。不包含本地账号列表、监控目标、主机名称/IP、文件、告警正文、密码、监控密钥或应用密钥。实例凭据只用于登记和请求认证，不在界面显示。后台账号独立于 Monitor Go：本地 Console 账号保存用户名与显示名称；选择 GitHub 登录时另行保存经验证的 GitHub 编号、用户名和显示名称。

实例登记和活跃统计无需绑定账号。Console 支持本地管理员账号密码登录，GitHub 登录为可选功能；安装 Monitor Go 无需配置 OAuth。

如需关联账号，先使用本地 Console 账号或已启用的 GitHub 登录 Monitor Console，生成 10 分钟有效的一次性绑定码，再粘贴到 Monitor Go 的上报设置卡片。需先开启上报。解除绑定仅移除账号关联，不会关闭上报；也可在后台解除自己名下实例的关联。

“上次同步的 Console 账号”是本地快照。在 Monitor Console 端解绑后，Monitor Go 要等到下次成功上报才更新显示。网络故障或旧实例等待确认期间可能保留旧账号。“刷新上报状态”仅重新读取本地设置，不发起远端同步。

开启后独立任务先上报一次，此后约每 6 小时上报并加入随机错峰。单次请求 5 秒超时，不跟随重定向，失败采用有上限的退避重试；最多保留 7 个 UTC 日期的待发送活跃标记。自动刷新和单纯加载页面不计入人工活跃。每日按实例去重，不代表独立用户人数；这些是自报的使用情况估算，无法证明身份或完整安装量。

如果远端登记成功，但本地创建管理员事务失败或安装被取消，后台可能保留未绑定的随机实例记录；重试复用同一身份。因此登记数不等于已完成安装数或真实用户人数。

激活或确认后，上报持续开启，界面、API 和部署参数均不提供关闭方式；请求关闭返回 HTTP 403。Console 故障只触发独立后台退避重试，不会阻断登录、监控或告警。后台每日记录保留 90 天，365 天未上报的实例会清理；后续上报可再次登记，但需重新绑定账号。解绑不会停止上报，也不删除已接收的历史记录。

仅支持 HTTPS；数字回环地址的 HTTP 仅供本机联调。容器中的回环地址指向容器自身，分开部署的容器应连接真实 HTTPS 地址。不要将凭据、数据目录或备份提交 Git；反向代理日志应避免记录 OAuth 查询参数、完整来源 IP 和凭据。

数据库继续使用结构版本 10；告知版本 `2` 利用已有告知版本、同意时间和激活时间字段记录持续上报规则的确认，不改写已有历史同意。升级前完整备份数据目录，回退需恢复原备份。随机身份随数据目录保存，克隆目录可能合并统计；未确认的旧实例和网络不可达的客户端不会构成完整安装量统计。

`MONITOR_CONSOLE_URL` 未设置时，原生程序和 Compose 使用 `https://feiniu.i7f.cn:5090`；可设为其他 HTTPS 来源以更换目的地，原生 `-console-url` 参数优先。空值或纯空白目的地（包括环境变量提供的值）属于无效配置，标准 CLI 会拒绝启动，不能用于关闭上报或绕过激活。版本查询和备份命令不依赖激活配置。

标准 CLI 与 Compose 必须激活并上报。旧的 `-require-activation=false` 和 `MONITOR_REQUIRE_ACTIVATION=false` 配置会明确报错，不再支持；`true` 保留兼容。没有受支持的离线安装或关闭上报参数。应配置可达的 HTTPS Console 地址，空或纯空白目的地属于无效启动配置，不能用于关闭上报或绕过激活。Console URL 参数优先于对应环境变量；已有 activation=false 配置不能通过另加 true 参数变为有效。

```sh
./bin/monitor -data data -listen 127.0.0.1:5080
```

`MONITOR_CONSOLE_URL` / `-console-url`; `MONITOR_REQUIRE_ACTIVATION` / `-require-activation`; `MONITOR_DEPLOYMENT=native|docker` / `-deployment`.

原生程序默认使用 `native`；Docker 镜像和 Compose 自动设置为 `docker`。
