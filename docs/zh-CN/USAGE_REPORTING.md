# 自愿使用情况上报

[English](../en-US/USAGE_REPORTING.md) · [简体中文](../zh-CN/USAGE_REPORTING.md) · [日本語](../ja-JP/USAGE_REPORTING.md) · [한국어](../ko-KR/USAGE_REPORTING.md) · [繁體中文](../zh-TW/USAGE_REPORTING.md)

Monitor Go 与 Monitor Console 是独立仓库和服务，放在同级目录，各自使用数据目录。Monitor Go 无需统计后台也能正常工作。

同时维护两个项目时，将源码目录并列放置，数据目录各自独立。普通 Monitor Go 安装只需要本公开仓库；可选上报只需要可访问的统计服务，不需要获取私有后台源码。

新安装以及从不含此功能的版本升级时，上报默认关闭。后续重启或升级会保留管理员对同一接收方保存的选择。先在服务端配置统计后台地址，再由具有 system:settings 权限的管理员，在系统设置中查看字段并明确开启。只配置地址不会开启上报；更换接收方地址需要重新同意。

上报仅包含随机实例编号、版本、系统类型、处理器架构、部署方式，以及已登录用户实际操作界面的 UTC 日期。不包含本地账号列表、监控目标、主机名称/IP、文件、告警正文、密码、监控密钥或应用密钥。实例凭据只用于登记和请求认证，不在界面显示。后台登录另行保存用户自愿关联的 GitHub 编号、用户名和显示名称。

先用 GitHub 登录 Monitor Console，生成 10 分钟有效的一次性绑定码，再粘贴到 Monitor Go 的上报设置卡片。需先开启上报。解除绑定仅移除账号关联，不会关闭上报；也可在后台解除自己名下实例的关联。

“上次同步的 GitHub 账号”是本地保存的快照。在 Monitor Console 端解绑后，Monitor Go 要等到下一次成功上报才会更新该显示。关闭上报期间不会联系后台，因此可能继续显示旧账号。“刷新上报状态”只重新读取本地设置，不会请求后台或发起远端同步。

开启后独立任务先上报一次，此后约每 6 小时上报并加入随机错峰。单次请求 5 秒超时，不跟随重定向，失败采用有上限的退避重试；最多保留 7 个 UTC 日期的待发送活跃标记。自动刷新和单纯加载页面不计入人工活跃。每日按实例去重，不代表独立用户人数；这些是自报的使用情况估算，无法证明身份或完整安装量。

可随时关闭：取消在途请求、清空待发送活跃记录，监控、告警和登录保持独立。关闭不删除后台已收到的历史记录。后台每日记录保留 90 天，365 天未上报的实例会被清理；之后重新上报可再次登记，但需要重新绑定账号。

仅支持 HTTPS；数字回环地址的 HTTP 仅供本机联调。默认不内置官方后台域名。容器中的回环地址指向容器自身，分开部署的容器应连接真实 HTTPS 地址。不要将凭据、数据目录或备份提交 Git；反向代理日志应避免记录 OAuth 查询参数、完整来源 IP 和凭据。

结构版本 9 新增上报设置和粗粒度活跃日期。升级前完整备份数据目录，回退需恢复原备份。随机实例身份随数据目录持久保存，克隆目录可能合并统计；关闭上报、离线或修改源码的安装无法完整统计。

```sh
MONITOR_CONSOLE_URL=https://console.example.com ./bin/monitor -data data -listen 127.0.0.1:5080
```

`MONITOR_CONSOLE_URL` / `-console-url`; `MONITOR_DEPLOYMENT=native|docker` / `-deployment`.

原生程序默认使用 `native`；Docker 镜像和 Compose 自动设置为 `docker`。
