## 语言与内容边界

浏览器首次访问默认英文，不自动按浏览器语言选择界面；以后恢复本地存储 `monitor.locale` 中的有效选择，未保存、无效或存储不可用时均使用英文。语言包按需加载，加载失败时保留当前语言并显示错误。`zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO` 归为繁体中文；其他中文区域回退简体。日期、时间、数字通过 `Intl` 格式化，时区使用浏览器本地时区。语言偏好不写入实例共享设置。

`api()` 与两种文件上传入口都会携带 `Accept-Language`。API 按权重选择语言，错误正文采用对应翻译，响应带 `Content-Language` 与 `Vary: Accept-Language`。无此请求头时保留原接口的简体中文行为；有请求头但没有受支持语言时使用英文。HTTP 状态码、JSON 字段名、权限键、页面键、机器 API 路径保持稳定。接口消息是给人阅读的内容，调用方应依据状态码及业务响应判断结果，不应解析翻译后的字符串。

本次覆盖页面固定文案、表单、按钮、状态、空状态、对话框、无障碍标签、导出表头、权限／密钥范围元数据和 API 校验提示。记录中的自定义名称、主机备注、文件名、文件内容、历史告警与审计、探测诊断、SMTP/Webhook 本文、日志和 CLI 帮助保留原文；这部分不等于已完成全链路翻译。

内置菜单仅在未改名时返回可翻译的 `nameKey`，界面在显示处翻译。自定义菜单和改名后的菜单不参与匹配。编辑表单始终保留原数据，不能对整个 API 响应或 DOM 文本进行替换。根目录等系统名称如未覆盖也按原始记录显示，不能拿普通文件名去匹配文案目录。

## 文案约定

- 使用源文案作为 gettext 风格消息键。键位于类型受约束的目录中；修改源文案时同时修改调用与五语目录。
- React 可见文案调用 `t()`；静态标签表用 `localizedLabels()` 惰性求值，避免语言切换后保留旧标签。后端固定权限／范围元数据只在指定展示位置调用 `metadataLabel()`。
- 带变量的整句使用 `{p0}`、`{p1}` 等占位符，允许翻译调整顺序。不要拼接“数量＋单位＋后半句”。原始参数通过 React 文本插值显示，不使用 `dangerouslySetInnerHTML`。
- 服务端带数字的校验使用 `badf()` 保留格式模板和参数，选定语言后再格式化。目录中的 `%d` 数量必须一致。
- 时间范围采用 `1h`、`24h`、`7d` 稳定值，不能用翻译后的“24 小时”作查询条件。永久删除界面按所选语言确认，向后端发送固定 `DELETE`，后端兼容旧中文确认值。
- 用户填写的文本不是语言资源。切换语言不可重建表单、清空输入或重新提交任何业务操作。
- 繁体中文使用独立目录。首次整理使用系统文字转换辅助，并调整伺服器、資料、檔案、設定等术语；后续按独立译文维护。英文、日文、韩文均有完整消息键集合，但仍欢迎母语使用者校订表达。

## 文档布局

根 `README.md` 是英文项目入口。五语文档统一按 `docs/<locale>/` 组织，目录和文件名使用英文，正文保留对应语言。[完整简体中文指南](README.md)保存当前部署细节，历史验证集中在 [历史验证记录](VALIDATION_HISTORY.md)，繁体指南位于 `docs/zh-TW/README.md`。总入口是 [docs/README.md](../README.md)。国际化维护规范也提供英日韩繁体入口。

现有简体中文设计文档集中在 `docs/zh-CN/`，保留原有实施边界，不把历史建议重新包装为已实现功能。当前没有宣称把全部历史设计文档逐篇翻译。修改部署命令、支持版本、安全边界或操作规则时，应同步五语当前指南；修改中文资料时更新 [文档索引](INDEX.md)。

## 表单与错误提示的语言

安装、登录、弹窗、浏览器字段校验及临时提示均跟随所选界面语言；切换语言后，无需重新提交即可更新已有错误。编辑弹窗中未改动的默认名称也随语言切换，已输入的名称和其他未保存内容保持不变。新建检测的空分组显示本地化默认名称；已有分组名称及历史记录保留原文。

原生表单校验统一使用 `Form`，需要保存的临时提示使用 `notice()` / `errorMessage()`。API 错误保留 `message`，并附带明确的 `key` / `args`，供界面响应语言切换；不得从用户文本猜测翻译键。下载与图片链接用 `apiLink()` 携带 `lang`，有效的 GET/HEAD 语言参数优先于浏览器请求头。总览和可用率接口用 `ungrouped=1` 筛选空默认分组；省略或传入空 `group` 仍表示全部分组。检查器拒绝英文翻译值中的中文及共享组件之外的原生 form，Go 测试检查 API 错误翻译覆盖。

## 弹窗内切换语言

所有共享弹窗均提供语言选择器，无需关闭编辑器即可切换。已填写的名称、备注、密码、复选框和下拉选择保持不变；删除确认按输入时的语言识别，服务端仍接收固定 `DELETE` 标记。API／上传返回异常格式时显示本地化错误，不存在的接口也返回可随语言切换的错误键。

文案检查新增韩文／中文／日文字形混用、整条英文照搬检查，对协议和产品名称保留明确例外；繁体中文统一采用登入、金鑰、封存、連接埠等术语。日文正常汉字和语言选项自称不算混用。检查仅作用于系统文案，不处理用户数据或已保存诊断。交互回归使用弹窗内真实语言选择器，校验草稿保留且不新增请求。

## 手机布局与弹窗

语言选择器的文字与下拉箭头应保留间距；紧凑控件的内边距不能覆盖箭头预留区域，所有屏幕宽度都需检查。

窄屏下时间范围按钮自动换行，超长应用名、主机名和告警资源名在面板内折行。弹窗正文独立滚动，关闭和底部操作保持可用；长说明随正文滚动，长标题在限制高度的区域内滚动。文件／图片预览和安装包目录下拉框适应可用宽度。

弹窗随浏览器可视区域的高度和平移变化调整位置，并将当前输入框滚动到可见位置，保留草稿。手机表单采用可读字号，底部按钮扩大点击区域并允许长标签换行。维护时检查五语在 320px、390px 竖屏、640px 横屏及缩小高度下的表现，同时测量页面／弹窗内部宽度和按钮实际命中区域。

## 手机实际流程验证（2026-10-15）

使用独立临时安装和合成文件复查完整操作，而不只检查截图。在 320×568、390×844 浏览器视口下覆盖五种界面语言：

1. 检查首次默认英文、安装必填提示及切换语言后的安装草稿。通过真实 HTTP 完成初始化，核对 SQLite 管理员记录和 `setup-token` 自动移除。
2. 逐一使用五语登录、退出；刷新登录页确认语言记忆。已有登录错误随语言更新，已填写凭据不清空。
3. 创建应用和目录，保存设置，新增／编辑 HTTP 检测。保存前切换语言，核对文字、数字及目录选项；重新打开或刷新，并通过 HTTP 和 SQLite 复核持久化值。对本地测试目标实际执行检测。
4. 在五语界面分别选择文件、真实上传、预览及下载，比较源文件与下载内容的 SHA-256；保留多语文件名和正文。空文件被拒绝时，同批有效文件仍成功上传；同名冲突提示随五语切换。修正文件后重试，并验证测试服务中断后的上传恢复。改名、移动后再次核对下载名称和内容。

本次使用版本 `2a5674c`，独立端口 `62538`，核对五个应用、一个新目录、设置、一个正常 HTTP 检测及八份已存储文件。五语下载均与源文件一致；SQLite 完整性及外键检查通过。未复现新的产品缺陷，本次追加仅更新文档。

初始化提交通过 HTTP 验证，安装表单校验和草稿切换通过浏览器验证。这些属于桌面浏览器手机视口与文件选择流程验证，不代表已在实体手机、手机原生选择器或真机键盘上验收。中断测试不得使用真实安装数据。
