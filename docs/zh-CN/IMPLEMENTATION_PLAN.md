# 实施计划与验收标准

> 文档类型：长期实施与验收规划；不是已完成清单。当前使用方式以 [使用指南](README.md) 为准，公开发布流程见 [GitHub 发布指南](GITHUB.md)。

已完成独立项目与五类页面的首轮后端接入，包括账号权限、SQLite、本机与 Agent 采样、五种检测、站内告警、SMTP / Webhook 和投递重试。已补齐菜单管理、文件与目录、图片样式、回收站、操作审计和基础设置，以及应用密钥、安装包、二维码条码。实际交付与验证结果以 README 为准。以下阶段按完整产品划分，尚未整阶段完成，不代表全部功能已经开发。

确定的实施边界为 Go 后端、React 前端、内置 SQLite、单套安装内多人协作和完整通用后台。项目名称为 Monitor Go，许可证为 Apache-2.0；公开源码仓库为 lorvanto/monitor-go。

## 实施顺序

| 阶段 | 交付内容 | 验收条件 |
|---|---|---|
| 第一阶段 方案和原型 | 功能范围、数据模型、API 基线、五类代表页面原型 | 明确已实现与规划能力；权限、导航和交互规则可评审 |
| 第二阶段 工程基础 | Go 服务、React 工程、SQLite 迁移、初始化、登录、角色、菜单、审计 | 空目录首次启动成功；两名用户权限不同；直接请求越权接口被拒绝；改密和停用撤销会话 |
| 第三阶段 完整检测流程 | HTTP/TCP/SSL 目标、调度、历史、告警规则、Webhook 和投递重试 | 创建目标后实际检测，产生故障和恢复，通知结果可追踪；重启不重复创建活动告警 |
| 第四阶段 主机与 Agent | Agent 安装注册、主机指标、历史聚合、MySQL/Redis 探测、导入导出 | Linux amd64/arm64 验证采集和探测；重复上报不重复入库；断网重连后有明确结果 |
| 第五阶段 完整告警与证书 | 全部通知渠道、静默、维护、日报、ACME 申请、验证、续期和下载 | 通知与维护场景完整；使用 ACME 测试环境签发；手动 DNS 不被误标为自动续期 |
| 第六阶段 通用后台补齐 | 文件真实上传、目录、图片样式、应用凭据、安装包、二维码条码、系统工具 | 上传下载和权限完整；客户端凭据可限制和撤销；通用后台清单逐项验收 |
| 第七阶段 发布准备 | 打包、容器、备份恢复、升级、容量报告、文档、许可证与贡献说明 | 干净环境独立安装，备份可恢复，升级可演练，发布包运行依赖完整 |

阶段顺序可按使用优先级调整，但第一稳定版的范围以完整功能清单为准。中途发布测试版必须明确未完成模块。

## 工程初始化建议

先建立能运行的最小链路：启动服务、打开页面、初始化管理员、登录、显示当前身份。随后增加用户和角色及一个真实监控目标。

Go module 路径为 `github.com/lorvanto/monitor-go`。React 工程启用 TypeScript、格式检查、类型检查和构建。SQLite 只维护一套 SQL 迁移，使用真实临时文件做集成测试。

第一版可运行包包含前端资源，默认在受控监听地址启动并指定数据目录。部署配置明确监听地址、公开访问地址、可信代理、数据路径和日志级别。示例配置不含可用密钥。

## 核心测试

| 范围 | 必须验证的行为 |
|---|---|
| 账号 | 错误密码、登录限流、注销、会话过期、改密、停用、最后一个管理员保护 |
| 权限 | 菜单隐藏与直接 API 访问分别验证，导出和敏感下载权限单独验证 |
| 协作 | 并发修改返回冲突；授权撤销影响现有会话；审计记录明确操作人 |
| SQLite | 新建、升级、唯一约束、外键、短事务、写入繁忙、磁盘不足、崩溃后恢复 |
| 调度 | 同一计划幂等、超时取消、租约恢复、重复领取和停用资源后的行为 |
| Agent | 安装凭据过期与并发使用、重复注册、设备吊销、时钟偏差、重复上报和缓冲溢出 |
| 历史 | 聚合加权、缺失值、迟到数据重算、原始记录清理前检查聚合水位 |
| 告警 | 连续失败、恢复、规则优先级、确认、静默、维护结束、通知重试与去重 |
| 证书 | HTTP/DNS 挑战失败、重启恢复订单、签发、手动续期提示、下载权限和私钥保护 |
| 文件 | 上传失败清理、目录防环、类型与大小限制、路径边界、预览和下载授权 |
| 前端 | 首次安装、登录、添加检测、Agent 接入、告警处理、角色授权和版本冲突 |

外部通知使用模拟发送端验证协议和失败处理，经过用户配置后再测试真实渠道；测试不得向真实团队发送无关通知。证书测试优先使用 ACME staging，避免生产环境速率限制和真实域名配置变更。

## 容量验证

容量目标随实际测试确定。建议使用以下梯度作为测试输入，不作为支持能力承诺。

| 场景 | 主机数 | 检测目标数 | 主要频率 | 浏览器并发 |
|---|---|---|---|---|
| 轻量 | 20 | 50 | 主机 60 秒、检测 60 秒 | 3 |
| 团队 | 100 | 500 | 主机 60 秒、检测 60 秒 | 10 |
| 压力探索 | 500 | 2000 | 主机 60 秒、检测 30 秒 | 30 |

SSL 日常检查单独使用较低频率。网络检测耗时、失败比例和通知延迟要同时进入测试，不能只测数据库空写入。测试数据覆盖原始和聚合保留范围，包含多磁盘主机。

记录硬件、操作系统、驱动与 SQLite 版本、数据量、并发设置、每秒写入、CPU、内存、数据库大小、WAL 大小、队列长度、写入延迟、调度延迟和查询延迟。

基础通过条件为：没有静默丢失已确认上报、队列没有持续失控增长、没有长期锁死、常见页面保持可操作。延迟目标在原型与首轮实测后定义，并与最终容量报告一起公开。超出容量时返回明确错误或排队状态，不能把丢弃数据记为成功。

## 备份与升级验收

在独立空目录执行恢复，验证账号和权限、监控配置、文件、证书解密、ACME 账户和任务状态。数据库备份与文件、密钥资料必须形成一致的备份集。

SQLite 使用驱动的一致性备份机制或经验证的导出方式；运行时不得简单复制主数据库文件当作完整在线备份。停止服务后的离线备份也应纳入数据目录和密钥说明。

对至少一个前序数据库版本演练升级；中断迁移后再次启动不能进入不完整业务状态。升级失败的恢复路径是还原对应软件与完整备份，过程写入文档。

## 独立仓库与公开发布

- 仓库只包含本项目源码、测试、样例和文档，不提交运行数据和密钥。
- 不引用相邻项目目录，不使用指向仓库外部的软链接，不依赖外部业务数据库。
- 运行成品不要求用户安装 Go、Node.js 或外部数据库服务。
- 为目标平台生成校验和与版本信息，核对服务端和 Agent 版本兼容范围。
- 已提供五语当前使用指南；每次发布同步安装、升级、备份和已知限制。
- 项目采用 Apache-2.0，发布产物需要保留项目与适用第三方许可证、署名和通知。
- 在用户实际要求发布时，才创建或绑定 GitHub 远程并推送。
