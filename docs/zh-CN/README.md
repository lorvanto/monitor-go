# Monitor Go

面向个人和团队自行部署的监控运维平台。Go 服务、React 19 界面、内置 SQLite 文件数据库；一套安装内多人协作，不做多租户。当前开发基线 0.4.0 已完成五类核心页面、远程 Agent、邮件 / Webhook 通知，以及菜单、文件、图片样式、操作审计、基础设置、应用密钥、安装包、二维码和条码。其余模块按 [项目文档](INDEX.md) 分阶段实施。

## 国际化

界面支持简体中文、英文、日文、韩文、繁体中文。登录页和登录后侧栏均可切换；首次访问默认英文，不自动跟随浏览器语言；此后恢复本浏览器已保存的有效选择，未保存、无效或存储不可用时均使用英文。语言仅影响当前浏览器显示，日期、数字和图表时间跟随语言，时区仍采用浏览器本地时区。正在编辑的表单不会因语言切换而重建。

页面固定文案、未改名的内置导航、权限与接口范围说明、API 校验错误已接入语言目录。用户填写的名称、备注、目录、历史告警、探测诊断、审计记录、SMTP/Webhook 内容及服务端日志保留原文。历史设计资料目前以简体中文为准，其他语言使用指南列明当前能力与限制。扩展规范见 [国际化与文档维护](INTERNATIONALIZATION.md)。

## React 前端结构

当前使用 React / React DOM 19.3.0、TypeScript 5.9.3、Vite 8.3.4 和 Zustand 5.0.15。`web/src/views/` 按业务页面组织，通过 `React.lazy` 按需加载；`components/` 为共享 TSX 组件，`stores/app.ts` 管理会话、权限、导航与刷新，`lib/` 保存 API 类型、图表和格式化工具，`i18n/` 订阅五语状态。构建产物由 Go 内嵌提供，生产环境不需要 Node.js 服务。

`npm --prefix web test` 执行语言测试和 Vitest / React Testing Library 交互测试；`npm --prefix web run typecheck` 同时检查应用与测试代码。此次迁移保留原 API、CSRF、上传和 SQLite 契约，没有新增数据库迁移。部署时重新构建 Go 二进制并重启服务。具体范围见 [React 前端迁移与验证](REACT_MIGRATION.md)。

前端会忽略旧登录会话和旧页面选择的迟到响应；主机备注与告警静默绑定打开弹窗时的对象和版本。文件末页清空后自动调整页码，审计查询加载中也可清除条件。浏览器无法保存偏好时仍可切换主题；页面加载失败会提供刷新入口，并提醒未保存修改将丢失。

## Docker 部署

宿主机安装 Docker 与 Compose 后，可直接从源码构建，无需宿主机 Go 或 Node.js：

```sh
docker compose up -d --build
docker compose exec monitor cat /data/setup-token
```

打开 5080 端口，使用初始化码创建管理员。命名卷持久保存完整数据目录；容器默认关闭本机指标采集，真实主机使用原生 Agent。端口冲突、HTTPS、备份恢复与升级详见 [Docker 部署指南](DOCKER.md)。

## 启动

示例命令使用 POSIX shell；Windows 开发者可使用 WSL。开发构建需要 Go 1.26.9 或更新的兼容版本，以及 Node.js 22.12+ / 24.x。依赖锁定在 `go.mod`、`go.sum` 和 `web/package-lock.json`。前端运行依赖为 React / React DOM 19.3.0、Zustand 5.0.15、`lucide-react` 1.57.0 图标，以及 `@fontsource-variable/ibm-plex-sans` 5.3.0 与 `@fontsource/ibm-plex-mono` 5.3.0 字体（OFL-1.1 许可，用于数字、英文和机器标识）；字体文件随前端资源嵌入二进制，浏览器按字符范围按需加载（中文界面通常只加载拉丁子集），中文使用系统字体。

```sh
make build
./bin/monitor -data data -listen 127.0.0.1:5080
```

打开 [本地服务](http://127.0.0.1:5080/)。成品二进制已嵌入前端资源，运行时无需 Node.js、Java 或外部数据库。

首次启动后，从同一数据目录读取初始化码：

```sh
cat data/setup-token
```

在页面输入初始化码、用户名、姓名和密码。初始化完成后自动删除初始化码文件，进入监控中心。此时本机指标会自动采集，检测列表为空，按需要添加真实目标。不会自动创建公网检测、演示账号或虚构业务数据。

用于多人访问时可修改监听地址，并在可信 HTTPS 反向代理后运行：

```sh
./bin/monitor -data data -listen 127.0.0.1:5080 \
  -public-url https://monitor.example.com -secure-cookie
```

`-public-url` 填浏览器实际访问的来源，不带末尾斜杠。代理须正确转发请求。`-collect-host=false` 可关闭本机采样。当前支持一个活动服务进程，不允许多个实例共享一个数据目录。

## 接入远程主机

在「主机详情」点击「接入远程主机」，填写名称后生成有效期 15 分钟的接入码。每次接入绑定一台预登记主机，不能用同一接入码注册其他机器。主机页支持切换、重新接入与撤销；操作需要新增的 `host:agents` 权限，默认仅超级管理员拥有。

`make build` 同时生成服务端 `bin/monitor` 与采集端 `bin/agent`。将匹配远程系统 / 架构的采集程序复制到远程主机，例如构建 Linux 版本：

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o bin/agent-linux-amd64 ./cmd/agent
# ARM64 主机将 GOARCH 改为 arm64
```

在远程主机保存页面下载的 `enrollment-token`，然后运行：

```sh
chmod 600 enrollment-token
./agent -server https://monitor.example.com -enrollment-file enrollment-token -config agent-data/config.json
```

Agent 必须能访问服务端，HTTPS 证书要有效且受系统信任。私有 CA 可在首次运行加 `-ca-file /path/to/ca.pem`。仅数字回环地址允许 HTTP 本机联调。服务端通过反向代理公开时，应转发 `/api/v1/agent/`，无需开放 Agent 入站端口。

成功注册后，持久凭据保存到 `agent-data/config.json`（0600 权限），接入码从配置中移除，原 `enrollment-token` 文件可由部署者删除。以后启动只需要：

```sh
./agent -config agent-data/config.json
```

不要把同一配置文件复制给其他主机。重新接入会立即吊销旧凭据，需要停止旧进程并使用新的配置路径注册。凭据只可上报自身指标，不具有后台登录或修改权限。当前最多登记 1000 台远程主机，此数值只是配置限制，尚未完成容量压测。

Agent 注册后立即采样，随后约每 15 秒上报 CPU、内存、磁盘、网络和系统信息。服务端以接收时间记历史；同一报告重复发送不会重复入库或延长在线时间。采样时间需在服务端 ±5 分钟内，乱序数据拒绝写入。网络错误退避重试，最长 60 秒；当前不保存断网期间的历史，曲线如实留空。超过 90 秒未收到数据产生离线告警，最多再等待 10 秒巡检；新上报自动恢复。待接入主机不触发离线告警，已注册但一直未上报的主机会触发。

Linux 常驻运行可使用 [systemd 单元](../../deploy/monitor-go-agent.service)。先由部署者创建 `monitor-go-agent` 系统用户与 `/var/lib/monitor-go-agent`（该用户所有、0700），将程序放到 `/usr/local/bin/monitor-go-agent`；以该用户完成首次注册，配置路径为 `/var/lib/monitor-go-agent/config.json`。随后安装单元到 `/etc/systemd/system/`，执行 `systemctl daemon-reload` 和 `systemctl enable --now monitor-go-agent`。该单元无需 root 运行，配置与采样权限不足时应检查日志。此文件是部署模板，当前机器没有自动安装系统服务。

## 外部告警通知

在「告警中心 → 通知渠道」新增 SMTP 邮件、通用 Webhook 或群机器人 Webhook；配置需要 `notification:manage`，默认仅超级管理员拥有。支持编辑、启停、软归档及真实测试投递，渠道最多 20 个。SMTP 密码 / 授权码和 Webhook 签名密钥不通过读取接口回显，整个渠道配置在 SQLite 中使用 AES-GCM 加密。编辑时密钥留空保持不变。

- SMTP 仅支持校验证书的 TLS（通常 465）或 STARTTLS（通常 587），拒绝降级明文。可配置 1–20 个收件邮箱，SMTP 服务接受不保证邮件最终进入收件箱。
- Webhook 必须为 HTTPS（数字回环地址可 HTTP 联调），POST JSON，通用格式以 HTTP 2xx 视为成功；不跟随重定向，不发送浏览器 Cookie。与检测拨号共用地址校验，拒绝链路本地 / 云元数据地址。
- 新故障与恢复各生成一次持久投递任务，同一事件与渠道有唯一约束。新渠道不追溯历史事件。两名后台执行器并发发送，网络调用不占用数据库事务。
- 最多尝试 4 次，失败后依次等待 15 秒、60 秒、5 分钟；重启继续未完成任务。最终失败后可在「投递记录」手动重试，保留相同投递 ID。
- 发出前再次检查事件静默和渠道状态；静默期跳过故障及恢复通知，不在到期后补发；已恢复故障的过时首报也会跳过。修改或停用渠道取消旧的待投递任务。已开始发送的消息不能保证撤回。
- 传输采用至少一次语义：发送成功但确认入库前崩溃可能重复。Webhook 接收端以 `X-MonitorGo-Delivery-ID` 去重；SMTP 使用稳定 Message-ID，但不承诺收件端去重。
- 投递记录保留 30 天，页面返回最近 200 条；静默跳过、失败原因、尝试次数和下次执行时间均可查看。测试通知每渠道每分钟最多 3 次，不受某一事件静默影响。

通用 Webhook 请求体示例（字段值仅为示意）：

```json
{"deliveryId":"101","event":"opened","at":1791936000000,"alertId":"22","resource":"api.example.com","severity":"critical","title":"服务异常","description":"HTTP 503"}
```

`event` 为 `opened`、`resolved` 或 `test`。配置签名密钥后，`X-MonitorGo-Signature` 为 `sha256=` 加 HMAC-SHA256 十六进制值；待签字节为 `X-MonitorGo-Timestamp` 的秒级时间文本、一个英文句点、未经重新编码的请求体。接收端应验证签名与时间窗口，并以稳定投递编号做幂等处理。

## 菜单、文件和基础管理

侧栏新增「文件与资源」和「系统管理」分组。导航由 `GET /api/v1/me/navigation` 按角色权限返回；每 10 秒刷新，保存菜单后立即刷新。最多 200 个菜单、3 层结构，支持分组、已注册页面和不含登录凭据的 HTTP(S) 外链。排序值越小越靠前，父子关系不能成环。内置菜单可编辑或隐藏，类型和绑定页面固定；自定义菜单可软删除，删除分组前需先处理子菜单。恢复内置导航会保留自定义项。隐藏只改变展示，不撤销直接访问页面或 API 的权限；个人菜单始终为有权用户提供「管理导航」和「系统设置」入口。

文件在本实例内由团队共享，创建人仅用于审计。原文件写入 `data/uploads/objects/`，磁盘名称为服务器生成的随机对象键；SQLite 保存目录、名称、MIME、大小、SHA-256 与版本。重命名和移动不复制原文件，存储使用 `os.Root` 限制路径和越界符号链接。目录内名称采用 SQLite NOCASE 唯一约束（ASCII 大小写不区分），最多 1000 个未永久删除的目录，目录层级受限。

- 界面支持一次选择最多 50 个文件，逐个上传并显示进度，失败逐项提示。服务端同时接收最多 2 个上传，每个请求包含一个 multipart `file`。默认单文件 32 MB，可配置 1–1024 MB；默认原文件总配额 1024 MB，可配置 10–1048576 MB。最终入库再次检查配额，回收站占用也计入。
- 上传先写临时文件，计算 SHA-256 并同步磁盘，再以短事务和原子重命名完成存储。失败清理本次临时对象；启动和每小时巡检会在受限时间内清理超过 24 小时的未引用上传残留，保留近期传输和已引用原文件。
- 文件列表每页 50 项，名称搜索限定当前目录；回收站只显示每次删除的根条目。普通删除将整个有效子树一同移入回收站。根目录与包含默认上传目录的子树不可删除，需先更换默认目录。
- 恢复时可选择新目录或名称，重名、层级和成环检查在事务中执行。永久删除必须输入界面当前语言显示的确认短语，先记录不可恢复的删除状态，再回收原文件与其缓存；中断会在启动和每小时巡检继续回收，保留元数据墓碑。此前单独删除的子项仍独立保留在回收站。
- 原文件只通过鉴权接口下载，使用附件响应和 `nosniff`，不作为公开静态资源。图片预览支持 PNG、JPEG、GIF 首帧、WebP，最多 2400 万像素、单边 16384 像素。服务端重新编码为 PNG，样式宽高 16–2048，最多 30 个；等比适配不放大，裁切填满指定尺寸。
- UTF-8 文本按转义文本预览，最多 256 KB；HTML/SVG 不直接执行，其他文件提供下载。缓存根据原文件对象键和样式版本生成，读取仍鉴权，不保留浏览器缓存；磁盘样式缓存上限 128 MB，可在系统设置中清理。预览授权本身允许读取预览内容，下载权限控制原文件和样式下载入口。

新增权限为 `menu:manage`、`file:read`、`file:upload`、`file:download`、`file:manage`、`file:styles`、`audit:read`、`system:read`、`system:settings`，默认只授予超级管理员。普通角色需要明确勾选。文件查看、上传、下载、管理分别校验，文件页面可对仅上传成员开放元数据列表，但不给予预览和下载能力。总览中的审计摘要也必须具有 `audit:read`。

审计记录成功的管理变更，保存操作人、动作、资源摘要、服务端请求编号、方法和路径，不记录密码、渠道密钥或上传正文。列表每次最多 50 条，使用编号游标加载更多；默认保留 90 天，可配置 7–365 天，每小时分批清理。历史记录没有请求编号时如实显示为空。运行信息展示 Go/应用版本、SQLite 版本号、数据库及原文件占用和待回收数量，不回显主机绝对数据路径。

## 应用密钥、安装包与编码工具

在「应用与密钥」创建应用，填写不可变的 3–48 位小写标识。每个应用最多 10 个未撤销且未过期的密钥，实例最多 200 个有效应用。密钥使用 256 位随机值，明文仅创建/轮换时返回一次，数据库仅保存 SHA-256 摘要与短前缀；有效期 1–365 天。轮换在同一事务中撤销旧密钥并签发新密钥，撤销、到期或停用应用后拒绝后续请求。归档应用前必须先归档它的安装包，归档会撤销全部密钥。

浏览器继续使用 Cookie + CSRF；程序接入单独使用 `Authorization: Bearer $MONITOR_GO_API_KEY`，不接受查询参数传密钥、不允许密钥登录管理接口。提供主机读取、检测状态、告警读取、安装包列表与下载五个范围，按需勾选。前三项是本实例共享数据，安装包只限密钥所属应用。每个密钥与来源 IP 每 5 分钟最多 300 次请求，过限返回 429。完整协议及示例见 [应用分发与编码工具](APPLICATION_DISTRIBUTION.md)。

安装包关联已有文件或直接上传，也可使用不含用户名/密码的 HTTPS 外链。本地文件关联需要 `file:download`，直接上传还需 `file:upload`。首次发布后锁定所属应用、版本号、平台、架构与文件来源；更新文件应创建新版本。应用、版本号、平台与架构的组合在归档后仍不能重复使用。所有未归档安装包（含草稿与下架）都阻止关联文件或父目录移入回收站，归档不删除文件。

只有已启用应用下的已发布版本可下载。本地下载支持 Range/HEAD 并返回 `X-Checksum-SHA256`；下载次数统计成功的 GET 请求（含分段），不代表安装量。浏览器外链下载返回 302，统计跳转次数；机器 API 返回外部 URL 的 JSON，调用方须另起不含应用密钥的下载请求，该地址查询不计下载次数。外部内容不由服务器抓取、不提供外部文件校验值。私有部署首次不包含示例应用、密钥或安装包。

编码工具在本实例生成，不保存输入正文，不调用外部图像服务。二维码支持 UTF-8、L/M/Q/H，内容最多 1200 字节；Code 128 支持可打印 ASCII、Code 39 支持大写字母与指定符号；EAN-13/8 自动补齐或检查校验位。导出 PNG 与安全的纯几何 SVG，自动保留静区与整数模块尺寸。宽度 128–2048 像素，条码高度 80–512；尺寸不足返回所需宽度。改变内容后需重新生成才能导出。每人/来源 IP 每 5 分钟最多生成 120 次，全局最多 2 个并行生成任务。正式印刷请实际试扫，生成 EAN 不等于取得商品编号。

新增 `application:read`、`application:manage`、`application:keys`、`release:read`、`release:manage`、`release:download`、`tool:generate` 七项权限，默认只给超级管理员。`application:keys` 是敏感权限，持有者可为应用签发五种接口范围；应用管理与密钥管理可分别授权。只拥有安装包权限的成员可读应用目录以选择归属，但不能管理应用或读取密钥。

## 从早期版本升级

先正常停止旧服务并完整备份数据目录（包括 `master.key` 和已有 `uploads/`），再用新二进制启动同一目录。已实现 v1 → v2 → v3 → v4 → v5 → v6 → v7 → v8 顺序事务迁移：v2 添加 Agent 与通知，v3 添加菜单、文件、图片样式、基础设置和审计请求信息。原有主机、用户、检测和告警保留。新增权限只授予内置超级管理员并撤销其旧会话，其他角色需明确授权。v4 新增应用、密钥和安装包，以及按固定内置键分配的新导航，避免与已有自定义菜单编号冲突。旧版本二进制不能直接读取 v8，回退需恢复整套升级前备份。

## 数据、调度与备份

- `data/monitor.db`：用户、角色、会话、主机资料、采样、检测、执行任务、告警和审计。
- `data/master.key`：检测访问凭据的 AES-GCM 主密钥，与数据库分开保存。凭据接口不返回明文。
- `data/uploads/`：原文件、上传临时对象和可重建的图片缓存，备份必须包含原文件。
- `data/instance.lock`：实例锁；运行数据、密钥、构建产物均被 Git 忽略。
- 后台最多同时执行 4 项检测，活动任务队列最多 256 项，同目标活动任务合并；重启后恢复未完成任务。
- 当前最多配置 500 个有效检测目标，这是输入上限，不代表已完成该规模压力测试。单目标周期 15–86400 秒，超时 1–30 秒且短于周期。
- 主机与检测原始指标默认保留 7 天（可配置 1–30 天），检测小时汇总默认保留 90 天（可配置 90–730 天），每小时先汇总再分批清理；告警持续保留，审计按系统设置保留 7–365 天。曲线按时间桶聚合，缺失区间不补零，可用率为成功次数 / 总检测次数。
- 告警确认、静默或暂停检测都不会伪造恢复。检测连续异常达到目标阈值后创建事件，一次正常结果恢复；主机 CPU、内存和磁盘阈值可在系统设置中配置，详见下方说明。
- 探测允许私网和回环，适合内部服务监测；拒绝链路本地、常见云元数据、组播和未指定地址，HTTP 重定向也经过同一拨号检查。HTTP/SSL 和启用 TLS 的数据库连接均校验证书。

备份时先正常停止服务，再完整复制数据目录，包括 SQLite 可能存在的伴随文件、`master.key` 与 `uploads/` 原文件。恢复时整体放回并使用同版本启动。当前没有在线备份界面；运行中不要只复制 `monitor.db` 当作完整备份。

## 可信代理与登录限流

`-trusted-proxy` 接受逗号分隔的代理 CIDR，默认留空（不信任代理），非法值会阻止启动。只填写本进程实际看到的代理地址；代理必须覆盖或安全追加 `X-Forwarded-For`。服务端从右向左寻找首个不可信地址，忽略其他来源提供的转发头。登录只统计失败：每个客户端 IP 每 5 分钟 30 次、每个规范化用户名每 5 分钟 10 次；成功登录不消耗也不重置这些计数。初始化对所有尝试计数（每个 IP 每 5 分钟 10 次）。

## 检测编辑与归档

检测列表支持完整编辑名称、类型、地址、周期、超时、阈值和凭据。编辑时密码留空保留旧值，填写新密码则替换，勾选“清除已保存凭据”则清空；改为 HTTP/TCP/SSL 会清空数据库凭据。保存通过版本号校验，重置当前状态和调度并取消排队任务，保留历史与未恢复告警。归档需要确认并停止后续检测。只读成员没有编辑或归档入口。409 冲突会刷新服务端数据并保留当前表单；再次保存前请重新打开编辑器核对最新配置。

默认实例名随界面语言切换，英文显示 “My monitoring center”。系统设置中勾选“使用默认实例名称”可恢复这一行为；自定义名称在所有语言下均保持原文。旧安装从未修改过的默认名称会自动识别，已保存过的名称保留原文，需主动选择默认名称。

## 群机器人 Webhook

Webhook 消息格式支持通用、钉钉、飞书和企业微信，旧渠道默认按通用格式发送。在渠道编辑器选择格式：钉钉使用 Markdown，加签时在 URL 中携带毫秒时间戳和签名；飞书使用文本，加签时在正文中携带秒级时间戳和签名；企业微信使用 Markdown，密钥在 URL 的 `key` 参数中，无需额外签名密钥。编辑器切换格式会清除之前的签名密钥。

通用格式沿用原有 JSON 和签名头约定。群机器人格式必须同时满足 HTTP 成功及平台错误码为 0（钉钉/企业微信为 `errcode`，飞书为 `code`）；缺失或畸形错误码视为失败，依次在 15 秒、1 分钟、5 分钟后重试。消息包含事件、原文标题/资源/描述、级别、UTC 时间及投递编号，固定标签使用英文。长字段仅在通知正文中截短，以满足企业微信 Markdown 的 4096 字节限制，数据库原始告警保持不变。本次未做真实平台验证，使用本地 HTTP 模拟测试格式、签名、错误码和重试；部署时请通过测试投递验证自己的机器人密钥及平台策略。

## 主机告警阈值

系统设置可配置实例级 CPU、内存、磁盘阈值（默认 90%、90%、85%）以及 1–60 分钟的持续时长（默认 5 分钟）。单项阈值为 0 时关闭该指标告警。结构版本 6 新增这些带约束的设置；升级前停服并完整备份数据目录，旧程序不能读取结构版本 8。

本机与远程主机共用判定规则。CPU/内存必须在整个持续时长内达到或超过阈值：样本需覆盖整个窗口，包含窗口起点或之前的有效样本，不能缺值或出现超过 45 秒的间隔。数据不足不会新增告警，也不会让已有告警恢复；最新有效值低于阈值时立即恢复。磁盘按最新可用采样立即判断。关闭阈值会在下次上报时恢复该指标告警；配置变更也从下次上报生效。远程主机 90 秒离线规则不变。按主机单独覆盖阈值尚未实现。

## 按页刷新与列表查询

页面可见时每 10 秒只刷新当前页所需的主机、检测和告警数据，同时刷新会话与导航。其他页面使用轻量告警计数接口更新移动端徽标，范围与告警列表的最近 200 条事件一致。角色、成员和权限仅在进入相应页面或变更后读取，不参与定时轮询。切页与写入后会重新读取，旧页面和旧会话响应会被丢弃。检测列表使用 3 次 SQL 查询，告警列表使用 2 次；响应结构、24 小时可用率、最近 32 次检测和每个事件最近 100 条活动保持一致。

## 静态资源缓存

服务端启动时使用 Go 标准库预生成强 ETag 和 gzip 内容。`/assets/` 下带哈希的文件使用 `public, max-age=31536000, immutable`，HTML 和其他无哈希文件使用 `no-cache` 并协商验证。gzip 协商遵守禁用和权重偏好，响应带 `Vary: Accept-Encoding`，压缩与原始内容使用不同 ETag。条件 GET/HEAD 在匹配时返回 304，保留字节范围和原有安全响应头，无需外部压缩服务。

## 构建版本与 CI

服务端、Agent 上报及外发请求 User-Agent 统一使用 `internal/buildinfo.Version`。直接 `go build` 默认为 `0.4.0-dev`；`make build` 注入 `git describe --tags --always --dirty`，无 Git 信息时回退到默认值。可用 `make build VERSION=0.4.0-dev` 明确指定。两个二进制均支持 `-version`。前端包使用开发基线，系统设置显示实际服务端构建版本。GitHub CI 配置为 push 和 pull request 触发，使用 go.mod 中的 Go、Node 22、固定提交的 Action，执行 race 测试、类型检查、构建和格式检查。工作流文件不代表远端已运行通过或已发布版本。

`make docker-build` 会注入 Git 派生版本。直接使用 Compose 时可传入 `MONITOR_VERSION`，未指定则显示 `0.4.0-dev`。直接构建可用 `docker build --build-arg VERSION="$(git describe --tags --always --dirty 2>/dev/null || printf 0.4.0-dev)" -t monitor-go:local .`。Git 历史不进入 Docker 构建上下文。

## 在线备份与恢复

执行命令时服务可以继续运行。输出目录必须不存在，父目录必须已存在。命令只读打开源库，不获取实例锁、不执行迁移（支持结构版本 3 至当前版本），生成一致的 SQLite 快照，并复制主密钥及快照引用的全部对象，包括回收站文件。快照之后的新上传不纳入本次备份。缺失对象会重试；仍缺失、损坏或变更时以非零状态退出并保留 BACKUP_INCOMPLETE，不能恢复该目录。完成清单记录 UTC 时间、构建/结构版本、对象数量及 SHA-256。初始化码、锁、暂存文件和图片缓存不复制。

```sh
mkdir -p backups
./bin/monitor backup -data data -out backups/snapshot-001
```

恢复时先停服，用完整备份替换整个数据目录，再使用支持该结构版本或更高版本的程序启动。验证成功前保留旧目录。只支持离线恢复，不要向运行中的实例合并文件。备份包含凭据，应私密保存并复制到独立存储；原有冷备份方式仍可使用。

## 默认资源名称

未修改的预置目录（含设置与安装包选择器中的路径）、角色名称和说明、图片样式及本机别名会随界面语言切换。改名后的值按原文显示；由服务端明确提供名称键，不会仅因自定义名称与默认名称相同就自动翻译。已有历史记录保持原样。

审计的固定操作标签在显示时翻译；操作者、资源文本以及数据库中的原始审计记录保持原样。

菜单管理的内置名称、指向页面、上级分组和权限选项也按界面语言显示。只修改显示状态或排序而未编辑名称时，保留内置名称的默认翻译行为；明确编辑的名称作为用户文本保存，切换语言不会覆盖草稿。

## HTTP 响应规则

创建与编辑 HTTP 检测均支持可选 UTF-8 关键字（最多 1024 字节）、反向匹配及耗时警告阈值（0–30000 毫秒，0 关闭）。匹配区分大小写，只检查解码后响应体前 1 MiB，截断会在详情中注明。关键字为空时保留仅判断状态码的行为。耗时包含读取被检查响应体的时间。连接或状态码失败优先，其次是关键字失败，再判定耗时警告；详情不回显响应内容。非 HTTP 检测会清除这些规则。自定义请求头、GET/HEAD 选择仍是可选后续功能。结构版本 7 新增字段，升级前停服并完整备份，旧程序不能读取新结构。

HTTP 耗时告警使用响应耗时标题；SSL 证书警告保留证书专用标题。

## Agent 重试与采集验证

网络或服务端故障按连续失败次数 × 5 秒退避，最长 60 秒；成功上报后恢复正常 15 秒间隔。HTTP 401/403，以及注册阶段的 409，会因凭据失效或注册冲突而停止 Agent，应使用新配置重新接入，不会持续重试已撤销凭据。自动测试使用本地 HTTP/TLS 服务及可注入采集器/时钟，覆盖凭据持久化、上报、退避上限与重置、禁止重定向、私有 CA、分区过滤（最多 16 个可用且不重复的挂载点）、部分指标错误和网络计数器/时间重置。

## 长期可用率与保留策略

结构版本 8 新增检测小时汇总（总数、成功数、平均/最大耗时）、事务内已汇总标记及待汇总部分索引。启动及每小时维护时，先累加已结束小时的数据，再清理原始记录。重复执行和迟到结果不会重复计数；汇总失败时保留原始记录。设置默认原始主机/检测指标 7 天（可配置 1–30 天），检测汇总 90 天（可配置 90–730 天）。清理按 UTC 整点对齐并分批执行，实际原始保留期可能多出一小时及维护积压时间。未新增主机汇总表。升级前停服并完整备份，旧程序不能读取结构版本 8。

总览与服务检测可选 30/90 天可用率。GET /api/v1/monitors/availability?hours=720 或 2160 需要 monitor:read 权限，总览支持同样范围。单次 SQLite 快照合并小时汇总与未汇总原始记录，按实际检测次数加权；healthy 和 warning 均计入可用，与原 24 小时口径一致。窗口起点按 UTC 整点对齐，并纳入当前未结束小时。缺失采样不会假设为成功，无历史返回 null/“—”；升级前已经删除的历史无法补回。

容量估算：原始检测行数 ≈ 目标数 × (86400 / 检测间隔秒数) × 原始保留天数；汇总行数 ≤ 目标数 × 24 × 汇总保留天数；主机原始行数 ≈ 主机数 × 5760 × 原始保留天数。使用有代表性详情的一次性数据库测量每行及索引开销，以 (page_count − freelist_count) × page_size 对比已用页增长，另外预留 WAL、上传文件和备份空间。删除仅使页可复用，不保证文件立即缩小；公式为估算，不是容量承诺。

## SQLite 并发读取

检测列表、长期可用率、总览、告警和主机指标查询使用最多 2 个只读连接（`mode=ro`、`query_only=1`），配合原有单写连接。鉴权、调度、修改、迁移与 seed 保留写连接路径；在线备份仍使用独立快照连接。事务回调必须通过自身事务读取。保留 WAL、FULL 同步和单实例锁，无新增迁移或依赖。

Apple M1 / Go 1.26.9 / 真实 WAL 文件下，以 500 个目标 × 1440 条结果、4 路轮询各读 5 次及 80 次间隔写入进行 3 轮合成压测：单连接写入 P95 中位数 866.6 ms，2 个只读连接为 0.478 ms；总耗时中位数从 10.45 s 降至 5.713 s。该本地测量不构成生产容量承诺。复现命令：`go test ./internal/app -run '^$' -bench BenchmarkConcurrentPollingWrites -benchtime=1x -count=3`；比较共享连接、2 个和 4 个只读连接，数据构造不计入耗时。

## 表单与错误提示的语言

安装、登录、弹窗、浏览器字段校验及临时提示均跟随所选界面语言；切换语言后，无需重新提交即可更新已有错误。编辑弹窗中未改动的默认名称也随语言切换，已输入的名称和其他未保存内容保持不变。新建检测的空分组显示本地化默认名称；已有分组名称及历史记录保留原文。

## 弹窗内切换语言

所有共享弹窗均提供语言选择器，无需关闭编辑器即可切换。已填写的名称、备注、密码、复选框和下拉选择保持不变；删除确认按输入时的语言识别，服务端仍接收固定 `DELETE` 标记。API／上传返回异常格式时显示本地化错误，不存在的接口也返回可随语言切换的错误键。

## 手机布局与弹窗

窄屏下时间范围按钮自动换行，超长应用名、主机名和告警资源名在面板内折行。弹窗正文独立滚动，关闭和底部操作保持可用；长说明随正文滚动，长标题在限制高度的区域内滚动。文件／图片预览和安装包目录下拉框适应可用宽度。

## 主机操作系统名称

本机采集与新版 Agent 将苹果电脑显示为 `macOS <产品版本>`，版本来自实际 macOS 系统版本；Darwin 内核版本仍单独保留在“系统信息 → 内核版本”中。Go 构建／运行环境中的 `darwin/arm64` 仍是技术平台标识。已有远程主机需更新 Agent 并再次上报后更新名称，不改写历史记录；Docker 采集的是 Linux 容器环境。

## macOS APFS 容量与磁盘告警

APFS 多个卷共享容器空闲空间。采集器通过系统 `diskutil` 读取已挂载卷的归属和容器容量，每个已确认的 APFS 容器 UUID 只报告一份容量，并保留代表路径及其挂载点。数量表示容量项，不表示物理硬盘数量；配置了卷配额时另保留该配额项。独立容器即使占用数值完全相同也不会合并；Linux／Windows 以及不带容量身份的旧报告不按数值猜测去重。

磁盘告警使用全局实际阈值（0 为关闭），主机详情及总览的提示、颜色与配置一致。归并挂载点沿用原主机磁盘告警身份，不改变已有认领和静默状态。缺失或不完整的磁盘采样可确认已知超限，但不能作为恢复依据；完整低值采样或关闭阈值后才可恢复。APFS 归属读取失败时保留原挂载采样并标记不完整，读取失败的挂载点不会视为健康。

先更新服务端，再部署新版 Agent；当前资料随下次报告更新，不改写历史告警和采样。无需数据库迁移或新增依赖。容器使用率包含共享分配，因此可能与单个卷的 `df` 百分比不同。机制说明见 [Apple 的 APFS 空间共享文档](https://support.apple.com/en-au/guide/disk-utility/dskua9e6a110/mac)。
